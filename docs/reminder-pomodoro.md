## 1. 一句话目标

桌宠增加两个**互相耦合**的功能：

1. **番茄钟** —— 专注计时；开始前选一条待办，结束后写一条总结（永久留档）。
2. **对话提醒** —— 桌宠弹气泡提醒今天要做的待办，**只在非专注时间弹**。

---

## 2. 为什么这是一个整体

番茄钟给提醒提供**"现在能不能打扰"**的判断依据：

```
        现在是什么阶段？
        ├─ 专注中（focus）      → 一律不弹（含自动和阶段结束的提醒）
        ├─ 已暂停               → 算非专注 → 可以弹
        ├─ 休息中（break）      → 可以弹（最佳时机）
        └─ 番茄钟未开启         → 按间隔弹，受活跃时段限制
```

---

## 3. 技术约束（前几轮踩坑所得，直接决定设计）

| 约束 | 原因 |
|---|---|
| **窗口尺寸恒定 540×520，绝不 resize** | resize 会让 WebView2 视口滞后一帧，宠物跳到错误位置 |
| **窗口区域必须精确等于"页面画出来的矩形"** | 区域偏大 → 未绘制处叠加 DWM 玻璃 → 露出淡蓝色带 |
| **不能用 `box-shadow` / `filter`** | 它们画在元素盒子之外，直接糊在用户桌面上 |
| **气泡不新开窗口** | 复用面板那 380px 区域；气泡与面板**互斥** |
| 窗口是 `WS_POPUP` + `WS_EX_TOOLWINDOW` | 无标题栏、不进任务栏 |

**结论**：所有气泡都画在**现有窗口内**，通过切换区域裁剪来显示/隐藏。这避免了 resize 竞态，也避免重现历史显示问题。

## 4. 番茄钟

### 4.1 状态机

```
     [未开启 idle]
          │ 用户开启番茄钟
          ▼
     [空闲 ready] ──选待办──> [专注 focus] ──到点──> [写总结] ──> [休息 break]
          ↑              │             ▲                              │
          │              │             │                              │
          │           暂停 ⇄ 继续      │  休息到点 → 写计划（§4.5.2） │
          │              │             └──────────────────────────────┤
          └────────停止──┴────────────────────停止─────────────────────┘
                                                     │
                                       连续 N 个专注后 → 长休息
```

- 默认：专注 **25** 分 / 短休息 **5** 分 / 长休息 **15** 分 / 每 **4** 个专注后长休息。全部可配置。
- **自动进入下一阶段**可开关（默认开）：专注到点 → 自动开始休息；休息到点 → 状态机照旧把下一个专注安置好，但**计时由计划气泡的应答起算**（§4.5.2）。
- **跨重启恢复**：存「结束时间戳」，重启后按剩余时间续算；若已超时，按"已结束"处理并提示。

### 4.2 开始专注必须选待办（新增）

点「开始专注」后**不立即开始**，先弹出**选择气泡**：

```
┌────────────────────────────┐
│ 想专注做哪件事？            │
│ ┌────────────────────────┐ │
│ │ ○ 你好                  │ │  ← 未完成、未完成的都在
│ │ ○ 懂啊房东啊            │ │
│ │ ○ 写周报                │ │
│ └────────────────────────┘ │
│ [ 取消 ]      [ 开始专注 ]  │
└────────────────────────────┘
```

规则：

- 列出**所有未完成**的待办（按 §5.4 的优先级排序）。
- **必须选一条**才能开始（这就是你说的"需要选择"）。
- **确认后不直接计时**：紧接着弹出**计划气泡**（§4.5.2），由那句「接下来想专注做什么」的应答起算。选待办与写计划是两道连贯的题，只有后者能启动计时器。
- **选待办 ≠ 完成待办**：选中的待办**不会被自动标记完成**。如果这次没做完，下次选择时它**照旧在列表里**。
- 上次选过的那条**默认高亮/置顶**，方便连续几个番茄都做同一件事。
- 列表为空时：允许选「不关联待办」直接开始（否则没有任何可选项就无法专注）。→ 见 §13 待确认。

### 4.3 暂停 = 非专注

你明确了：**暂停说明人不在专注状态**。所以：

- 暂停期间**允许**弹出待办提醒（按 §5 的间隔规则）。
- 暂停时角标变为**灰色**，显示剩余时间（不再倒数）。
- 暂停期间角标仍显示待办数。

### 4.4 角标：同时显示倒计时和待办数（新增）

现在是**两个角标叠放**：

```
        ┌──────┐
        │ 24:13│  ← 主角标：阶段剩余时间
        └──────┘
        ┌──┐
        │ 2│      ← 副角标：未完成待办数（现有行为）
        └──┘
```

| 状态 | 主角标 | 主角标颜色 |
|---|---|---|
| 专注中 | `24:13` | 蓝（现有 `--accent`） |
| 短/长休息 | `04:58` | 绿 |
| 暂停 | `24:13`（不动） | 灰 |
| 番茄钟未开启 | 隐藏 | — |

副角标（待办数）保持现有逻辑：有逾期变红脉动，24h 内到期变橙。

### 4.5 专注结束必须写总结（新增）

**每个专注阶段结束**时（休息开始前），弹出总结气泡：

```
┌────────────────────────────────┐
│ 这一个番茄做了什么？            │
│ 待办：写周报                    │
│ ┌────────────────────────────┐ │
│ │ 完成了数据部分…             │ │  ← 可输入
│ └────────────────────────────┘ │
│ [ 跳过 ]          [ 保存 ]      │
└────────────────────────────────┘
```

- 关联的待办标题会显示在气泡里（作为提示）。
- **总结不抢键盘焦点**：气泡出现后你点一下输入框才能打字。这样你正在别的程序写东西时不会被打断。（自动聚焦仅在桌宠窗口本来就有焦点时发生。）
- **`Enter` 直接保存**，`Shift+Enter` 换行。气泡不是 `<form>`，所以这一条是显式挂的键盘处理；`isComposing` 必须判断，否则中文输入法**选字的那一下回车**会把没写完的总结存掉。
- 点「保存」→ 写入记录（§6），**然后休息才开始计时**。
- 点「跳过」→ 也写入一条记录，`summary` 为空，标记为未填写。**记录照样保留**（因为记录不可删，不能靠"跳过"绕过）。**跳过同样会开始休息**——门控卡的是"有没有应答"，不是"有没有写字"。
- **总结气泡不能随便关掉**：Esc、拖动桌宠、点别处都不会关它，必须明确选一个。见 §4.5.1。
- **双击桌宠也不会把它顶掉**：总结气泡占着那一块矩形，而实时交流浮层同样要占那块，**占了就是删掉问题**（不是盖住）。所以浮层在有未回答的问题时**拒绝打开**，并把光标送进总结输入框（§8.2）。

### 4.5.1 休息由记录**门控**（2026-10-04 修订）

> **这一条推翻了本文档早先的设计。** 原设计是"休息照常开始，不被总结阻塞：写总结的同时休息已经开始计时"。
> 用户明确要求改成现在这样，理由是：**没有记录的番茄不应该占用休息时间**。

**现在的行为**：专注到点 → 弹总结气泡 → 计时器**停住**（`runState=stopped`，
`pendingRecordId` 有值，`endsAt` 为空）→ 你点「保存」或「跳过」→ 休息**从那一刻**开始计时。

三个设计要点：

1. **休息从"应答那一刻"起算，不是从专注结束时**。你填总结花的时间是你自己的，
   算进休息就等于**少给你休息**。
2. **气泡不可关闭**。它是门控本身——能随手关掉的话，要么计时器永久停住且屏幕上没有任何解释，
   要么用户从没选择过"跳过"就被跳过。应答只需要一次点击，两个按钮都能解决。
   （Esc、拖动桌宠、点别处都拦住了；**提醒气泡不受影响**，它不提问，照旧自动隐藏。）
3. **重启后会把没答的记录重新问一遍**。`pendingRecordId` 存在磁盘上，但气泡不在——
   不重新问的话，这个门控就会在**每次重启后变成死路**。

**`AutoStartNextPhase` 仍然管其他所有转换**：休息结束 → 由计划应答启动下一个专注（§4.5.2），
因为那一步多出了一次提问；其余不涉及提问的转换照旧自动接续。

### 4.5.2 计划气泡与专注由计划应答启动（2026-10-04 新增）

> **这一条补上了 §4.1 里"休息到点 → 自动开始下一个专注"留下的空档。** 休息结束什么都不问时，
> 用户没有机会在专注开始前写下"这一段要做什么"，只能等专注结束才被问结果。

**现在的行为**：休息到点 → 弹**计划气泡** → 计时器**停住**（`runState=stopped`、
`planPending=true`、`endsAt` 为空）→ 你按 Enter 或点「开始专注」/「跳过」→ 专注**从那一刻**开始计时。

```
┌────────────────────────────────┐
│ 接下来想专注做什么？            │
│ 待办：写周报                    │
│ ┌────────────────────────────┐ │
│ │ 这件事是…（可留空，Enter 开始）│ │  ← 可输入
│ └────────────────────────────┘ │
│ [ 跳过 ]          [ 开始专注 ]  │
└────────────────────────────────┘
```

要点：

1. **两条进入专注的路都经过它**：休息自然到点（状态机照旧按 `AutoStartNextPhase` 把下一个专注安置好，app 层在其上追加"暂停 + 等计划"），以及手动点「开始专注」（选待办气泡确认后紧接弹出同一个计划气泡）。两条路共用同一个装载动作，因此不存在"选待办的 id 和结转的 id 谁为准"的分支。
2. **计划可留空**，`Enter` 直接完成，与「跳过」是同一条路径（只差一个空字符串）。计划为空**照旧产生记录**，与总结的"跳过也记录"一致。
3. **总结气泡会把计划显示出来**：专注结束时那句「这一个番茄做了什么？」下面多一行「计划：<当初写的>」，好让你填结果时有对照；计划为空则整行不显示。
4. **记录页一前一后两行**：第一行「计划：<预先要做的事>」，第二行「实际：<结果>」，两行都能就地改（§6.2）。老记录没有计划字段，第一行退回显示待办名，观感与今天一致。
5. **气泡不可关闭**：与总结气泡同理——它是门控本身。Esc、拖动桌宠、点别处都拦住了（§8.2）。
6. **幂等与例外**：
   - 只有"休息刚刚到点"这一刻会问。**重启补算**（关着的时候休息早就结束了）不问，直接开始专注，否则每次启动都会重复问同一个问题；
   - **全屏静默**（§4.7）不问也不置门控，计时照常，退出全屏后也**不补问**；
   - **面板打开会把气泡折叠掉**，而面板里没有回答计划问题的入口（记录页只能改已有记录）——所以**关闭面板时会重新弹出**这个未回答的问题，等价于"问题回来了"。
   - **重启后也会重新弹出**（`planPending` 存在磁盘上，气泡不在），与总结的 `pendingRecordId` 自愈同构。
   - **计划待答时拒绝隐藏桌宠**（`errPlanBlocksHiding`），理由同 §4.5.1。
   - **桌宠已隐藏时到点：先把桌宠显示出来**（§4.9），答完再自动隐藏回去。
7. **显式放弃/关闭会清掉门控**：休息期间「跳过」、关掉番茄钟、`ResetPomodoro` 三条路都清空 `planPending`/结转的待办/内存里的计划。不清的话，上一次遗留的计划会被写进**下一条永久记录**。
8. **专注进行中重启**：计划是内存态，随进程消失——那一次记录的计划为空、不报错、记录照旧产生。


### 4.6 声音

阶段结束时播放**系统提示音**（不引入音频文件）：

| 事件 | 声音 |
|---|---|
| 专注结束（该休息了） | 系统提示音 |
| 休息结束（该专注了） | 系统提示音（音调不同以示区分） |

用 Win32 `PlaySound` 的系统别名（如 `SystemAsterisk` / `SystemExclamation`）。设置里可**关闭声音**。

### 4.7 全屏时静默

- 检测前台窗口是否**全屏**（覆盖整个显示器、且不是桌面/任务栏）。
- 全屏中：**不弹**任何气泡、**不播**声音；番茄钟本身照常计时。
- 退出全屏后：若期间有错过的阶段切换/提醒，**补一个**气泡（不补一串）。

### 4.9 隐藏模式下到点会把桌宠显示出来（2026-10-08 修订）

> **这一条补上了隐藏与番茄钟门控之间的一个死路。** 原来的规则是"隐藏期间一律不弹"，
> 于是**先把桌宠藏起来、再让专注到点**（顺序与"先到点再按隐藏"相反）会留下一个
> 永远停住的计时器：气泡画在 `SW_HIDE` 的窗口里，屏幕上一个像素都没有，用户唯一的
> 出路是记得去按显示快捷键。

**现在的行为**：桌宠已隐藏时，凡是**需要用户回答**的时刻——专注到点的**总结气泡**、
休息到点的**计划气泡**——桌宠会**自己显示出来**，答完（或跳过、放弃）之后**自动隐藏回去**：

```
隐藏中 ──专注到点──> 显示桌宠 + 总结气泡 ──保存/跳过──> 休息开始计时 + 重新隐藏
隐藏中 ──休息到点──> 显示桌宠 + 计划气泡 ──应答/跳过──> 专注开始计时 + 重新隐藏
```

七条实现约定：

1. **只对"提问"破例**。总结气泡是休息的门控、计划气泡是专注的门控，两者都把计时器
   停住——那才是"必须让人看见"的理由。**提醒气泡仍然按原规则在隐藏期间不弹**
   （它不提问，看不见的通知没有意义，而且下一个间隔还会再来一次），
   **主动说话也照旧不开口**。
2. **显示但不抢焦点**。窗口用 `SW_SHOWNOACTIVATE` 显示，而不是 `desktop.Show`：
   你很可能正在别的程序里打字（这正是总结气泡本来就不抢焦点的原因），
   一个被激活的桌宠会把你下一串按键吞进它自己的输入框。
3. **只显示宠物，不恢复面板/浮层**。它们是被隐藏折起来的，问题只需要宠物自己露面；
   把更大的界面一起弹回来是第二种打扰。
4. **答完就藏回去**，四条路径都会：保存/跳过总结、应答计划、**放弃（`ResetPomodoro`）
   与关掉番茄钟**（它们同样清掉了门控）。藏回去时会顺手把面板/气泡折起来，
   与「隐藏桌宠」完全一致。
5. **你自己按过显示就不再有任何债务**。用快捷键、托盘或**打开面板**显示过桌宠
   （`ShowPet` / `SetPanelOpen(true)`）之后，回答提问**不会**把它再藏起来——
   "我要它回来"不能被后面某个动作反悔。再按一次隐藏则重新记账。
6. **显示失败就不改状态**。窗口解析不出来或 `ShowWindow` 失败时，`hidden` 保持为真、
   区域不动，唯一的退路仍然是你原来那条（这保证"状态"和"屏幕"不会各说各话）。
7. **与"拒绝隐藏"不冲突，各管一个方向**：门控**已经在等**的时候按隐藏 → **拒绝**
   （§4.5.1），所以你不可能主动藏掉一个正在等回答的问题；而隐藏**已经生效**之后
   才到点 → **显示出来**。两条规则合起来，提问永远不会落在看不见的地方。

## 5. 对话提醒

### 5.1 交互

- 桌宠旁边（与面板同侧）弹气泡，带尖角指向桌宠。
- 内容：标题 + 最多 N 条待办 + `还有 M 项`。
- **自动消失**（默认 12 秒）；**悬停暂停倒计时**，移开继续。
- **点击气泡** → 收起气泡、打开待办面板（立刻处理）。
- **气泡不抢键盘焦点**（与总结气泡不同，它纯展示）。
- 面板已打开时不弹。

### 5.2 触发时机

| 触发源 | 条件 |
|---|---|
| 番茄钟进入休息 | **立即**弹一次 |
| 番茄钟未开启 / 已暂停 | 每 `间隔` 弹一次；有内容才弹 |
| 专注中 | **绝不弹**（含到点的间隔，记下"错过"，休息时补一次） |
| 全屏中 | **绝不弹** |
| 托盘菜单 / 面板按钮 | 手动"立刻提醒一次"，任何状态都弹（手动优先） |

其它门控：活跃时段内（默认 09:00–22:00）、有内容才弹、不重复打扰。

### 5.3 间隔带随机抖动（新增）

**每次间隔 = 配置值 + 随机 0–3 分钟**。

即配置 30 分钟时，实际在 **30:00 ~ 33:00** 之间随机触发，下一次重新随机。目的是不要像闹钟一样准点。

> 我对你这句的理解是「每次间隔加 0–3 分钟随机量」。如果你的意思是「程序启动后 0–3 分钟内就弹第一次」，告诉我，改起来是一行。

### 5.4 内容选取

按优先级取，最多 `MaxItems` 条：

1. 已逾期（逾期最久的在前）
2. 今天到期（按时间升序）
3. 24 小时内到期

不显示已完成的项。

### 5.5 设置项

| 项 | 默认 | 范围 |
|---|---|---|
| 启动时开启提醒 | **关** | — |
| 提醒间隔 | 30 分钟 | 5–240 |
| 活跃时段 | 09:00–22:00 | — |
| 每次显示条数 | 3 | 1–5 |
| 自动消失 | 12 秒 | 5–60 |
| 空列表也提醒 | 关 | — |

## 6. 番茄钟记录（永久，可改不可删）

### 6.1 规则

- **每个专注阶段结束**产生一条记录（即使总结为空）。
- **不可删除**：界面上没有删除按钮，也没有"清空"。
- **可修改**：计划与实际结果两段文字随时能改。
- 关联的待办标题**存快照**（待办以后被改名或删除，记录里仍是当时的标题）。
- 记录里还存**开始前写下的计划**（§4.5.2）。旧记录没有这个字段，按空值读，不写迁移代码。

### 6.2 界面

面板新增第三个页签 **「记录」**。记录**按天折叠**：

```
┌─────────────────────────────────┐
│  待办  |  记录  |  设置          │
├─────────────────────────────────┤
│ ▾ 今天 · 10月5日    3 条 · 100 分│  ← 展开
│   18:10 · 写周报          25分  │  ← 这行逐字不变
│   计划：整理接口                 │
│   实际：完成了数据部分…    [改] │
│   14:20 · 未关联待办      25分  │
│   计划：未关联待办               │  ← 老记录：退回待办名
│   实际：（未填写）         [改] │
│ ▸ 昨天 · 10月4日    3 条 · 100 分│  ← 折叠
│ ▸ 9月30日           3 条 · 100 分│
│ ▸ 8月12日           3 条 · 100 分│
├─────────────────────────────────┤
│ 共 37 条 · 累计专注 15.4 小时    │
└─────────────────────────────────┘
```

- 一天一个可折叠分组，按 `endedAt` 的**本地日历日**（不是 UTC 日期）归组，
  日期新的在上。
- **首次打开时只有最新一天是展开的**，其余折叠。分组标题本身就带
  「日期 · 条数 · 当天分钟数」，所以折叠状态也回答得了"那天干了多久"。
- **折叠状态是跨重渲染保留的**（存在 `openRecordDays` 里，不在 DOM 里）：
  `applyState` 每次状态推送都会重画记录页，折叠状态放在 DOM 里会不停弹回。
- **后来才出现的一天自动展开**（`seenRecordDays`）：应用开着的时候跑完一个番茄、
  或跨过零点产生新一天时，新记录不能落在一个收起来的分组里。
- 单条记录只显示**时间**（`18:10`），日期已经在分组标题上了。
- 每条记录的字面是**两行**（§4.5.2）：第一行「计划：<预先要做的事>」，第二行
  「实际：<结果>」。有计划时第一行就是那段计划；**没有计划（含全部历史老记录）**
  第一行退回显示待办名，观感与改造前一致。第二行为空时写「（未填写）」。
- 「改」→ 就地编辑**两行**（上「计划」、下「实际」两个文本框），保存时一次性写回
  两个字段并各自更新修改时间；计划可以被清空。记录仍然**不可删除**。
- 底部显示总条数与累计专注时长（顺带就有，成本为零）。
- 记录按时间**倒序**（最近的在最上）。

> 为什么改折叠：最初是**一整条平铺列表**，一年下来最新几条和整年历史挤在同一屏，
> 想看最近的也要先滚过全部历史。折叠后一屏就能扫完所有天数。
>
> 折叠用**两个字符**（`▸` / `▾`）而不是 CSS `transform: rotate()`：面板内部加
> transform 其实是安全的（被面板 border box 裁掉），但这个项目"边界框外不许有任何
> 装饰"的规则之所以有效，是因为它**没有例外**——旋转正是那种一开始是例外、后来就
> 没人再审计的东西。两个字符不花钱，规则还能保持完整。

滚动条：记录页、对话页与设置页、待办列共用 `style.css` 「scrollbars」一节里的
**一条**规则（8px、无轨道、半透明白）。之前设置页和待办列各有各的私有副本，
记录页和对话页则留在 WebView2 默认的深灰控件上，在 380px 的深色面板里看起来不像
同一个程序。

### 6.3 数据增长

一条记录约 200 字节。每天 10 个番茄 = 2KB/天 ≈ **0.7MB/年**。可以忽略，所以"永久保存"没有容量问题。

### 7.2 番茄钟运行状态 —— `pomodoro.json`（新文件）

```go
type PomodoroState struct {
    Enabled          bool       `json:"enabled"`          // 用户是否开启了番茄钟
    Phase            string     `json:"phase"`            // idle|focus|short_break|long_break
    EndsAt           *time.Time `json:"endsAt"`
    PausedAt         *time.Time `json:"pausedAt"`
    RemainingOnPause int        `json:"remainingOnPause"` // 秒
    CompletedCount   int        `json:"completedCount"`   // 已完成专注数
    CurrentTodoID    string     `json:"currentTodoId"`    // 本轮选中的待办
    CurrentTodoTitle string     `json:"currentTodoTitle"` // 快照
    PhaseStartedAt   *time.Time `json:"phaseStartedAt"`
    PendingRecordID  string     `json:"pendingRecordId,omitempty"` // 有记录在等总结（休息的门控）
    PlanPending      bool       `json:"planPending,omitempty"`     // 正等用户写下本轮专注要做什么（§4.5.2）
    NextTodoID       string     `json:"nextTodoId,omitempty"`      // 结转给下一个专注的待办
    NextTodoTitle    string     `json:"nextTodoTitle,omitempty"`   // 结转的待办标题快照
}
```

单独文件：这是**运行状态**而非用户偏好。损坏时**直接重置为空闲，不弹警告**（区别于 config/todos 的容错策略）。

`NextTodo*` 的结转时点是**专注结束时**（那时候会话自己才知道它做的是什么），而不是休息结束时——
`finishPhase` 在专注分支就清空了 `CurrentTodo*`，休息到点那一刻已经无值可复制。
`Phase == idle` 时 `NormaliseState` 会把 `PlanPending`/`NextTodo*` 一并归零，避免"空闲却等计划"的僵尸门控。

### 7.3 番茄钟记录 —— `pomodoro-records.json`（新文件）

```go
type PomodoroRecord struct {
    ID          string    `json:"id"`
    TodoID      string    `json:"todoId,omitempty"`
    TodoTitle   string    `json:"todoTitle,omitempty"`   // 快照
    StartedAt   time.Time `json:"startedAt"`
    EndedAt     time.Time `json:"endedAt"`
    FocusMinutes int      `json:"focusMinutes"`          // 计划时长
    Summary     string    `json:"summary"`               // 实际结果，可为空（跳过时）
    EditedAt    *time.Time `json:"editedAt,omitempty"`
    Plan        string     `json:"plan,omitempty"`        // 开始前写下的计划（§4.5.2），旧记录缺此键按空值读
    PlanEditedAt *time.Time `json:"planEditedAt,omitempty"` // 计划被事后修改的时间
}
```

**不可删除**：store 层不提供 `DeleteRecord`，从类型上就杜绝。
**零迁移**：`plan`/`planEditedAt` 是新增键，旧 JSON 缺它们时 Go 零值天然兼容，不需要迁移脚本。

## 8. 布局与区域裁剪

### 8.1 气泡的四种形态，共用一块区域

都显示在面板那块 **380px 宽**的位置（窗口左侧），靠桌宠一侧对齐：

| 气泡 | 尺寸 | 内容 |
|---|---|---|
| 提醒 | 300×140 | 标题 + 待办列表 |
| **选择待办** | 300×200 | 可选列表 + 取消/开始 |
| **写总结** | 300×160 | 关联待办 + 计划提示行 + 输入框 + 跳过/保存 |
| **写计划** | 300×180 | 标题 + 结转的待办 + 输入框 + 跳过/开始专注 |

尺寸**固定**（不随内容变），因为区域裁剪必须精确。
写计划比写总结高一点：它要放一个期待用户写一句话的输入框；比选择待办矮一点：它不列待办。

### 8.2 区域裁剪

`applyWindowGeometry()` 中 `SetWindowRegion` 的矩形集合：

```
空闲：        { 宠物 }
气泡显示：    { 气泡, 宠物 }
面板打开：    { 面板(圆角), 宠物 }
浮层打开：    { 卡片, 输入条, 椭圆…, 宠物 }
```

**同一时刻只能是其中之一**，多一个像素就会重现淡蓝色带。

**四态互斥中的例外是"提问气泡"**。`#bubble` 与浮层共用同一块矩形，所以浮层不是"盖住"提问，而是**删掉提问**——而总结气泡是休息的门控（§4.5.1），删掉它等于计时器永久停住、屏幕上却没有任何解释。因此：

| 想打开的 | 气泡正在等回答（选择待办 / 写总结 / **写计划**） | 气泡只是通知（提醒） | 面板开着 |
|---|---|---|---|
| **实时交流浮层** | **拒绝**，返回说明并聚焦到那个输入框 | 打开，提醒收起 | 打开，面板收起 |
| 面板 | 打开（记录页能改总结，问题仍可回答；**写计划除外——面板里没有回答它的入口，所以关闭面板时会重新弹出**，§4.5.2） | 打开，气泡收起 | — |
| 提醒气泡 | **不弹**（丢掉这次） | 替换 | 不弹 |

两条实现约束，缺一不可：

- **Go 侧必须拒绝**（`OpenLive` 读 `unansweredQuestionKind`）。只靠前端拦不住别的调用方，也拦不住事件顺序上的竞态。
- **前端也必须拦**（`openLive` 读同一个状态）。因为「操作失败」的 toast 长在面板里，而气泡占着槽位时面板必然是关着的——报错弹在一个看不见的地方等于什么都没说。所以双击桌宠在这个状态下变成"**去回答问题**"：光标落进总结/计划输入框（选择气泡则落在「开始专注」上）。
- **主动说话同样被挡**（`decideProactive` 的 `awaitingAnswer` 门）。它会自动弹浮层，所以撞上提问时的后果和双击一样。
- **三种提问各有自己的说明文案**（"选一件事"/"写总结"/"写计划"不是同一句话），所以拒绝时能说清是哪一个问题占着槽位。

### 8.3 视觉

- 深色圆角卡片（`#1c1e24`）+ 1px 浅色描边 + 指向桌宠的小三角。
- **无阴影、无发光**（会画到桌面上）。
- 出现/消失用**透明度**过渡，**不用位移**（位移会露出未绘制区域）。
- 尖角用 CSS 边框三角形或小旋转方块实现，注意不能超出边界框。

## 9. 边界情况

| 情况 | 期望行为 |
|---|---|
| 专注中到提醒间隔 | 不弹，记"错过"，休息时补一次 |
| 专注中手动"立刻提醒" | **弹**（手动优先） |
| 暂停中到提醒间隔 | **弹**（暂停=非专注） |
| 气泡显示时拖动桌宠 | 收起气泡 |
| 气泡显示时进入专注 | 收起气泡（专注优先） |
| 开始专注但没有任何待办 | 允许选「不关联待办」→ 见 §13 |
| 写总结时跳过 | 仍生成记录，`summary` 为空 |
| **写总结/选待办时双击桌宠** | 浮层**拒绝打开**，光标落到那个输入框（问题不能被顶掉，见 §8.2） |
| 休息到点 | 弹**计划气泡**，计时器停住；应答（含留空/跳过）那一刻专注才开始计时（§4.5.2） |
| **计划气泡显示时按 Esc / 拖动桌宠 / 点别处** | **不消失**，计时器仍停着（门控不可随手关掉，§4.5.2） |
| 计划待答时打开再关闭面板 | 关闭面板时**重新弹出**（面板里没有回答它的入口，§4.5.2） |
| 计划待答时隐藏桌宠 | **拒绝**（`errPlanBlocksHiding`），门控与气泡原样保留 |
| **桌宠已隐藏时专注到点** | 桌宠**显示出来** + 弹总结气泡（不抢焦点）；保存/跳过 → 休息开始计时 + **重新隐藏** |
| **桌宠已隐藏时休息到点** | 桌宠**显示出来** + 弹计划气泡；应答/跳过 → 专注开始计时 + **重新隐藏** |
| 桌宠已隐藏时手动"立刻提醒" | 仍然**不弹**（提醒不提问），下一个间隔照旧 |
| 隐藏期间到点弹出后，用户自己按了显示快捷键 | 答完提问后**不再**隐藏（显式显示优先） |
| 计划待答时浮层/主动说话/提醒 | 一律让位（与写总结同一套规则，§8.2） |
| 计划待答时关掉番茄钟 / `ResetPomodoro` / 休息期间跳过 | 清空 `planPending`、结转的待办与内存里的计划 + 清气泡，不留僵尸门控、不留遗留计划 |
| 重启时门控仍为真（等计划时被关掉） | 重新弹出计划气泡；输入框初值取最近一条记录的计划 |
| 专注进行中应用重启 | 内存里的计划丢失 ⇒ 该次记录计划为空、不报错、记录照旧产生 |
| 留空 / 点「跳过」计划 | 同一条路径，计划为空字符串，记录照旧产生 |
| 专注中途停止/跳过 | 询问是否记录；不记录则不生成 |
| 全屏中阶段结束 | 静默；退出全屏后补一个气泡 |
| 睡眠唤醒 | 按已超时处理；提醒若已过间隔则弹一次 |
| 系统时间被改 | 倒计时跳变过大 → 重置为空闲并提示，避免负数 |
| `pomodoro.json` 损坏 | 静默重置为空闲 |
| `pomodoro-records.json` 损坏 | 改名 `.bak` 保留 + 提示（数据不可丢） |
| 关联的待办被删除 | 记录里保留当时的标题快照 |
| 多显示器 | 气泡跟随桌宠所在显示器 |

## 10. 验收标准

沿用本项目的**像素级**验证（这个项目多次出现"肉眼看不出但确实有问题"）。

**番茄钟**
- [ ] 默认关闭；手动开启后才工作
- [ ] 点开始 → 弹出选择气泡；**不选则无法开始**
- [ ] 选中的待办**未被自动标记完成**
- [ ] 未完成的待办在下次选择时**仍出现在列表里**
- [ ] 25 分到点 → 播声音 + 弹出总结气泡 + 记录生成
- [ ] 总结气泡**未抢键盘焦点**（在记事本里打字不中断）
- [ ] 总结气泡里 **`Enter` 保存**、`Shift+Enter` 换行、中文选字的回车不保存
- [ ] 总结气泡在时**双击桌宠不会顶掉它**，光标落到输入框
- [ ] 记录**没有删除入口**；修改总结后重启仍在
- [ ] 第 4 个专注结束 → 进入**长**休息
- [ ] 专注中途重启 → 剩余时间正确续算

### 13.1 「停止」的语义（重要，与常见番茄钟不同）

你说的「中途停止不生成记录，但可以继续那个番茄钟」意味着 **停止是可恢复的**：

```
专注中 ──停止──> 已停止（保留：关联待办、已过去的时间、已完成计数）
                    │
                    └──继续──> 专注中（接着走，不清零）
```

所以按钮是 **停止 / 继续**，而不是「放弃」。只有**阶段正常走完**才生成记录。

配套规则：

- 停止后角标显示为**暂停态**（灰色），仍显示剩余时间。
- 停止状态下算**非专注** → 允许弹提醒（与 §4.3 一致）。
- 停止后**再点开始**：默认接着当前这条待办与剩余时间继续；若要换待办，走「选择待办」流程。
- 停止状态**跨重启保留**（`pomodoro.json` 里记着），下次打开还在。
- 「退出程序」不清除停止状态；想彻底放弃需要一个显式的**重置**入口（放在设置里，避免误触）。

### 15.3 实测发现并修掉的三个真实缺陷

**(a) 补算级联（严重）**

用打包后的 exe 做端到端测试（预置一个「在关闭期间过期」的专注阶段）时发现：
恢复时会话结束后，**下一阶段沿用了历史结束时间**，于是重启瞬间就过期，接着又
立刻完成下一个专注阶段并写入第二条记录——离开越久，伪造的记录越多。

修法：`finishPhase` 现在同时接收 `endedAt`（阶段真正结束的时刻）和 `now`
（处理时刻）。**记录用 `endedAt`**（不被关机时长拉长），**下一阶段从 `now` 起算**。
回归测试：`TestCatchUpDoesNotCascade`。

**(b) `RemindDuringBreak` 是个摆设（功能缺失）**

该开关存了、也传到前端了、设置界面也能勾，但**门控逻辑里从来没读过它**——
勾掉之后休息期间照样弹。这是文档 §4.8 明确列出的「核心约束开关」，已补上
判定并加测试 `TestRemindDuringBreakSwitchIsEnforced`。

**(c) 倒计时数字抖动（用户截图反馈，严重）**

根因是**同一个瞬间有两个不同取整规则、两个不同时钟**在产出同一个数字：

- Go 侧 `RemainingSec` 用**截断**（`int(d.Seconds())`），而 `Countdown` 用
  `formatCountdown` 的**向上取整**——同一份视图里两个字段本身就互相矛盾；
- 前端还有一条每秒定时器，从 `remainingSec` **递减**并再按向下取整重算一次。

于是三者每秒互相覆盖。实测：在一个整秒内均匀取样 20 个时刻，**19 个**时刻两个
字段显示不同数字（`24:59` vs `25:00`）。

修法：

1. **一次取整，两个用途**：新增 `ceilSeconds()`，`RemainingSec` 与 `Countdown`
   都从它派生（`formatSeconds`），从类型上杜绝两者再分歧。
2. **前端不再递减计数器**，改为由 Go 下发**绝对截止时间** `endsAtMs`，前端按
   **同一套 ceil 规则**从该瞬间反算。这样它天然自校正：事件迟到、丢失或合并都
   不会累积误差（旧写法在间隔 1050ms / 900ms 时分别漂 +1s / −4s）。
3. 本地 tick 提到 250ms，数字在整秒边界翻转得更利落。

回归测试：`TestSecondsAndCountdownAgree`（跨整秒边界扫描）、
`TestPomodoroViewCountdownMatchesSeconds`。

**(d) 「跳过」弹的是浏览器原生对话框（用户截图反馈）**

`window.confirm` 在 WebView2 里渲染成**原生浏览器对话框**：白底、
标题是「wails.localhost 显示」、完全无视应用主题、盖住整个面板，而且位于窗口
裁剪区域之外——看上去像闯进来一个浏览器窗口，和桌宠格格不入。

改成面板内自绘的确认卡片（`#confirm`）：深色圆角、与应用同一套样式、
居中等宽、`Esc` 取消 / `Enter` 确认、默认焦点落在「取消」上（避免误按回车毁掉
当前番茄）。同时让最外层 `Esc` 在确认框打开时不关面板。

> 顺带说明：**没有用 Wails 的 `runtime.MessageDialog`**，它同样是原生系统对话框，
> 会脱离窗口区域，只是比浏览器对话框好看一点，问题一样。
