## 1. 一句话目标

在**不改变现有窗口几何、不破坏三态互斥、不重现淡蓝色带**的前提下，给桌宠加一个住在宠物旁边那块矩形里的对话能力：

- 双击桌宠 → 打字聊天 → 流式回复（可随时停止）；
- 桌宠说话时**知道你的待办和番茄钟状态**（上下文注入），所以它像桌宠，而不是一个套壳聊天框；
- 未配置 / 断网 / Key 失效时，**番茄钟、提醒、待办全部照常工作**。

## 2. 现有约束（直接决定设计，来自 `reminder-pomodoro.md` §3 与实测）

| 约束 | 原因 | 对本功能的影响 |
|---|---|---|
| 窗口 **540×520 恒定，绝不 resize** | resize 会让 WebView2 视口滞后一帧，宠物跳到错误位置 | 对话 UI 只能复用现有矩形，不能新开窗口、不能撑大 |
| 窗口区域必须**精确等于页面画出的矩形** | 区域偏大 → 未绘制处叠加 DWM 玻璃 → 淡蓝色带 | 对话与其它 tab 共用同一块 380×520 矩形与同一圆角 |
| 三态互斥：空闲 / 气泡 / 面板 | 同一个 slot，区域只能描述其中一个 | 对话 = 气泡态（新增一种气泡类型），与面板互斥 |
| 气泡高度**固定**，不随内容变 | 区域裁剪必须精确 | 主动说话有字数上限；新增气泡类型必须同时改 Go 高度表与 CSS |
| 不能用 `box-shadow` / `filter`，不能溢出，不能位移动画 | 元素盒外就是用户桌面 | 新 CSS 同样禁止；长回复只在内部 `overflow-y:auto` 里滚 |
| 气泡**不抢键盘焦点** | 用户可能正在别的程序里打字 | 主动说话绝不 focus；只有双击/点 tab 才 focus |
| `GetState()` 把整个 `store.Config` 发给前端 | 前端渲染需要 | **API Key 绝不能进 Config** |
| 依赖只有 wails + `golang.org/x/sys` | 现有 `go.mod` | DPAPI 用 `x/sys/windows`（零新增依赖）；SSE 手写（零新增依赖） |

## 3. 总体架构

```
┌─ WebView2（纯渲染，无业务逻辑，无密钥）─────────────────────────┐
│  对话 tab：transcript + 输入框 + 停止/清空/重新生成               │
│  EventsOn('pet:chat-delta' | 'pet:chat-done' | 'pet:chat-error')  │
└───────────────▲──────────────────────────┬──────────────────────┘
   事件(节流后)  │                          │ Wails 绑定(立即返回)
┌───────────────┴──────────────────────────▼──────────────────────┐
│  app_llm.go        会话管理 / 门控 / 事件推送 / 绑定方法          │
│  internal/llm      Provider 接口 · OpenAI 兼容流式客户端 · SSE    │
│                    解析 · delta 合并 · 提示词组装 · 错误分类       │
│  internal/store    DPAPI 密钥 · llm-history.json · llm-usage.json │
└───────────────────────────┬─────────────────────────────────────┘
                            │ HTTPS (SSE)
              任意 OpenAI 兼容端点（含本机 Ollama）
```

**为什么网络逻辑放在 Go 而不是前端直连**

1. 密钥不进页面：页面可被 DevTools 检查，配置本来就是用户可读的 JSON；
2. 流式 + 可取消 + 超时 + 重试 + 错误分类，不该塞进已经 1300 行的 `main.js`；
3. 后续要让它改待办，必须调用 Go 侧的绑定方法，放前端会绕一圈；
4. 断网/未配置时必须优雅降级为今天的行为，这需要后端参与。

## 4. 模型接入

### 4.1 只做一种协议

`POST {baseURL}/chat/completions`，`stream: true`，SSE。一种协议覆盖：

| 服务 | baseURL | 备注 |
|---|---|---|
| **DeepSeek（默认）** | `https://api.deepseek.com/v1` | `deepseek-chat` |
| 月之暗面 Kimi | `https://api.moonshot.cn/v1` | `moonshot-v1-8k` 等 |
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` | 兼容模式 |
| 阿里通义 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | 兼容模式 |
| OpenAI | `https://api.openai.com/v1` | |
| **本机 Ollama** | `http://127.0.0.1:11434/v1` | key 可留空，**数据不出本机** |
| one-api / new-api 网关 | 自填 | 走同一实现 |

Anthropic 原生协议（`/v1/messages`）**本版不做**，但 `Provider` 接口预留。

### 4.2 客户端要点

- **按字节流分块喂入的 SSE 解析器**：一个 `data:` 行经常被拆进两三个 TCP 包，也经常一次到达多行。解析器必须是纯函数、可任意分块喂入，这是整个功能里最容易写错的地方。
- `reasoning_content`（DeepSeek-R1 系）单独收集，默认丢弃；不混进正文。
- 超时：连接 10s；整体 `LLMTimeoutSec`（默认 90s），用 `context` 取消。
- 重试：仅 429 / 5xx / 网络错误，退避 0.5s → 1.5s，最多 2 次；**401 / 404 不重试**。
- 流式失败时回退一次非流式请求。
- 错误分类表（全部以**对话内系统消息**呈现，绝不用原生弹窗）：

| 情况 | 文案 |
|---|---|
| 401 / 403 | API Key 无效或已过期 |
| 402 / 429 | 额度或频率受限，请稍后再试 |
| 404 | 模型名不存在（`<model>`） |
| DNS / EOF / 连接被拒 | 网络不可达，请检查网络或 baseURL |
| context deadline | 响应超时，已取消 |
| 其他 | 原始状态码 + 截断到 200 字的消息体（脱敏后） |

### 4.3 两个必须写进代码注释的坑

1. **Wails 绑定是同步桥**：`SendChat` 里绝不能直接 `http.Do`，否则 UI 卡到超时。必须 `go func()` + 事件回传。
2. **token 级 `EventsEmit` 会打爆 IPC**：500 字回复 ≈ 数百次跨进程调用 × 序列化。Go 侧合并成 **50ms 或满 24 字符**刷一次，打字机手感不变，IPC 降一个数量级；`done` 事件带整段文本兜底，丢帧也能自愈。

## 5. 密钥与隐私

- **不进 `config.json`**（§2 已说明原因）。
- Windows：`CryptProtectData`（当前用户 DPAPI）→ `%AppData%\PetPC\llm-key.bin`。
- 兼容只读环境变量 `PETPC_LLM_API_KEY`，优先级 **env > 文件**（便于 CI / 多机 / 便携）。
- 前端只能拿到 `hasKey: bool` 与掩码 `sk-…a1b2`；日志、错误信息、`DebugLog` 一律脱敏。
- 设置页给出**隐私说明**，明确列出会发送的内容：系统提示词、你的输入、注入的待办/番茄钟上下文；**不会**发送文件、剪贴板、其他窗口内容。附「只用本机模型」一键填 Ollama。
- 首次开启大模型时弹一次确认（复用面板内自绘确认卡片）：`数据将发送到 <baseURL>，是否继续？`

## 8. 对话界面

> **v3**：曾经改成独立的浮动卡片（一种气泡），后来**退回面板 tab**。保留这段记录，因为它解释了
> 为什么不是独立窗口，以及那条路为什么没走通。

### 8.0 为什么是面板 tab，而不是独立窗口

对话是面板的第四个 tab（`待办 / 对话 / 记录 / 设置`），与其它 tab **共用同一块 380×520 矩形与圆角**。

| 想做成"真正的独立弹窗"会撞上什么 | 说明 |
|---|---|
| Wails v2 **没有多窗口 API** | `pkg/` 下没有 window 包；`NewWebviewWindow` 是 v3 的功能 |
| `FindWindow` 靠**类名** `"wailsWindow"` 找自己的窗口 | 第二个同类名窗口会直接打架，`resolveWindow` 会找错 |
| 窗口只有**一个槽位** | 540×520 = 宠物 150 + 间距 10 + 面板 380，第三块面没有地方放 |

**曾经试过的中间方案**：把对话做成一种**气泡**（356×468 插在 380×520 槽位里，
四周留 24px / 52px 露桌面，看起来像浮在宠物旁边的弹窗）。技术上是成立的，
`applyWindowGeometry` 的区域逻辑都不用改。**但它被放弃了**，因为代价是：

- 对话与待办面板**互斥** —— 看对话就看不到待办；
- 气泡尺寸是**固定**的（区域裁剪要求精确），不能按用户意愿拉大；
- 多了一层"卡片 vs 面板"的心智负担，而收益只是"看起来像弹窗"。

结论：**用面板 tab**。省掉一个面、一套互斥规则和一组尺寸常量，
而且和其它 tab 走完全相同的、已经验证过的裁剪路径。

### 8.1 布局

- 对话 tab 与其它 tab 使用**完全相同的 380×520 矩形与圆角**，
  `applyWindowGeometry` 的 `open` 分支一行都不用改。
- **不新开窗口、不 resize 任何东西**，只切换区域裁剪。
- 内部结构：状态行 + 消息列表（`#chat-log` 内部滚动）+ 底部输入框。
  只有消息区滚动，所以面板矩形恒定，不触发排版抖动、也不会让区域裁剪与实际绘制错位。

### 8.2 打开方式

- **双击桌宠** → `OpenChat()`：打开面板并切到对话 tab，输入框获得焦点。
- 也可以直接点面板上的「对话」tab。
- 「待办」按钮（`OpenTodoPanelFromChat`）切回待办 tab；
  这两个 tab 的切换方向由 `pet:chat-open` 事件的 `open` 字段承载 —— 布局只带几何，不带"哪个 tab"。

### 8.3 双击唤起与「单击 / 双击」冲突

现状：`pointerup(moved=false)` **立即**调 `TogglePanel()`。加上双击后，双击 = 两次单击 = 面板开了又关 → 一次明显闪烁。

对策（必须写进代码注释，否则以后一定被改坏）：

```
pointerup(moved=false):
    if 距上次点击 < 200ms:
        clearTimeout(pendingClick); OpenChat(); return
    pendingClick = setTimeout(() => TogglePanel(), 200ms)
```

- 双击检测放在**指针流**里，不用 `dblclick` 事件：`pointerdown` 里有 `preventDefault`，而浏览器此后是否还合成兼容鼠标事件是不该依赖的细节。
- 200ms 与系统双击间隔一致；单击手感损失肉眼不可见，但彻底消除「开→关→开」。
- 双击**不加**位移动画或缩放（`transform` 外扩会画到桌面），只用现有透明度过渡。
- 只有**用户明确动作**（双击、点 tab）才 `focus()`；主动说话绝不抢焦点，沿用番茄总结气泡的 `document.hasFocus()` 判断。

**为将来留的余地**：`frontend/src/chat.js` 里的对话视图**不关心自己被挂在哪个容器里**
（它只按元素 id 找节点），所以以后要给「桌宠主动说话」做一张自带输入框的卡片时，
可以把同一份视图挂到气泡上，而不必重写流式渲染那一套。

## 9. 主动说话（默认关，P5 可选）

复用 `decideReminder` 已经解决的判断，再加 LLM 专属门控：

```
LLMProactive 关            → 不说
专注中（focus 且在跑）      → 不说
全屏中                     → 不说
不在活跃时段                → 不说
距上次主动说话 < 最小间隔    → 不说
当日用量超预算              → 不说
```

两个时机：

1. **提醒间隔到点**：不再只列待办，而是让桌宠说一句自然的话（"你 3 件事今天到期，先从哪个开始？"），下面仍保留原来的待办列表。**LLM 失败时自动回退到今天的静态文案**——不可用不是错误路径。
2. **番茄结束**：现有「写总结」气泡里**预填一段 LLM 起草的总结**（关联待办标题 + 时长 + 最近记录），你改完点保存。纯增量，不改记录机制。

若为此新增 `say` 气泡类型（300×160，3 行截断 + 「展开」跳对话面板），**必须同时改 `bubbleLogicalHeight` 与 CSS 盒子**，否则区域裁剪立刻错位。

## 10. 边界情况

| 情况 | 期望行为 |
|---|---|
| `LLMEnabled=false` | 双击仍可打开对话 tab，但显示「去设置里开启」的引导；其余功能完全不受影响 |
| 未配置 Key | 输入框可用，发送时提示「请先在设置里填写 API Key」 |
| Key 失效（401） | 对话内系统消息；设置页红色状态提示 |
| 断网 / baseURL 写错 | 对话内系统消息；**番茄钟、提醒、待办照常** |
| 生成中关闭应用 | `shutdownOnce` 里 cancel 所有在飞请求 |
| 生成中收起面板 | 请求继续，事件仍推；重开面板能看到完整内容（历史已落盘） |
| 生成中再次发送 | 忽略并提示「上一条还在回答」，或先取消再发（实现取「先取消再发」） |
| 历史文件损坏 | 改名 `.bak` + 提示，从空历史开始 |
| 当日预算用尽 | 静默停止自动请求，对话内提示一次，设置页可见用量 |
| 回复超长 | 面板内滚动；`max_tokens` 兜底 |
| 提醒到点但面板开着 | 沿用既有规则：面板在显示时不弹提醒（用户已经在看同一批内容了） |
| 中文 / 长单词换行 | 复用 `.bubble-item-title` 的 `word-break: break-word` |
| 主动说话时长气泡与面板同时要显示 | 沿用三态互斥：面板优先，气泡丢弃 |

## 11. 实现顺序

| 阶段 | 内容 | 验收 |

### 15.2 实现中做出的决定（文档未明确规定处）

| 情况 | 处理 | 理由 |
|---|---|---|
| 上一轮回复未完时用户又发一句 | **取消旧的并标记为「已被取代」**，其残句**不落盘** | 旧残句属于已被替换的问题，落盘会插在新问题与答案之间 |
| 用户主动点「停止」 | 残句**保留**落盘 | 与上一条相反：问题是最后一个，文字是他眼看着出现的 |
| 用量计数 | 请求**发出时**计 1 次，token 到达时只累加 token | 天真的「记录两次」实现会把一条消息算成两次 |
| `stream_options` 被网关拒绝 | 记住并自动去掉后重试一次 | 用户不该为一次字段嗅探反复付费 |
| 流中途断开 | **保留已收到的部分文字**，不重试 | 重试会让已经显示的回答从头再来一遍 |
| 取消的错误 | **不写入对话记录** | 一次刻意的取消不是对话内容 |
| 双击检测位置 | 放在**指针流**里（`pointerup` + 时间戳），不用 `dblclick` | `pointerdown` 里有 `preventDefault`，兼容鼠标事件是否合成不该被依赖 |
| 单击延迟 | **200ms** 后再开关面板 | 否则双击会先「开→关」再弹聊天 |
| 掩码阈值 | Key 短于 16 字符则**全部打码** | 「123…6789」把 9 位密钥暴露了 7 位 |
| 错误详情 | 只取 200 字符 + 去标签 + 压缩空白 + **脱敏** | 网关有时把整个请求（含 Authorization）回显在错误里 |
| 对话与面板的关系（v3） | 对话是**面板的一个 tab**，不额外占面 | 窗口只有一个槽位；做成气泡会与待办面板互斥、且尺寸固定，收益不值得（§8.0） |

### 15.3 实测发现并修掉的真实缺陷

这些都是先写测试、再被测试逼出来的，不是事后美化：

1. **`unsafe.Slice` 是视图不是拷贝** —— DPAPI 返回值被 `LocalFree` 之后才写出，密钥文件里是已释放的内存（解密报 "The data is invalid"）。改成显式 `copy`。
2. **`Flush()` 被大小阈值挡住** —— 少于 24 字符的回复留在缓冲区里：`Result.Text` 正确，但 UI 永远收不到。终端 flush 必须是**无条件**的。
3. **非流式回退把整段文本写进 result 却没推给 UI** —— 界面空白、结果有内容。
4. **`OpenChat` 在窗口调用失败时不通知前端** —— 双击后什么都不发生。事件改为无论如何都发，并带上"该显示哪个 tab"。

**做成气泡卡片那一次抓到的两个（该方案已回退，但教训留着）**：

5. **`clearAllBubblesLocked` 漏了新的气泡类型** —— 它按写死的种类列表逐个清理（`pick/summary/reminder`）。新类型不在列表里，于是**开始一个番茄钟时它不会被收起**，两个面同时抢同一个槽位（区域只能描述一个，结果是画了却看不见或互相覆盖）。
6. **`bubbleAwaitingAnswer` 同样漏了它** —— 提醒会把用户**正打到一半的对话**顶掉。

> 这两条是「给一个既有枚举加成员时，忘了它散落在多少个 switch/list 里」的典型。所以这次回退时，
> 是把 `BubbleChat` 及其所有分支**整体删掉**，而不是留一半 —— 半留着的枚举成员比没有更危险。

7. **被取代的旧请求会在新问题之后追加残句** —— `cancelChat()` 清 id 与 `generation++` 之间存在窗口，旧请求可能正好完成并被判定为「用户主动停止」。合并为一次加锁的 `supersede()`。
8. **前端把「后端 id 尚未到达」误判为过期事件** —— 回复以本地占位 id 开始，后端一开始流式推送就可能早于 `SendChat` 的 promise 解析，导致每次快回复的开头被丢掉、快失败整条丢失。加 `acceptsEvent`。
9. **测试自身的两个问题**：重试退避硬编码让测试白等 8 秒（改为可注入）；DNS 用例依赖真实解析器（改为注入 transport）。

## 12. 实时交流浮层（本次新增）

### 12.1 为什么不是「再做一个对话框」

原来双击打开的是面板的「对话」tab。那是**记录**：整段对话、可滚动、可清空、可重新生成。
但它是 380×520 的一个 tab，输入框在底部、历史在上方，用户想「随口说一句」时得先让面板盖住半个桌面。

浮层把**实时**和**记录**分开：

| | 面板「对话」tab | 实时交流浮层 |
|---|---|---|
| 定位 | **记录**（永久、完整） | **实时**（当前这一轮） |
| 触发 | 浮层的「记录」按钮、设置里说 | **双击桌宠**、桌宠主动说话、设置里「立刻说一句」 |
| 内容 | 整段 transcript | 只有当前一轮：问题 + 正在流式到达的回复 |
| 数据 | 同一份 `llm-history.json` | 同一份 |

**两套 UI 共用同一条对话**：同一份落盘历史、同一组 `pet:chat-delta/-done/-error` 事件、同一套 request id。
两边都监听、各自渲染到自己的 DOM，Go 是唯一事实来源 —— 所以浮层关掉不会中断回复，回头打开面板能看到完整结果。

### 12.2 几何：三块矩形 + 宠物

浮层不是**一个**盒子，而是**三组**互不相连的矩形，加上宠物本身：

```
┌────────────────────────────────┐  ← 卡片：当前这一轮（固定 150 高，内部滚动）
│  你：…                          │
│  桌宠：…                        │
└────────────────────────────────┘
      (o)      ← 指引椭圆 ×3，从卡片边缘走向宠物
    (o)
   (o)              [ 宠物 ]
┌────────────────────────────────┐  ← 输入条（固定 58 高）
│  说点什么…                      │
└────────────────────────────────┘
```

全部画在**现有 540×520 窗口内**，窗口不 resize、不移动 —— 所以宠物一个像素都不动（这是 §2 第一条约束的直接延续）。
窗口区域 = 卡片 ∪ 输入条 ∪ 三个椭圆 ∪ 宠物。

**椭圆必须是真椭圆**，这是新增的能力：`desktop.RegionRect` 加了 `Ellipse` 字段，
`SetWindowRgn` 走 `CreateEllipticRgn`，与 CSS 的 `border-radius: 50%` 是**精确对应**。
用圆角矩形近似不行：34×20 的小椭圆配 10px 圆角，两条轮廓每条边差几十像素，
而区域里页面没画的像素会渲染成叠加的玻璃色（就是那条淡蓝色带的成因，README 10(d)）。

实机像素验证（`.dev/verify-live.ps1`）：椭圆**中心**是绘制的强调色 `216,230,255`，
而其**包围盒角落**是纯桌面 `255,255,255` —— 这条对比就是「区域确实是椭圆」的证据。

### 12.3 三态互斥扩成四态

原来：空闲 / 气泡 / 面板。现在加浮层，仍然是「同一时刻只有一个」：

| 打开 | 收起 |
|---|---|
| 浮层打开 | 面板关上、气泡收掉 |
| 面板打开 | 浮层收掉、气泡收掉 |
| 气泡显示 | 浮层收掉、面板关上 |

这条不变量散落在 `setLiveLocked` / `setBubbleLocked` / `SetPanelOpen` / `showBubble` /
`OpenTodoPanelFromBubble` / `StartDrag` / `ResetToDefaultPosition` —— 每一处都必须同时改，
否则区域会描述一个页面已经不再绘制的东西（§15.3 第 5、6 条就是这个坑）。

另外：**提醒气泡不会顶掉浮层**。浮层是用户正在看的东西，提醒最多是冗余的；
手动「立刻提醒」也不例外（和 picker/summary 同样的理由）。

**反过来有一条例外：浮层也不顶掉"提问气泡"**（选择待办 / 写总结）。

```
浮层打开  →  面板关上、气泡收掉        ← 但若气泡正在等回答，则整个操作被拒绝
面板打开  →  浮层收掉、气泡收掉
气泡显示  →  浮层收掉、面板关上
```

浮层和 `#bubble` 共用同一块矩形（RegionRect 只能描述其中一个），所以打开浮层不是
"盖住"提问，而是**删掉**提问。总结气泡又是休息的门控，删掉它 = 计时器永久停住且屏幕
上没有任何解释（`reminder-pomodoro.md` §4.5.1），所以：

- `OpenLive` 读 `unansweredQuestionKind()`，有问题就直接返回错误（说清是哪一个问题），
  **不改任何状态**；
- 反方向不需要新代码：提问气泡出现时 `showBubble` 本来就会把浮层收掉（`setLiveLocked(false)`），
  这是对的 —— 浮层只是"当前这一轮"的视图，回复照常到达并落盘，再双击就能看回来；
- 前端 `openLive` 也读同一个状态，因为"操作失败"的 toast 长在面板里、而气泡占着槽位时
  面板必然关着 —— 报错弹在看不见的地方等于什么都没说。双击桌宠于是变成"**去回答问题**"：
  光标落进总结输入框（选择气泡则落在「开始专注」按钮上）。
- 主动说话（下一节）会自动弹浮层，所以它也被 `awaitingAnswer` 这一道门挡住。

提醒气泡和面板**没有**这层保护：前者不提问，后者本身就能回答（记录页可改总结）。

### 12.4 主动说话（P5，默认关）

门控从「五重」变成实际上**九条**，任一命中就不说话：

```
LLM 未开启 / 未就绪        → 不说
LLMProactive 关            → 不说（默认）
当日预算用尽                → 不说
专注中（focus 且在跑）      → 不说
全屏中                     → 不说
面板或浮层开着              → 不说
有气泡在等回答（选择/总结）  → 不说
不在活跃时段（复用提醒的时段）→ 不说
没有可聊的内容（无待办、番茄钟关、今天没完成过）→ 不说
距上次主动说话 < 最小间隔     → 不说
```

判定是**纯函数** `decideProactive(...)`，和 `decideReminder` 一样可以脱离时钟/窗口/宠物单测
（`app_live_test.go`，含「专注中 200 次迭代永不说」这类穷举）。

说话流程：`speakProactive()` → `startChat(proactive)` → 流式回复 → **同时打开浮层**。
两条数据上的讲究：

1. **那条指令永不落盘**。它作为最后一条 user 消息发给模型（在 history 之后追加），
   但**不写进 transcript** —— 它是系统提示，不是用户打的字；写进去会让面板的记录变成假话。
2. **回复本身带 `proactive` 标记并落盘**。这是「这一轮是它自己开口的」的唯一记录。
   前端靠它决定**不要**在回复上方画问题行 —— 否则主动说的话会挂在用户上一句问题下面，
   读起来就像是那句的回答。这个标记**每一个事件都带**（delta 也带），
   因为浮层在看到第一个 delta 时就要决定画不画问题行。

回复长度在**到达后**截断（80 字），且截断的是**推给前端的同一份文本**：
卡片高度固定，超出的部分会在完成的那一帧滚出视野 —— 看起来就像桌宠什么都没说。

### 12.5 键盘焦点

- 双击 / 点「立刻说一句」→ 这是**用户明确动作**，聚焦输入框。
- 桌宠**主动说话** → **绝不聚焦**。用户很可能正在别的程序里打字（沿用 §8 的结论）。
