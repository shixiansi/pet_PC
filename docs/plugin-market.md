# 插件市场：管理插件的独立程序

**插件市场是一个独立的程序**（`tools/plugin-market/`，产物 `PetPCPluginMarket.exe`），
不是桌宠面板里的一个标签页。

它负责**全部**插件管理：浏览市场、安装、逐项授权、启停、卸载，
以及编辑插件自己声明的配置（包括对话插件的 AI 配置与 API Key），
还有**把插件挂起来测**（「扩展能力」页，见 §2.16）。
桌宠只负责**运行**插件。

---

## 1. 为什么搬出去

最初插件管理是桌宠面板的第 5 个标签页「插件」：上面是已装列表，下面是市场列表，
底部一个地址框。写这个 change 时对着真机截图逐项复核，四项问题**都不是布局技巧能解决的**：

| # | 截图里的现象 | 根因 |
|---|---|---|
| 1 | 权限勾选行被右边界**切断**，说明文字看不全 | 详情区可用宽度不足，而权限说明是一句话，不是几个字 |
| 2 | 地址框**只剩半截**，保存按钮**另起一行** | 380px 里放不下「输入框 + 保存 + 刷新」一行 |
| 3 | 对话框与两个列表**争抢同一块滚动区** | 面板只有一条滚动条，三个独立滚动的面挤在一起 |
| 4 | 可点击区域与提示文字**尺寸不匹配** | 面板的纵向空间被压缩到只能画小控件，命中区跟着变小 |

根因是同一个：**面板是固定 380×520 的矩形**，由 layout 决定、窗口区域又按它裁剪，**不能长大**。
而插件管理是个**工作面**——左边两份列表、右边详情 + 权限表 + 配置表、上面还有地址栏——
它需要的宽度和高度都不是「再挤一挤」能腾出来的。

这与配音工坊当初拆出去的理由完全一致（见 `docs/voice-studio.md` §1）——**而且那个工坊最后正是被并回了这里**：语音变成插件之后，它的工坊界面由**本程序**托管（见 `docs/voice.md` §3），所以独立程序从三个减回两个。

---

## 2. 搬出去之后的结论

四项问题逐条对照**现在**的实现：

| # | 搬出去之前 | 搬出去之后 | 由什么保证 |
|---|---|---|---|
| 1 | 权限行被右边界切断 | 权限行**完整可见**，说明文字**换行**而不是被裁 | 每个权限是一整行 `.perm`，标签与说明共用一个可换行容器；`.dev/verify-plugin-market.ps1` 在详情列右边界**内侧 2px** 的竖条上做像素扫描，那里必须是背景色而不是字形 |
| 2 | 地址框只剩半截、保存按钮换行 | 地址框**占满可用宽度**（≥ 容器 90%），保存与刷新**同一行** | 地址行是一条 flex：输入框 `flex: 1` 吃掉按钮之外的全部像素；同一个门禁量它的可见宽度并与容器比较，且要求按钮与它在同一水平带内 |
| 3 | 对话框与两个列表抢一块滚动区 | 列表与详情**分区滚动**，各自独立 | `#detail-pane` 是 `#list-pane` 的**兄弟**而不是子元素，两个 `.pane` 各自 `overflow-y: auto`；静态检查钉住这层结构 |
| 4 | 可点击区域与提示文字尺寸不匹配 | 对话框**不溢出被裁**，控件按正常尺寸绘制 | 窗口是普通带框可缩放窗口（`Frameless=false`、`WS_THICKFRAME`），有 980×700 的初始客户区和一个合理的最小尺寸，不再受 380×520 约束 |

窗口规格：**普通带框、可缩放**的 980×700（`MinWidth 720` / `MinHeight 520`）、
不置顶、不透明背景、标题「PetPC 插件市场」。

### 2.1 界面重做（第二轮：从「搬出来能用了」到「像个正常程序」）

搬出去解决了**空间**问题（上面四项），但没有解决**信息组织**问题。真机截图里的第二轮问题是四类：

| # | 截图里的现象 | 根因 | 现在由什么保证 |
|---|---|---|---|
| 1 | 同一个插件在左栏出现**两次**（已安装一次、市场一次），名字/版本/描述完全一样，3 个插件画成 6 张卡片 | 左栏把两份列表**上下堆叠**，没有任何东西说明哪份是哪份 | 左栏改成**分段开关**（`.list-tabs`：已安装 / 市场），**一次只显示一份列表**；两份列表都仍在 DOM 里且都照常渲染，所以切页不发请求、目录页也照旧读已安装列表来定自己的标签 |
| 2 | 看不出「这个插件现在到底是什么状态」 | 状态只由**哪些按钮恰好可见**表达（有「更新」= 已装且落后；没有按钮 = 未装），要靠反推 | 详情区顶部一个**状态徽标**（`#detail-state`：已启用 / 已停用 / 未安装 / manifest 读取失败），当前状态直接读出来；每行左边缘再加一条**状态色条**，整份列表可以扫而不是读 |
| 3 | 「卸载」和「启用」挨着，还是最靠左的主按钮之一 | 最危险的操作放在最常用的控件旁边，且和「安装」同样重 | 操作栏用 `.action-gap` 把「插件是什么」与「插件在不在」分开：主操作靠左，`卸载`（改成**描边**而不是实心红）与启用开关靠右；启用开关由裸 checkbox 改成真开关 |
| 4 | 配置表单是一条很长的单列全宽输入框，宽窗口大半空着 | 单列布局，12 项配置要滚很久 | 配置表单改成响应式**两列栅格**（`.cfg`），长内容字段按自身形状（长标签/长值/带说明/多行）自动占满整行 |

**动的是界面，不是判据**：插件生命周期、权限语义、配置读写、沙箱与共享实现一行没改，
市场仍然只做 `internal/plugins` 的投影。改的只有 `frontend/{index.html,src/style.css,src/main.js}`
与它自己的测试。

### 2.2 界面重做（第三轮：从「像个正常程序」到「看得出层级」）

第二轮解决了**信息组织**，第三轮只动**视觉层级**——判据、绑定与 `internal/plugins` 一行未改：

| # | 上一轮的样子 | 现在 | 机制 |
|---|---|---|---|
| 1 | 一行插件就是一个灰色矩形加名字，同一个插件在已安装列表与目录页里看不出是同一个 | 每行与详情头部各一个**monogram 字母块**，色相由插件 id 哈希得出 | `.avatar` + `main.js` 的 `avatarTint`/`paintAvatar`；同一 id 两处颜色必然相同，没见过的插件也不会退化成统一的灰 |
| 2 | 页面、卡片、输入框是同一个灰，卡片只靠一圈 1px 边框站立 | 四级表面：画布 `--bg` → 面板/卡片 `--bg-soft` → 行 `--bg-card` → 输入框 `--bg-input`，每级差 6–8 个色阶 | `:root` 的色阶；详情区三块内容各自成卡（`.dsec`） |
| 3 | 权限行是「卡片里套卡片」，两层边框说同一件事 | 权限卡内是**扁平行**，只用 1px 分隔线；复选框自绘（深色方块 + 白色勾） | `.perm` 去掉边框；`input[type=checkbox]` 用 `appearance:none` + 内联 SVG 勾 |
| 4 | 行里只有名字、描述和一个游离的标签 | 名字 + 版本胶囊；描述两行截断；页脚 = 状态胶囊 + 作者 | `.row-title` / `.row-ver` / `.row-foot` / `.row-author`（版本胶囊在第六轮改成同族等宽小字，见 §2.6） |
| 5 | 配置面板与它自己的输入框同色，输入框只剩一圈边框可辨 | 配置面板比输入框浅一档，字段框看得见 | `.cfg` 的 `background: #10141b`，输入框仍是 `--bg-input` |
| 6 | 未安装插件的「配置」区留着一个空的黑框 | 空配置面板**整个隐藏**，只留一行「安装后才能配置。」 | `renderConfigPane` 里 `show(els.cfgForm, …)` |

**门禁照旧，并且重新量过**：`.dev/verify-plugin-market.ps1` 在新界面上仍是全绿
（地址行占其份额 99.8%、三个控件框、详情列右边界内侧 2px 仍为背景色）。
两处**测量口径**值得写下来，因为它们是「改样式」最容易踩的坑：

1. **表头三个控件不许加外阴影**。门禁靠 8px 空白间隙把输入框、`保存`、`刷新`分成三段
   ink run；带扩散的阴影会把这 8px 填上墨，三段并成一段，检查报「found 1 control box」。
   所以按钮只有 `inset` 高光，外阴影只出现在 toast、安装对话框与 monogram 这些量不到的地方。
2. **滚动条宽度是实测量**。门禁采样客户区右边缘内侧 18px 的那一列，并要求它是背景色。
   有滚动条时内容盒比客户区窄「16px + 滚动条宽」，那一列落在内边距里；把滚动条收窄
   （或让内容短到根本不需要滚动）就会把这一列挪进卡片，读数立刻变成「文字越界」。
   现在宽 12px，理由注释就写在 `::-webkit-scrollbar` 上方，改宽度前先读它。

新增的两条 jsdom 用例钉住第 1 与第 4 项：`gives a plugin one monogram, the same in the
list and in the header`（行与详情头部的 `--tint-a`/`--tint-b` 必须逐字相同，monogram 是
`aria-hidden`）与 `keeps the version beside the name and the author in the row footer`。

同时修掉了**门禁自身的两个哑火**（都不影响上面的产物，但它们让「已通过」变得不诚实）：

1. **种子数据编码**：`.dev/verify-plugin-market.ps1` 用 here-string 写带中文的 manifest，
   而 Windows PowerShell 5.1 会把**无 BOM** 的 `.ps1` 按系统 ANSI 代码页（本机 GBK）读取，
   于是落盘的 manifest.json 是 GBK 字节、却被加载器按 UTF-8 解析 → **不是合法 JSON** →
   详情区只画一行报错、**一条权限行都没有** → 「右边界内侧 2px 是背景色」这条检查
   在**一个没有权限行的面板上**通过。这是种子数据存在的意义所要防止的**空洞通过**。
   现在该 manifest 的名字与描述写成 `\uXXXX` 转义，文件是纯 ASCII，任何代码页都改不坏它。
2. **地址行根本没被量到**：门禁报告「found 1 control boxes ... could not be measured」后**跳过**检查。
   根因是 `Runs` 用「本带内最常见的颜色」当背景，而地址框一宽，**输入框自己的填充色**就成了那个颜色，
   于是除输入框外的每一列都算「有墨」，整行并成一段。
   现在背景色改为**采样**页面左上角（布局到不了的点），测量函数接受调用方给的颜色，
   并把「量不出来」从**提示**改成**失败**——量不到自己要量的东西，就是没通过。

### 2.3 界面重做（第四轮：详情区只留「这个插件」，其余浮起来）

第三轮解决的是**视觉层级**，但详情区仍然是**一条长页面**：权限表、配置表、插件自己的界面
从上到下堆着。这一轮试了两版：先做成选项卡，用户指出**用一个选项卡装一张永远存在的列表**
就是多余的一行装饰、**配置页和顶部齿轮重复**、**插件界面被套在带标题和「沙箱内运行」角标的
卡片里**；再改成「动作栏下方展开的面板」，用户又指出**面板照样占位置、会把工坊往下挤**。
最终形态是：**权限＝贴着按钮的悬浮层，设置＝弹窗，界面＝面板本身**。

| # | 上一版的样子 | 现在 | 机制 |
|---|---|---|---|
| 1 | 权限展开是页面里的一块面板，点开就把工坊往下推 | 权限是**贴着「权限」按钮的悬浮层**（popover），浮在工坊之上、不占布局；再点一次、点别处、按 Esc 都收起 | `#perm-popover` 挂在 `<body>` 末尾 + `position: fixed` + `positionPermPopover()` 用按钮的 `getBoundingClientRect()` 定位（**不能**放进详情列：那一列是滚动容器，会把它裁掉），并夹在窗口与详情列之间 |
| 2 | 「配置」选项卡与顶部齿轮是同一件事的两个入口 | 只留**齿轮**，它开的是**弹窗**：改完 保存 就关；插件没声明配置项时整个按钮不出现 | `#settings-sheet` 与安装确认共用 `.sheet`（一个程序一个模态框）；`applyPanels()` 里 `hasConfig` 决定按钮与弹窗 |
| 3 | 权限单独占一个选项卡，还要先展开一层下拉才看到勾选行 | 权限的**计数就在按钮上**（`4/5`），点开就是勾选列表，勾选/取消即授权（沿用「改即保存」） | `#perm-count` 是按钮里的徽标；`renderPermCount()` |
| 4 | 插件界面套在带标题与「沙箱内运行」角标的卡片里，固定 520px，自己再滚一次 | 界面**是面板剩下的全部**：没有卡片、没有标题、没有角标，滚动交给插件自己的文档；两个浮层都不占布局，所以永远挤不到它 | `.panel-interface` 是 `#detail`（flex 列）里的 `flex: 1 1 auto`；沙箱仍是 iframe 上的 `sandbox="allow-scripts"` 属性——**属性在**，外框没了 |
| 5 | 面板/浮层的开合状态跟着上一次渲染走，换插件可能带着上一个的形态 | 换插件**两个浮层都关**；插件停用/卸载时它们的入口一起消失；但同一次会话里的重渲染（勾权限、切开关）**不会把用户打开的浮层关掉** | `select()` / `confirmInstall()` 里重置 `state.permsOpen`/`state.cfgOpen`；`applyPanels()` 只读状态。打开设置弹窗时会顺手收起权限浮层——模态框盖住了它，留一个看不见也关不掉的层更糟 |

顺带修了一处**弹窗自身的老毛病**：`.sheet-box` 原来是「整块一起滚」，12 项配置的插件会把
`保存` 顶到视口外，用户得先滚到底才能存。现在它是**flex 列**：表单区自己滚，`关闭 / 保存`
固定在底部。

被这轮改动影响到的**测量口径**，必须写下来（它是最容易被"改样式"踩坏的一条）：

> `.dev/verify-plugin-market.ps1` 采样详情列「内容边缘内侧 2px」的竖条，要求那里是**背景色**。
> 第三轮它成立靠的是「详情列**一定**有滚动条」——`.pane` 的内边距 16px + 滚动条 12px，
> 采样列因此落在内边距里。把长内容收起来之后，5 项权限的插件**根本不需要滚动条**，
> 内容盒于是长到离边缘只剩 16px，采样列落进卡片、读数会变成「文字越界」。
> 修法不是放宽 5% 的阈值，而是让那个前提重新成立：`.pane` 加 **`scrollbar-gutter: stable`**，
> 无论要不要滚动条都预留 12px。这样采样列在**两种情况下都是内边距**，顺带也不再出现
> 「内容跨过一屏时面板宽度跳一下」。
> 这一轮在真窗口里跑过门禁：**ALL PLUGIN MARKET CHECKS PASSED**，其中
> 「右边界内侧 2px」的偏差是 **0%**（x=946）。

jsdom 用例（`tools/plugin-market/frontend/src/main.test.js` 的 `detail surfaces` 组）钉住上面每一条：
**两个浮层默认都关**、浮层是 `position: fixed` 且**不在 `#detail` 里**（所以挤不到工坊）、
界面直接铺开且没有标题/角标（并断言 `sandbox` 属性还在）、权限按钮上的计数与勾选即授权、
**点浮层内部不关、点别处关、Esc 关**、齿轮只在声明了配置项时出现、弹窗的标题/关闭/保存与
「保存后关闭」、插件停用/未装时不出界面、重渲染不关用户的浮层、换插件重置、以及每个控件都有图标。

### 2.4 顶部栏、详情头与主题（第五轮）

用户看完第四轮的两张截图提了四条：**详情区那一块**（头像/名称/描述/一排按钮）三个横条各自浮在
页面上，右下角那排按钮左边全是空的；**顶部把「插件市场」又写了一遍**读着别扭；**希望能切主题**；
然后追加两条：**「已启用」标签去掉**（开关已经说得很清楚）、**把权限/启用/卸载挪到跟设置一行**。
这一轮只动排版与配色，判据与绑定一行未改（除了多出 `Theme` / `SetTheme` 两个只读写一个字符串的绑定）。

| # | 上一版的样子 | 现在 | 机制 |
|---|---|---|---|
| 1 | 头像/名称/徽标一行、描述一行、动作栏一行，三块都飘在页面背景上；已安装时动作栏全挤在右下角，左边大片空白 | 整个插件头是**一张卡片**：**身份行（头像 + 名称/版本作者 + 四个控件）** 和它下面的描述。控件全在**名称那一行的右端**：`权限 / 启用 / 设置 / 卸载`，一行四个，不再有自己的页脚 | `.detail-head`（列 + 边框 + 圆角 + `--bg-soft`）/ `.detail-identity`（flex + `flex-wrap`）/ `.detail-actions`（`margin: 0 0 0 auto` + `justify-content: flex-end`，**没有** `border-top`，`.action-gap` 占位符已删） |
| 2 | 徽标「已启用」占一个位置，说的和右边开关是同一件事 | **没有徽标了**。状态就是开关：开着/关着，点一下就是切换；manifest 坏掉时是**红字错误行 + 禁用的开关** | 删掉 `#detail-state` / `renderStateChip()` / `.chip` 一族；列表行的色条与标签保留（那是「扫列表」用的） |
| 3 | 顶部左边是渐变方块 + 「插件市场」+ 来源徽标，右边是地址与两个按钮 | **一行**：主题开关、来源徽标、「市场地址」、地址、保存、刷新。页面不再重复窗口标题里已有的字，省下的 ~90px 全给地址栏 | `.top` 变成单一 flex 行，删掉 `.top-left`/`.top-right`；主题开关在**地址左边**，因为真窗口门禁取「最右三个控件框」= 输入框/保存/刷新，放右边会把它量的东西换掉 |
| 4 | 只有深色 | **深/浅两套**，开关在顶部左边；图标画的是**点下去会得到的**那个（深色时是月亮，浅色时是太阳），`aria-label` 说同一件事 | `:root[data-theme="light"]` 重定义全部颜色 token（不是第二份样式表）+ `applyTheme()` 往 `<html>` 写 `data-theme`；`color-scheme` 一起切，原生控件跟着走 |
| 5 | — | 主题**记住**：它进 `plugin-market.json` 的 `theme`，重启还在；`""`（旧文件没有这个键）读作深色 | `Market.Theme()` / `Market.SetTheme(name)` 两个绑定 + `config.go` 的 `Theme` 字段；值在**读入时**归一化，除了 `light` 一律 `dark` |

身份行用 **flex + `flex-wrap`** 而不是 grid：`.detail-heading` 的 basis 是 96px（这一轮定的；第六轮
把 120px 降到 96px 是因为启用开关加了框，见 §2.6），能放下就**一行**
（980 默认窗口就是一行），放不下时**整组控件换到第二行**，而不是把名字挤成一列单字
（先试过 grid + 固定中列，900px 下名字被压到 60px、一个字一行，已回退）。
`#detail-meta` 因此改成**单行省略**，只显示 `版本 · 作者`，完整 `id · 版本 · 作者` 在 `title` 里。

#### 亮色下三处"看不见"的地方（用户指出的）

浅色不是把深色反过来就完事：深色里靠"更亮一点"表达的层次，在白底上全都消失了。用户点出的两处，
加上一处顺手查出来的：

| 位置 | 浅色下的毛病 | 现在 |
|---|---|---|
| 左栏的行与选中行 | 面板与行**都是纯白**，只靠 1px 边框分家；选中行是一层 16%→9% 蓝，在白底上等于没有 | 新增 `--pane-bg`（面板比画布**亮**一档、比行**暗**一档），选中行整套放进 `--row-sel-bg/-border/-shadow/-stripe`：浅色下是真蓝底 + 实心蓝边 + **4px** 色条，深色下仍是原来那层淡淡的光 |
| 选中行的**插件名** | 名字原来写死 `color: #fff`——深色下（淡蓝洗在近黑卡片上）正好，浅色下变成**白字落在 `#e8f0ff` 上，等于没字** | 提成 `--row-sel-text`：深色 `#ffffff`，浅色指回 `--text-strong`。测试同时钉住"规则必须用这个 token"且"浅色那份不许是白色" |
| `已安装 / 市场` 分段开关 | 轨道用 `--bg`、当前项用 `--bg-card-hi`，浅色下**两者都是近白**，整条读成一个白条，看不出当前在哪一份列表 | 新增 `--track` / `--track-pill` / `--track-pill-shadow`：浅色下轨道是画布上的一档灰、当前项是**白色凸起** + 细阴影；深色不变 |
| 任意"色彩 token" | — | 见下 |

**顺手查出来的真 bug**（不是配色偏好）：那一轮把颜色机械替换成 token 时，`--ok-fg: #8fe0b6` 这种
**定义行本身也被替换**了，于是变成 `--ok-fg: var(--ok-fg)` —— 自我引用。它**看起来**"已定义"
（名字在、值在），但按规范这是 *invalid at computed-value time*：所有 `var(--ok-fg)` 都退化成
继承色，于是深色下的绿色「已启用」标签、权限名、卡片内嵌面板底色全都悄悄丢了，**没有任何东西报错**。
现在改成正确字面量，并把「两套调色板的 token 名必须一一对应」的测试扩成
**"任何 token 不许自我引用"**，防止再犯。

#### 插件界面怎么跟着主题走

插件工坊是 **sandboxed iframe 里的外来文档**：它看不到本页的 CSS 变量，宿主也不该往里注入样式。
所以是**告知**，不是覆盖，三条通道各管一段时间：

1. **`?theme=dark|light` 挂在 frame URL 上** —— 插件在 `<head>` 里一个内联脚本读它并写到
   `<html data-theme=…>`，**首帧之前**就生效，浅色窗口不会先闪一下深色；
2. **`init` 带着 `theme`** —— 桥协议里多一个字段，插件在 `onInit` 里应用（同一份文档也可以被桌宠
   挂载，那时没有方案，一律深色，行为与以前一致）；
3. **`theme` 消息** —— 用户**在工坊开着的时候**切换主题，宿主 post 一条消息；插件改
   `data-theme` 即可，**不重挂 frame**（重挂会丢掉输入到一半的表单和滚动位置）。

宿主侧（`plugin-ui.js`）：`windowTheme()` 读 `<html data-theme>`；`setFrameTheme()` 负责 (2)(3)；
frame 元素上还设置 `color-scheme`，让文档里的原生滚动条/光标跟着走。
插件侧：`chat` / `qq` / `voice` 三个包各加一个 `html[data-theme="light"]` 调色板块
（`qq` 本来就是 token 化的，只重定义变量；`chat`/`voice` 原来是散落的字面量，先把它们收成
`--p-*` 变量再加浅色块 —— 深色一个字节没变）。

**一个坑必须写下来：插件是"安装时复制"的。** 宿主加载的是 `<dataDir>/plugins/<id>/` 里的那一份，
不是本仓 `market/plugins/<id>/` 的源码——所以**只改源码、不重新打包并让市场装一次，窗口里的插件
仍然是旧的那份**（这一轮第一次拍图时正是如此：QQ 与语音的工坊依旧深色，因为机器上装的是
`qq 1.9.0` 与 `voice 1.0.0` 的旧拷贝）。修法按仓里的发版流程走：

1. 三个包升 patch：`chat 1.4.0 → 1.4.1`、`qq 1.9.0 → 1.9.1`、`voice 1.0.0 → 1.0.1`；
2. `pwsh -File market/tools/package.ps1` —— 重打 zip、实算 sha256、回写 `market/index.json`，
   并**刷新**宿主内置源 `internal/plugins/sample/` 里已有的那些包（同名同版本才换字节；样例的
   `index.json` 按磁盘重算 sha256 后重写）。它**不会**把市场目录整个抄进兜底源：`sample/embed.go`
   是一份手写的包名单，多出来的 zip 会让兜底目录宣告 36 个下载、二进制只带 10 个；
3. 想让兜底源跟着**换版本**，仍然是手工的：新包放进 `sample/`、删掉被取代的旧包、把
   `sample/embed.go` 的 `//go:embed` 清单改成新文件名（它逐一列名，不改就**编译失败**——这是好事），
   然后再跑一次脚本，让样例 `index.json` 的版本与 sha256 对上；
4. 重编市场程序（内置源随 exe 一起走）；
5. **本机**把这三份新包装进 `<dataDir>/plugins/<id>/` 并在 `plugins.json` 里改版本号，等于替用户
   做了一次「更新」——不动 `plugin-data/` 里的私有数据与授权，所以设置与密钥都还在。

线上发布（`git push` 到 `PetPC-plugin`）仍由维护者执行：远端 index 还是旧版本时，市场里的
「更新」按钮不会出现，这一步不由 agent 做。

### 2.5 第五种控件：`select`（用户：「谁知道 36 是知识」）

用户对着 B 站插件的设置截图问：**「这里数字分区，用户根本不知道分区对应的数字啊，不能改成选分类吗」**。
那一栏写的是「分区（逗号分隔 rid，例如 36=知识 188=科技 181=影视）」——把一张对照表塞进了 label，
让用户自己背。这不是文案问题，是**控件类型少了一种**。

清单的 `config[]` 原来只有四种控件：`text` / `number` / `bool` / `secret`。现在加第五种：

```json
{ "key": "rids", "label": "分区（可多选）", "type": "select", "multiple": true,
  "default": "36,188,181",
  "options": [{ "value": "36", "label": "知识" }, { "value": "188", "label": "科技" }] }
```

| 位置 | 变更 |
|---|---|
| `internal/plugins/manifest.go` | `ConfigValueTypes` 加 `select`；`ConfigItem` 加 `options`（`{value,label}`）与 `multiple`；`validateConfigOptions`：**至少 2 个选项**、value/label 非空、value 不重复、label 不超 64 字、最多 64 项；`select` 不许同时是 `secret` 或 `hostWhitelist`；非 `select` 不许带 `options`/`multiple` |
| `tools/plugin-market/market.go` | `ConfigEditor` 多带 `Options` / `Multiple`（原样来自清单，编辑器不发明选项） |
| 市场前端 `main.js` | 单选画 `<select>`；多选画复选框组（`.checks`），**值仍是逗号分隔的字符串** —— 插件那边本来就 `split`，一行没改 |
| 市场前端 `style.css` | `.field .checks` 换行排列并占满整行（`fieldWantsFullWidth` 对 `select` 返回 true） |

两条判断值得记下来：

1. **校验在作者侧就失败**。一个没有选项的 `select` 会画出一个空下拉——用户点开什么都没有；一个
   没有 label 的选项在界面上是一行空白。两者都在 `ParseManifest` 里拒掉，而不是变成市场里的一行坏控件。
2. **`select + secret` 的报错文案**：原来的「type 与 secret 必须一致」会先命中，于是作者看到的是
   一句与他实际错误无关的话。所以 `validateConfigOptions` 排在 secret 一致性检查**之前**，
   报「select 不能同时是 secret」。

B 站插件因此改了 4 项：分区（22 个选项）、来源（4 个）、摘要长度（3 个）、评论模式（2 个）。
清单项数不变（31），也没动任何插件逻辑。

用户这次的反馈只有一句「优化一下插件市场整体的样式布局」，没有点名。所以这一轮先做的事是**量**：
把真窗口按 980×700 拍下来，再放大到 3 倍逐块看。读完得到的问题不是"哪里丑"，

**两条回归是这一轮自己的教训，都记在这里以免下次再犯：**

1. **启用加框后，动作栏在 964px 客户端宽度下换行了**。第 2 轮定下的形态是"四个控件跟名字同一行"，

   修法不是把框去掉，而是把**名字块**的 basis 降到 96px（名字仍然会先长到剩下的空间）、

2. **`.top` 里一条多余的 `.top-right input#market-url` 早已失效**（`.top-right` 在第 5 轮就被删了）：
   它不影响任何像素，所以门禁一直是绿的，也所以它一直没人发现。这一轮删掉了，并在原处留下说明。

门禁口径**没有变**，这一轮的改动全部落在被量的数字之外：三个控件框、8px 间隙、无外阴影、

`.dev/verify-plugin-market.ps1` 能证明，而后者需要先构建 exe。

### 2.7 骨架重做（第七轮：从「两栏管理器」到「商店」）

用户看完第六轮的效果只说了四个字：「还是好丑」，然后是三版候选（放大层次 / 紧凑工具 /
玻璃质感）全部否决。到这一步才承认：前六轮改的都是**皮**——间距、字号、徽标、控件高度——
而窗口的**骨**（信息架构）从来没动过。三条证据：

1. **顶栏是一条调试条**。窗口最显眼的位置摆着一串 70 字符的镜像 URL。任何程序把裸 URL
   摆在正中间都会立刻显得像开发者工具，而这串地址一年也改不了第二次。
2. **信息架构反了**。这是「市场」，可默认视图把**某个插件自己的运行时页面**摆在主舞台，
   占掉一半面积；逛与装这两个正事被挤到 310px 的侧栏里。
3. **没有商品感**。左栏 4 个一模一样的行、每行重复一遍「已启用」和作者名、字母色块像占位符；
   整窗没有搜索、没有分类、没有重点色，只有边框和灰字。

| # | 上一版 | 现在 | 机制 |
|---|---|---|---|
| 1 | 左栏插件列表 + 右侧详情，两栏常驻 | **两个视图，一次只显示一个**：市场网格，或某个插件的页面 | `#grid-view` / `#detail-view` 是 `<body>` 的兄弟；`goGrid()` / `goDetail()` 只切换 `hidden`，两个视图都照常渲染 |
| 2 | 顶栏：主题开关 + 市场地址 + 保存 + 刷新 | 顶栏只剩**标记 + 搜索框 + 刷新/设置/主题**；地址进设置弹层 | `#market-sheet`（地址 + 保存并刷新），齿轮打开；`#search` 实时过滤名字/作者/描述/权限 |
| 3 | 每个插件在左栏是一行，状态是绿色胶囊 + 左侧色条 | 每个插件是**一张卡片**：46px 应用图标（右下角一个状态点）、名称、版本·作者、两行简介、底部状态词 + 一个动词（安装/更新/打开） | `.card` / `.app-icon` / `.app-dot`（`is-on/is-off/is-err/is-update`）/ `cardFor()`；`gridEntries()` 把**目录与已安装两份数据合并**，装了但目录里没有的插件照样出现 |
| 4 | 详情是一张头卡片 + 一个面板 | 详情是**一页**：面包屑 → hero（图标 + 22px 名称 + 两行简介 + 三枚事实徽章 + 动作条）→ 左边插件界面、右边权限栏 | `.crumb` / `.hero` / `.badges` / `.detail-body` / `.workspace` / `.rail` |
| 5 | 权限是要点开的浮层，计数在按钮上 | 权限是**右侧栏的第一块面板**，常驻、就地勾选、计数在面板抬头（`8 / 8 已授予`） | 删掉 `#perm-popover`、`positionPermPopover()`、`applyPanels()`、`state.permsOpen` 与"点别处关闭"；`.rail` 整列滚动 |
| 6 | 插件界面"就是面板"，外面没有任何边界 | 界面装进 `.workspace`：圆角 + 1px 边 + **一条说明带**（"插件界面 · 在沙箱里运行，只拿到你勾选的权限"） | round 4 去掉外框的理由是"框套框"；但用户点名这块最丑——它需要的不是装饰，是一条**边界**，让眼睛知道下面是插件的页面 |

**两个窗口入口的取舍**（用户选定）：装了插件的机器，窗口**默认打开上次那个插件的页面**，
「插件市场」按钮回网格；没装任何插件才落在网格上。理由是这个程序同时是插件工作面的宿主，
每次启动多一次点击去干活，比商店页多一次点击更贵。`state.view` 不落盘，`selected` 落盘。

**这一轮真正的教训写在这里**：前三版都是在同一个骨架上换颜色和字号，所以"都好看不起来"。
改骨架之后，同样的配色和字号突然就成立了——**观感问题先怀疑结构，再怀疑样式**。

### 2.8 界面重做（第八轮：换到 Svelte 之后，插件自己的界面丢了又接回来）

`openspec/changes/ui-rebuild` 把本程序的界面搬到了 `cc/`（Svelte 5 + TypeScript），
`tools/build-all.ps1` 的做法是「先 build cc，再用 `cc/dist` 覆盖 `frontend/dist`」——后者才是
`//go:embed all:frontend/dist` 读的那棵树。于是**旧的那套 JS 页面（`frontend/`）不再出货**，
而 `ui-rebuild` 的阶段 3 只写了「插件列表与权限勾选搬进控制中心」，**插件界面、市场目录与
安装、配置编辑器三项从来没有被列进任务**，一起丢了。

代价不是「少看一块界面」：`market/` 四个插件里，voice / qq / bilibili 三个是
`panel: false`、`surface: []`、`background: true`——它们的 `entry` **只可能由本程序以
`surface.slot = "workshop"` 挂起来**。本程序不挂，它们在任何程序里都没有可见界面，只剩桌宠里
一个看不见的常驻帧。修复记在 `openspec/changes/plugin-page-workspace`。

现在的插件页是**主从布局**：

| 位置 | 是什么 | 为什么 |
|---|---|---|
| 左栏 | 已装插件列表（状态点 / 名字 / 版本） | 一屏扫得完；名字缺 ID 的行会把对象原样打出来 |
| 右栏 | **这个插件自己的界面**（沙箱 iframe，`/plugin-asset/<id>/<entry>?theme=…`） | 见上：三个插件的界面只可能活在这里 |
| 「权限 n/m」 | `<details>` 上挂的**绝对定位面板** | 沿用 §2.3 的结论：展开不能把工坊往下挤。关闭时**不占布局**，内容仍在 DOM 里（`render-smoke.mjs` 因此能断言文案来自宿主，而 jsdom 本来也不实现 `<details>` 的点击开关） |
| 「设置」 | **弹窗**，只在插件声明了 `config[]` 时才出现 | 同一个结论的第三面：配置表单在流程里占高度、把工坊挤下去。表单区自己滚、`关闭/保存` 固定在底部（12 项的插件在 520px 高的窗口里会把 `保存` 顶到视口外，§2.3 记过这件事）。没有声明就没有按钮——一个打开空表单的齿轮和"什么都不做的开关"是同一类缺陷 |
| 「展开界面」 | 收起左栏，界面拿到整页宽度 | 980−168（侧栏）−48（内边距）−232（左栏）≈ 510px，而语音工坊在 **720px** 就塌成单列；收起左栏正好过线。侧栏不动：再省 168px 要跨组件控制 `App.svelte`，不值 |

**配置编辑器（`manifest.config`）的取舍**，与旧 JS 窗口一致，因为每一条都是被撞过的：

- **五种控件**全部来自声明（`text` / `number` / `bool` / `secret` / `select[+multiple]`），
  页面不认识任何插件的私有键名——`select` 的选项来自清单，多选的值仍是**逗号串**
  （插件那边本来就是 `split`，不发明第二种编码）。
- **`secret` 永远不回填**：宿主只给 `secretSet` 与 `secretMask`，输入框从空开始，
  **留空 = 保持不变**，输入新值才替换。把掩码写回去会把密钥换成几个圆点。
- **布尔总是发送**（`true`/`false`），因为"没勾"就是它的值；空字段保存时落回**声明的默认值**，
  免得存的值和框里显示的东西对不上。
- 保存成功后**关掉弹窗**并刷新（`usage` 这类行会变）；失败则**保持打开**——里面有东西要改。
- 打开/保存都**不会移动插件的界面**：弹窗是 `position: fixed` 的浮层，实测帧的 y/高度前后一致
  （见下面那张表）。


三条实现上的硬约定（都在 `cc/src/lib/plugin-frame.ts` 与
`cc/src/components/PluginFrame.svelte` 的注释里）：

1. **iframe 归模块，不归 Svelte。** 模板里的条件块/`{#key}`/列表 diff 都会重建节点，
   而重建一个 iframe 就是销毁那个正在按用户权限运行的文档。Svelte 只给一个稳定挂载点，
   帧由 `$effect` 命令式建、命令式销毁。
2. **重挂的判据是一个字符串键**：`id | version | entry | 排序后的 granted`。
   `$derived` 只在值变化时通知下游，所以刷新列表、切标签都不会把工坊拆了。
   `granted` 进键是**故意的**：改授权会重启界面（界面上写着这句话）——不发第二次 `init`，
   因为四个随包插件的 `onInit` 都会重建视图、其中两个还会起定时器。
3. **主题两条通道**：`?theme=` 管首帧（不闪），`theme` 消息管运行中切换（不重挂）。

**第 2 条现在桌宠也照做了，而它是被一个真机 bug 追上的。** 桌宠的重挂判据原来只有
`id | version`（`frontend/src/plugin-host.js` 的 `applyGeometry` / `openBackground`），
理由是「授权只在 `init` 里给一次，改了重启就行」。这个理由不成立：授权是在**控制中心**改的，
两个进程只共享数据目录，桌宠靠 1.5s 轮询才发现新列表——而列表变了、帧没变，插件手里那份
`granted` 就永远是旧的。实测症状：weather-env 的常驻帧在只授了 `net.fetch` 时挂载，用户随后
补授 `pet.surface`，而它的徽标被 `granted.has('pet.surface')` 挡着，于是**一次都没出现，也没有
任何错误**（Go 的闸门每次调用都重读索引，会说「可以」，是插件早就决定不问）。现在两处判据
一样：`id | version | 排序后的 granted`（`grantedKey()`，`frontend/src/plugin-granted.test.js`
钉住「加了要重建 / 减了要重建 / 顺序不同不重建 / 两次轮询之间不重建」）。

**第四条是踩出来的：过边界前把值复制成纯数据。**

真机第一次跑就撞上：

```
Uncaught DataCloneError: Failed to execute 'postMessage' on 'Window':
[object Object] could not be cloned.
```

Svelte 5 的 `$state` 会把**纯对象与数组**深度代理，而 Wails 的绑定返回的正是**纯 JSON**，
于是 `inst.Manifest.permissions` / `inst.Granted` 是 Proxy；Proxy **过不了** `postMessage`
的结构化克隆。异常发生在**消息监听器里面**——页面一切正常，插件永远收不到它那唯一一条
`init`，界面停在「等待宿主初始化…」。修法是在 `mountPlugin` 入口把要重复使用的值读成局部
副本（`[...req.permissions]`），并且在 `post()` 里 `try/catch` 说明「发给插件的是含不可
结构化克隆的值」，因为**监听器里的异常本身不报错、也没有栈**。

**为什么 jsdom 和 `npm run dev` 都复现不出来**：dev 桩的行是 `Installed.createFrom(...)`
建的**类实例**，而 Svelte 只代理 prototype 是 `Object`/`Array` 的值——类实例被原样返回，
Proxy 根本不存在。所以桩现在用 `.map(asHostSends)` 摊平成**纯数据**（字段名仍由
`createFrom` 的类型把住），`render-smoke.mjs` 也因此能真的测到它：模拟一条 `ready`，
捕获回来的 `init`，要求 `structuredClone` 能克隆它。**这条断言做过「把修复拿掉就必须变红」
的验证**，不是摆设。

**光栅尺没变，量到的东西变了**：`.dev/check-frontend.cjs` 里原先钉在
`frontend/{index.html,src/main.js,src/plugin-ui.js}` 上的三条托管断言
（`the market can host a plugin interface` / `… sandboxed to allow-scripts alone` /
`… only for an installed and ENABLED plugin`）已重新指向 `cc/src/**`——对着一个不再被构建的
文件报 PASS，比没有门禁更糟。权限文案那条也换了口径：生产界面直接读宿主的
`PermissionLabels()`，唯一的重复副本是 `cc/src/lib/bridge.ts` 的 **dev 桩**，门禁改为比对
它与 `AllowedPermissions`。

**量出来的数字**（`scratch/layout-cc.cjs`：开发态包 + 无头 Edge，与 WebView2 同一引擎类，
手法同 `.dev/layout-report.cjs`；980×700 与 720×520 两个尺寸全绿）：

| | 980×700 | 720×520（最小） |
|---|---|---|
| 列表 / 详情 | 232 / 496 | 180 / 288 |
| 帧（列表在时） | 494×394，正好等于详情减去边框 | 286×214 |
| 权限浮层 | 不动帧（y141..537 前后一致），压到帧带上 | 同 |
| 设置弹窗 | 720×397，居中；表单 243px 不需要滚；`保存` 在屏内（y434..462） | 同（`min(720px, 92vw)`） |
| 展开后帧宽 | 740（> 语音工坊的 720 断点） | 480 |
| 越过窗口右边缘的元素 | 无 | 无 |

> **表里那两行宽度是修完一个真 bug 之后量的**：`min-width: auto` 让 iframe 的默认
> 300×150 变成它的 min-content 宽度，于是 720 窗口里帧**伸出自己的列 110px**、顶到窗口边，
> 而 980 下完全看不出来。三层都补了 `min-width: 0`（`.detail` / `.frame-area` / 帧元素的
> 内联样式）。jsdom 不做布局，这条只能靠引擎量——理由和 §2.7 末尾那句一样。


**还没搬回来的（阶段 3，见 tasks.md）**：市场目录与安装/更新/卸载、`Warnings()`。
所以现在这个页面能「运行、授权、**改配置**、看界面」，还**不能**装。

### 2.10 界面重做（第十轮：插件页之外，再给一个「市场」页）

**安装为什么不等于启用（本轮唯一一个"不做"）。** `Market.Install` 落地的插件是**停用 + 一项权限

### 2.11 卸载：先问一句，并且把"删数据"变成一个勾选框

用户的原话：

> 现在没有卸载插件的选项，添加卸载插件的选项，同时点击卸载要弹窗确认，同时需要勾选是否清除用户

**这不只是加一个按钮，是把一条既有语义改对。** 之前 `Manager.Uninstall` 无论用户怎么想，都会
`os.RemoveAll(plugin-data/<id>)`——也就是「卸载」是**这个程序里最具破坏性的按钮**，而这个词里没有
一个字提到你的密钥会跟着没。现在它是两个决定，用户分开回答：

| 删什么 | 什么时候 | 为什么 |
|---|---|---|
| `plugins/<id>`（本体） | 总是 | 这是**回滚**：把同一个版本装回来，它就接着用（因为私有目录还在） |
| `plugin-data/<id>`（配置、密钥、数据） | 只有用户勾了「同时删除它的配置与数据」 | 这一步**不可恢复**。安全的那一半要自己选，所以勾选框默认是空的 |

**做了什么：**

| 位置 | 改动 | 为什么 |
|---|---|---|
| `internal/plugins/manager.go` | `Uninstall(id string, purge bool)`：本体无条件删，私有目录只在 `purge` 时删 | 语义落在函数签名上，调用方无法"顺手"删掉别人的数据 |
| `tools/plugin-market/market.go` | `Uninstall(id, purgeData)`，两种结果两种日志（删除是 WARN，保留是 INFO 并写明"重新安装接着用"） | 日志是给 issue 贴的：一次卸载之后数据还在不在，应该能从日志里读出来 |

### 2.14 主题包：一份说明，两个窗口，外加插件文档里的一段 `<style>`（2026-11-01）

2026-11-01，界面改造方案里"看得见"的那一层落地。要点与坑：

- **一个文件、两个字段**：`theme.json` 从 `{theme}` 变成 `{theme, pack}`。两个写者（桌宠右键菜单改明暗、
  控制中心「偏好」页改包）都是**读-改-写**——各写各的字段，谁也抹不掉谁。`internal/store/theme.go`

- **四条内建包 + 任意已安装包**：内建的在 `internal/themepacks`（Go 表）与两份 CSS

  不合格的包会在卡片上标出来而不是被拒绝（用户已经选了它）。
- **插件界面靠注入**：帧是 opaque origin 的沙箱 iframe，宿主碰不到它的 DOM。所以
  `internal/plugins/asset.go` 在服务 entry 文档时把 `:root:root{…}` 拼在 `</head>` 之前——

  位置必须在插件自己的 `<link>` 之后。**包对已经挂着的帧在下次打开时生效**（文档里那段 CSS 是
  服务端拼的，重挂才能换）。
- **主题商店**：和插件市场同一个 base URL、同一条 sha256 校验，但装的是**一个 theme.json**，
  不是 zip——主题包只有颜色，没有代码，所以装它不需要授权。`themes/index.json` 由市场仓提供，
  由 `tools/check-catalogue.mjs` 校验（文件存在、摘要对得上、两套令牌齐全、名字在白名单里）。
## 3. 两个程序的关系

```
        ┌─────────────────────┐        ┌──────────────────────────┐
        │  PetPCPluginMarket  │        │        PetPC             │
        │   （插件市场）       │        │      （桌宠）            │
        └──────────┬──────────┘        └────────────┬─────────────┘
                   │                                │
   安装/授权/启用  │                                │  运行插件
   卸载/改配置     │                                │  槽位 + 浮层面
                   ▼                                ▼
        ┌──────────────────────────────────────────────────────┐
        │  %AppData%\PetPC\                                     │
        │    plugins.json          ← 已装索引（共享）           │
        │    plugins\<id>\         ← 插件文件（共享）           │
        │    plugin-data\<id>\     ← 私有存储与配置（共享）     │
        │    config.json           ← 桌宠的设置（市场只读一次） │
        │    plugin-market.json    ← 市场自己的设置（独占）     │
        └──────────────────────────────────────────────────────┘
```

**共享的是插件目录，不是配置**：

| | 市场 | 桌宠 |
|---|---|---|
| 设置文件 | `plugin-market.json`（地址、上次选中、窗口尺寸） | `config.json`（缩放、贴边、番茄钟、提醒、语音…） |
| 谁能写 | 只有自己 | 只有自己 |
| 读对方的 | 首次运行时读一次桌宠的 `marketBaseUrl` **播种**地址 | 不读市场的任何东西 |

### 3.1 「桌宠的 config.json 绝不会被另一个程序改写」

这不是一句口号，而是有测试钉住的性质：`tools/plugin-market/config_test.go` 的
`TestSaveMarketConfigLeavesThePetConfigByteIdentical` 会在保存前后**逐字节比对**
桌宠的 `config.json`。断言方式是**比字节**而不是「比路径」——只查目标路径的话，
一个在调用链里顺手写了桌宠文件的实现仍然会让测试通过。

配套的还有静态门禁：`.dev/check-frontend.cjs` 扫市场程序的**非测试产品代码**，
`config.json` 这个文件名必须**零命中**。连注释里都不能出现，因为「能写出这个
文件名」和「能改写这个文件」之间只差一行代码。播种那次读取住在 `internal/store`
里（`ReadMarketBaseURL`），那里本来就拥有这个文件名的所有权。

`*_test.go` 不在这条扫描范围内，而且**必须**不在：上面那个逐字节比对测试
就是以桌宠的 `config.json` 为断言对象的，把它一起扫掉会让「保证」与「检查」互相排斥。

### 3.2 「另一个程序改了插件列表，这边立刻看得到」

`plugins.Manager` **不做任何内存缓存**——`Plugins()` 每次调用都重新读 `plugins.json`。
所以桌宠装了/停用了插件，市场下一次 `Installed()` 就看到，反之亦然。
两进程之间**没有**任何刷新协议，因为它们共享的是文件而不是状态。
`TestInstalledSeesAnotherWritersChange` 钉住这条：先取一次快照，再用**另一个**
`plugins.NewManager` 写入一条，第二次 `Installed()` 必须多出一条。

### 3.3 两边用的是同一份实现

市场程序的每一个绑定都是 `internal/plugins` 上的**投影**：
`Installed` / `Install` / `Uninstall` / `SetEnabled` / `Grant` / `GetConfig` / `SaveConfig`
全部直通 `Manager`。市场**不复制任何插件逻辑**——不自己解析 `plugins.json`、
不自己校验权限、不自己判断「什么叫已安装」。

这是刻意的：桌宠也调同一个 `Manager`，两边各写一份的话，
「什么算已安装」就会有两个答案，而它们迟早会不一致。

## 4. 桌宠侧收口

搬走管理面之后桌宠侧**删掉**了这些东西，一条都没留：

| 删掉的 | 为什么删 |
|---|---|
| 面板的「插件」tab（`index.html` 整块 + `plugins.js`） | 管理面只在独立程序里，留一个 tab 就是第二份实现 |
| 7 个管理绑定（`PluginsView`/`MarketView`/`InstallPlugin`/`UninstallPlugin`/`SetPluginEnabled`/`GrantPluginPermissions`/`SaveMarketURL`） | 它们只在那个 tab 里被调用，删了 tab 就没有调用点了 |
| 设置页的 25 个 `llm-*` 控件与 6 个 AI 绑定 | AI 配置归对话插件，编辑入口在市场的配置区 |
| 主动说话整套调度 + 手动「立刻说一句」 | 它需要「有配置源」，而配置已经搬走 |

**保留**的是插件**运行**所必需的两条通用机制：

1. `PluginsInstalled` —— 桌宠要知道谁被装了、谁被授权了，才能解析「对话」tab 的槽位；
2. `OpenPluginSurface` / `ClosePluginSurface` / `PluginRequest` —— 浮层面几何与唯一那个受权限门控的调用入口。

### 4.1 「插件没了它的浮层面不能继续占区域」这条守卫换了承载

`UninstallPlugin` / `SetPluginEnabled` 原本在卸载或停用之后调 `closeSurfaceFor(id)`。
这两个绑定没了，而市场是**另一个进程**，它随时可以停用或卸载插件却不会通知桌宠——
所以「只在桌宠自己做出改动时才生效」的守卫已经不够了。

守卫因此改成**每次几何计算时判定**：`pluginSurfaceRects` 的可用性判据收紧为
「已装 **且** `Enabled` **且** `granted` 含 `pet.surface` **且** manifest 可读」，
不满足就不返回矩形。这比原来**更强**：它跨进程也成立，而原来那份只在桌宠自己动手时才看得见。

## 5. 数据迁移：一次性、幂等、可回滚

配置搬给插件之后，老用户的数据要跟着走。**两个程序都触发**迁移、共用
`internal/plugins/migrate.go` 一份实现（用户可能先开市场，也可能先开桌宠）：

| 从 | 到 |
|---|---|
| `config.json` 的 13 个 `llm*` 项 | `plugin-data/com.shixiansi.plugin-chat/config.json` |
| `llm-history.json` | 同上（`storage.*` 的落点） |
| `llm-usage.json` | 不动（用量仍由宿主唯一写、插件只读） |
| `llm-key.bin` | `plugin-data/com.shixiansi.plugin-chat/secret-llmApiKey.bin`（**按插件隔离重新加密**） |

三条性质：

- **一次性**：插件私有目录里的 `.migrated` 标记结束它；第二次启动不再搬。
- **失败不动原文件**：所有目标都写成功之后才改名原文件为 `.bak`，所以中途失败只是「没搬成」，
  下次启动重试，原数据始终在。
- **可回滚**：桌宠的 `config.json` 一个字节都没变，`.bak` 也在，回退版本即可。

### 6.1 「界面改了但窗口没变」——`dist` 只是**输入**，不是产物

`tools/plugin-market/main.go` 里是 `//go:embed all:frontend/dist`：市场的前端是**编译进 exe 的**。
所以改了前端并 `npm run build`（只更新 `dist`）之后，
`build\bin\PetPCPluginMarket.exe` **一个字节都没变**——它仍然是旧界面，而且在跑的那份进程里
连新标记都搜不到。

**2026-10-27 又一次，而且换了个形状**：界面已经搬进 `cc/`（Svelte），`frontend/dist` 只是它的
构建产物副本。于是「改了 `cc/src/*` → 忘了重建市场程序」的表现变成**功能消失**——插件页的主从
布局与其宿主写完了、`frontend/dist` 也换了，用户打开的还是前一天那个二进制，看到的是**只有列表、
没有任何插件界面**的那一版，于是报「插件页面又没有了」。同一天那个会话重建过**桌宠**，而
**重建桌宠不会重建市场程序**（两个独立 module、两次 `wails build`、两次复制）。

所以判据必须**在页面上**，而不是靠翻文件时间戳：控制中心插件页左上角是
`已装插件 · v5`——这个数字变了，说明窗口里跑的是新构建；它不变就说明重建没落到这个 exe 上。
（旧 JS 界面当年也有同样的标记，`已装插件 · v4`；Svelte 重写时把它丢了，这一轮补回来。）

正确的顺序是**一条命令**：

```
pwsh -File tools\build-all.ps1
```

它先 `npm run build` 控制中心（然后把 `cc/dist` 复制成 `frontend/dist`），
再 `npm run build` 桌宠的前端，然后 `wails build -s -skipbindings` 两个程序，
最后**把市场的 exe 复制到 `build\bin`**——桌宠的「打开插件市场」先找的就是那一份
（`app_plugin_market.go` 的 `PluginMarketCandidates`），只编译不复制等于按钮启动的还是旧的。

**只重建市场程序时**（例如只改了 `cc/`），顺序是三步，且 `-s` 不能省：

```powershell
cd tools\plugin-market\cc; npm run build
# 把 cc\dist 覆盖到 tools\plugin-market\frontend\dist（embed 读的是这一棵）
cd tools\plugin-market; & ..\..\.dev\bin\wails.exe build -s -skipbindings
# 再把 build\bin\PetPCPluginMarket.exe 复制到仓库根的 build\bin
```

省掉 `-s` 就会踩第二个坑：`wails build` 会先去构建 `tools/plugin-market/frontend`
（**旧的 JS 界面**，还在树里），把 `frontend/dist` 覆盖回去——于是你编出来的 exe 里是上一代界面。

判据可以自己验：新 exe 里能搜到新界面独有的字符串，旧 exe 里搜不到。

```powershell
$t = [Text.Encoding]::UTF8.GetString([IO.File]::ReadAllBytes('build\bin\PetPCPluginMarket.exe'))
@('已装插件 · v5','展开界面','从左边选一个插件') | ForEach-Object { "$_=$([regex]::Matches($t,$_).Count)" }
```

另外：**已经开着的窗口不会热更新**。市场是独立进程，重新构建后要把那个窗口关掉，
再从桌宠的 ⚙（或托盘菜单「打开控制中心」）打开一次。

`.dev/verify-plugin-market.ps1` 在没有交互桌面的环境里会**说明情况并 `exit 0`**——
这和 `verify-region.ps1` / `verify-live.ps1` / `verify-plugin-surface.ps1` 是同一个约定：
没有桌面时窗口根本没有客户区（`0x0`、样式位为 0），把「测不了」报成「代码错了」会让门禁说谎。
**注意区别**：这条约定说的是「没有桌面」；在**有桌面**的环境里，「量不到该量的控件」是**失败**而不是提示
（见 §2.1 的第 2 个哑火）。

这个脚本此前**没有被 git 跟踪**：`.dev/*` 是整目录忽略 + 白名单，
而它漏在白名单外——尽管 `check-all.ps1` 把它当门禁跑。现已补上白名单条目，
因为「门禁的改动必须和被它守护的代码一起可评审」正是那些白名单存在的理由。

### 2.15 配色是**一个**设置，两个窗口共用（2026-10-29）

用户原话：「怎么右键和设置界面的主题不统一的，一个亮一个暗的，像是独立的」。

当时确实是这样，而且是我自己造出来的：上一轮给桌宠加了 `settings.json` 的 `cardTheme`、控制中心
沿用 `plugin-market.json` 的 `theme`——**两个开关、两个文件**。翻一个，另一个不动，于是右键菜单
深色、设置页浅色。

现在配色住在**两个程序共用的** `theme.json`（`internal/store/theme.go`）：

| | 写 | 读 |
|---|---|---|
| 桌宠 | 右键菜单的「主题」→ `store.WritePanelTheme` | `Layout.Theme`（每次 layout 都读，不缓存） |
| 控制中心 | 「偏好」页 / 顶栏按钮 → `store.WritePanelTheme` | `Theme()`（挂载时读一次，写回后自己再读） |

三条规矩：

1. **一个值一份文件，两个程序都能写**。最后写的人赢——这是开关，不是文档，两次写都是单键的
   read-modify-write，最坏情况是翻转晚一拍。
2. **没有文件时不许猜**：`ReadPanelTheme` 对缺失的返回 `""`，让调用方回落到自己的旧字段一次
   （控制中心的 `plugin-market.json:theme`）。默认值是**浅色**，两边同一个默认，所以新装的机器
   不可能一上来就一个亮一个暗。
3. **认不出来就回到默认**，不是回到另一端：`store.NormalizeTheme` 把"不是 dark"的一律当 light。
   两个程序用同一个函数，否则同一个乱值在两个窗口里会变成两种配色。

门禁：`the colour scheme is one value both windows read and write`（两边都得走 store 的共享文件，
且谁都不许再长出 `CardTheme` 这种自己的开关字段）。

### 2.17 「扩展能力」：控制中心里的插件测试台（2026-11-01）

用户原话：「在设置界面新增扩展能力的菜单，里面可以直接展示插件的测试平台」。

这一页回答的是「这个插件**到了别的地方**会怎样」，而「插件」页回答的是「它长什么样」。
三件事只有这一页能看见：

| 想测的 | 插件页 | 测试台 |
| --- | --- | --- |
| 它在桌宠那块矩形里（被 `SetWindowRgn` 裁）会不会被切掉 | 不行：永远 `panel/workshop` | 选「浮层面第 N 块」，框就是清单那一块（380×260） |
| 用户什么都没勾时界面还立得住吗 | 只能真的去改授权 | 「模拟未授权」：`granted` 清空 + 请求在宿主层就被拒，真实授权不动 |
| 握手/请求/响应/宿主事件各是什么 | 一行都看不到 | 每条一行（方向、类型、方法、字节数、错误原文） |

页面上的东西：插件下拉（只列**挂得上**的：启用 + manifest 能解析 + 有 `entry`；其余在下面点名并
说明原因）、位置下拉（工作区 / 浮层面第 N 块 / 隐藏常驻帧）、矩形与宽高（改尺寸会**重新握手**，
因为尺寸写在 `init.surface.rect` 里）、100/75/50% 缩放、`模拟未授权`、`重挂`、`清空日志`、
以及两件开发工具：**手推一条事件**（`share.changed` / `storage.changed` / `config.changed`
——这三个名字是宿主真的会推的，手册 §7）和**以插件身份调一个方法**（走同一个
`Market.PluginRequest`，拒绝原样显示）。

三条要说清的边界：

1. **它量不了排版。** 沙箱是 `allow-scripts`（不含 `allow-same-origin`），帧是 opaque origin，
   父页面读不到它的 DOM。`getBoundingClientRect()` 一条也拿不到，所以"按钮被下边缘切掉"仍然只有
   `plugin-testkit/preview.mjs`（真浏览器 + 能读 DOM）看得见。**这一页量的是框，不是内容**——
   页面上也这么写着，免得有人把它当排版门禁。
2. **它不改真实授权。** 页面上没有 `Grant`/`SetEnabled`；「模拟未授权」的两半（`init` 里的
   空清单、宿主层的拒绝）在 `plugin-frame.ts` 里一起决定，所以不可能只做一半。
3. **它不是第二个宿主。** 帧仍然由 `plugin-frame.ts` 建，沙箱规则一字不改。这一页只多要了
