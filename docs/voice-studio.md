## 1. 为什么是独立程序

最初它做成了面板里的「配音」标签页，但**面板太拥挤**了 —— 而这不是布局能解决的问题：

| 面板的约束 | 为什么不合适 |
|---|---|
| 固定 380×520 矩形 | 由 layout 决定，窗口区域又按它裁剪，**不能长大** |
| 内容超长只能内部滚动 | 5 条台词 × 每行多个版本 × 每条 3 个按钮，纵向会到几千像素 |
| 空间要给待办和对话 | 配音是**偶尔用一次**的功能，却要占掉日常用的地方 |

而配音工坊实际是个**工作面**：左栏选角色、右栏逐句试听对比。
所以拆成两个程序，桌宠**不再背着一个很少用的渲染界面**。

## 2. 两个程序的关系

```
        ┌─────────────────────┐        ┌──────────────────────────┐
        │  PetPCVoiceStudio   │        │        PetPC             │
        │   （配音工坊）       │        │      （桌宠）            │
        └──────────┬──────────┘        └────────────┬─────────────┘
                   │                                │
      生成 / 采用  │                                │  播放
                   ▼                                ▼
        ┌──────────────────────────────────────────────────────┐
        │  %AppData%\PetPC\voice\user\   ← 共享的语音库         │
        │    voice-user.json   角色、版本、采用哪一版            │
        │    clips\<台词>\vNNN.wav                              │
        └──────────────────────────────────────────────────────┘
```

**共享的是语音库，不是配置**：

| | 工坊 | 桌宠 |
|---|---|---|
| 设置文件 | `voice-studio.json`（引擎地址等） | `config.json`（开关、缩放…） |
| 会合成吗 | **会**（用本机 GPT-SoVITS） | **不会**，永远只播放 WAV |
| 会启动引擎吗 | 会 | 不会 |

> **桌宠不碰引擎**，这是硬性约束。当初的实时合成就是因为"每次说话都要合成"而被停用的
> （太慢、太重、不稳定，见 `_archive/README.md`）。`check-frontend.cjs` 有一条检查
> 专门断言桌宠的播放路径**不导入**合成包。

## 3. 核心设计：生成 ≠ 采用

```
生成一版  →  存起来，可以试听、可以对比、可以留着   ←── 不影响桌宠说什么
采用一版  →  之后桌宠就说这一版                   ←── 改变这一句说什么
点角色    →  桌宠立刻改成那个音色                 ←── 改变"用谁的嗓子说"
```

**生成永远不会自动生效。** 反过来（生成即生效）意味着「你还没听完，它已经变成桌宠的声音了」。

> 「点角色」和「采用」是两件事，别混：**角色决定用谁的嗓子**，
> **采用决定这一句念哪一版**。而桌宠真正出声，两者都要满足：
> **当前角色名下有这一句已采用的版本**。

一次生成 = 一个 **take（版本）**，take **只增不删**：

```
focus_end
  v001  可莉   4.3s
  v002  可莉   4.1s
  v003  纳西妲  4.6s   ← 点「用这版」才会变成这一句正在用的版本
```

> 一个句子**只有一个**"正在用的版本"。所以如果 v003 被采用、而当前角色是**可莉**，
> 那么这一句就**不会出声**（采用的是纳西妲的版本），工坊里会标成
> 「现在：不生效（采用的是 纳西妲）」。

所以「单独替换某一句」的完整流程：

1. **生成** / **再生成一版** → 得到新版本（旧版本仍在本机，随时能听、能退回去）
2. **试听**对比，也可以「试听内置（可莉）」和原始音色对比
3. 满意 → **用这版**；不满意 → 再生成一版
4. **确认之后**这一句才改变桌宠说什么

### 没录过的句子不会退回内置音色

这一点是刻意的：如果当前角色是**纳西妲**、而某一句只有可莉的版本，
**退回内置音色会让你听到可莉** —— 也就是「界面上显示纳西妲，耳朵里是可莉」。
所以这一句**不出声**，并在工坊里标成：

| 徽章 | 含义 | 怎么修 |
|---|---|---|
| `现在：纳西妲 v2` | 这一句会用纳西妲 v2 出声 | 已就绪 |
| `现在：待生成（纳西妲）` | 纳西妲还没有这一句 | 点「整套换成这个角色」或逐句生成后「用这版」 |
| `现在：不生效（采用的是 可莉）` | 采用的是**别的角色**的版本 | 同上（需要重新生成成当前角色） |
| `现在：文件缺失（纳西妲）` | 采用的那一版音频文件不见了 | 重新生成并采用 |
| `现在：内置（可莉）` | **没有选任何角色**，用的就是内置音频 | 在左栏点一个角色 |

## 4. 怎么用

### 打开

桌宠面板 → **设置** → 语音朗读 → **打开配音工坊（换音色）**。

（工坊的 exe 必须和桌宠放在一起；`tools\build-all.ps1` 会自动复制过去。）

### 窗口布局

| 区域 | 内容 |
|---|---|
| 顶部 | 引擎状态 + **启动语音服务** / 停止 / 设置 / 查看日志 |
| 左栏 | **角色列表**（点一下切换）、音色参数、两个生成按钮 |
| 右栏 | **台词列表**：每条显示「现在：…」徽章 + 版本列表 |

### 两个生成按钮（区别很重要）

| 按钮 | 做什么 |
|---|---|
| **整套换成这个角色** | 5 条全部生成**并立即采用** —— 等于把这个角色当成新的"内置音色" |
| **只生成，不替换** | 只生成，之后逐条试听，满意再手动「用这版」 |

> 第一个按钮是**直接回答**「我选了角色，然后呢？」。没有它，用户会以为
> 「使用角色」应该已经换掉了声音 —— 而这正是最初被报上来的困惑。

### 每一句上有什么

| 元素 | 作用 |
|---|---|
| `现在：纳西妲 v2` / `现在：待生成（纳西妲）` | **明确告诉你桌宠此刻会说什么**，包括是哪个角色、会不会出声（见 §3 的徽章表） |
| **生成** / **再生成一版** | 为这一句新增一个版本 |
| **试听内置（可莉）** | 播放程序内置的音频，用来对比 |
| **清除采用** | 这一句不再采用任何版本，**不删**已生成的音频。注意：当前角色下它会变成「待生成」 |
| 版本行 **试听** | 播放这一版，**不采用** |
| 版本行 **用这版** | 采用这一版（这一句此后就用它，前提是它属于当前角色） |
| 版本行 **×** | 删除这一版（删掉正在用的那版会**变成「待生成」**，不会自动挑一版顶上） |

> **怎么回到内置音色？** 不是逐句「清除采用」—— 只要还选着角色，那一句就是「待生成」。
> 回到内置音色的唯一方式是**不选任何角色**（左栏选中态清空 / 重新扫描后不点角色）。
> 这条规则是刻意的：内置音频是**可莉**的，一边选着纳西妲一边放出可莉，
> 就是最初那个 bug 本身。

## 5. 内置音色 vs 自定义配音（最初的困惑）

**「内置」的那 5 条音频是烤进 exe 里的可莉**（`internal/voice/lines/*.wav`）
——这是**构建时的事实**，不是设置，重新构建才会变。

所以：

- **左栏点角色 = 立刻换桌宠的音色**（选中态**就是**播放源，不需要重启任何一个程序）
- 该角色**名下有这一句已采用的版本**，这一句就用那个版本出声
- 该角色**没有**这一句 —— **不出声**，标成「待生成」，**不会退回内置可莉**
- 想一次把 5 条都补上，用「整套换成这个角色」（生成**并采用**）
- 设置页会写明「当前：**纳西妲**（内置音色是 可莉），已换成该音色的 N 条」，
  工坊每行也有「现在：…」徽章

> 这两处显示是**为了修掉最初那个困惑**：改了角色、还是听到可莉，看起来像功能坏了。
> 修法不是把说明写得更清楚，而是让**界面选中态与运行时音色真正同源**
> （`Store.ResolveCurrentRole` 是唯一解析入口，播放和界面都走它）。

## 6. 语音引擎（本机 GPT-SoVITS）

**只在生成时需要。** 生成出来的就是普通 WAV，播放不需要引擎、不联网、不占内存。

### 为什么又用回合成

之前的实时合成被停用，是因为**每次说话都要合成**。这里**每条台词只合成一次、永久复用**，
引擎的成本（CPU 上 RTF ≈ 1.0、几百 MB 内存）只在**你主动点生成**时付出：

| 当时的问题 | 为什么这里不成立 |
|---|---|
| 54 字要 11 秒 | 只在生成时等，播放毫秒级 |
| 常驻 3.3 GB | 引擎可以随时关掉，播放完全不需要它 |
| 输出随机、不稳定 | **正是所以要"生成多版、挑一版"** —— 随机性变成可挑选的素材 |

### 实测（本机，CPU，`torch 2.14.0+cpu`）

| 项目 | 数值 |
|---|---|
| 单句合成 | 1.9 ~ 4.8 秒（对应 3.7 ~ 6.7 秒音频） |
| 全套 5 条 | 11 ~ 21 秒（按角色不同） |
| 切换角色 | 约 1.5 秒（加载权重） |

### 设置

| 项 | 默认 | 说明 |
|---|---|---|
| 服务地址 | `http://127.0.0.1:9880` | 本地 `api_v2.py` 的默认端口 |
| GPT-SoVITS 目录 | `D:\GPT-SoVITS` | 模型在 `<目录>\models\`，解释器在 `<目录>\.venv` |
| Python 解释器 | 留空 | 留空则用 `<目录>\.venv\Scripts\python.exe` |

**角色是自动发现的**：扫描 `<目录>\models\*\`，只要有
`gpt.ckpt`、`sovits.pth`、`ref.wav` 三个文件就算一个角色。
显示名优先读同目录的 `petpc-config.json`（旧实时合成留下的，里面有中文名）。

> **加新角色**：模型文件夹放进 `models\`，点「重新扫描」。
> 扫描是**只增不改**的 —— 已经调过参数的角色的设定**不会**被覆盖。

本机现有 5 个角色：**可莉 / 神里绫华 / 珊瑚宫心海 / 纳西妲 / 宵宫**（都已实测可渲染）。

## 7. 两个程序的时序问题（这次改动修掉的真 bug）

工坊和桌宠是**两个进程**，共享一个 JSON 索引。这带来一个原来不存在的问题：

**桌宠启动时把索引读进内存。** 你在工坊里点了「用这版」，文件变了，
但桌宠内存里还是旧的 —— 于是**它继续播放旧的那一版**，看起来像"改了没用"。

修法是：`voice.Store` 在**每次决定播什么之前**比较索引文件的
**修改时间 + 大小**，变了就重新读。所以：

- 工坊里**采用**一版 → 桌宠**下一次说话**就用新的，**不需要重启任何一个程序**
- 每次**写入前也重新读** —— 否则两个进程各自基于旧副本追加，会**复用同一个版本号**，
  互相覆盖对方的音频

> 这条用一个**双进程测试**验证过（两个真实的 OS 进程）：
> 读者先报 `BEFORE=builtin`，另一个进程写入并采用 v001，
> 仍然在运行的读者随后报 `AFTER=v001.wav` —— 没有重新打开库。

## 8. 两个引擎的坑（都是实测出来的）

### 8.1 引擎会重写自己的配置文件

> **【已不适用】** 这条讲的是**程序自己启动引擎**时要小心的事（`-c` 指定一个自己的
> `tts_infer.yaml`，因为引擎每次切角色都会把它写回 GPT-SoVITS 目录，而那里常常只读）。
> **现在没有任何程序替你启动引擎**——插件只发 HTTP 请求，所以 `-c` 由**你自己**在
> 启动命令里决定（见 `docs/voice.md` §5）。数据目录里遗留的 `tts_infer.yaml`
> 与 `tts-engine.log` 是上一版留下的文件，已经没有任何代码会读它们。

`TTS_Config.save_configs()` 在**每次切换角色时**把当前权重写回 `tts_infer.yaml`，
默认路径在 GPT-SoVITS 目录里。第一次启动直接失败：

```
PermissionError: [Errno 13] Permission denied:
  'D:\GPT-SoVITS\GPT_SoVITS\configs\tts_infer.yaml'
```

所以**总是**用 `-c` 指定一个**自己数据目录里**的配置路径：

```
%AppData%\PetPC\tts_infer.yaml      ← 上一版：桌宠启动引擎时
<工坊数据目录>\tts_infer.yaml        ← 上一版：工坊启动引擎时
```

首次从 GPT-SoVITS 目录复制一份，之后由引擎自己维护。

### 8.2 "端口通了"不等于"能合成"

引擎在 **import 时**构建 TTS 管线（加载模型），**之后**才 bind 端口。
本机这个版本的 `/tts` 被无参调用时返回 **500**（不是 422，它在校验前就解引用了
`text_lang`），所以健康检查把**任何 HTTP 状态**都算作"活着" ——
只认 200/422 会把一个完全正常的引擎误判为"没启动"。

## 9. 数据存在哪

```
%AppData%\PetPC\
  config.json              桌宠设置（开关、缩放…）
  voice\
    petpc-*.wav            内置音频的落地副本（启动时清理旧版本）
    user\                  ← 两个程序共享
      voice-user.json      角色、参数、每句的版本列表、采用哪一版
      clips\
        focus_end\v001.wav v002.wav ...
        break_end\v001.wav ...
  tts_infer.yaml           引擎配置副本（引擎会重写它）
  tts-engine.log           由 App 启动的引擎日志

tools\voice-studio\ 旁边（工坊自己的数据目录里）
  voice-studio.json        工坊设置（引擎地址、目录）
```

三条存储规则：

**内置与自定义分开**：`voice.Cleanup` 只删自己命名规则内的 `petpc-*.wav`，
而用户配音在 `user\` 子目录里，**永远不会被它碰到**（有测试守着）。

**先写音频，再写索引**：`AddTake` 先落盘 WAV、再更新 `voice-user.json`。
反过来的话，"索引里有、文件不存在"会变成**播放时静默失败**。

**索引坏了不致命**：解析失败时**重置为默认**而不是拒绝启动 ——
它唯一不可恢复的内容是"选了哪一版"；已生成的音频仍在磁盘上。

## 10. 构建

两个程序，一条命令：

```powershell
pwsh -File tools\build-all.ps1
```

它做四件事：构建工坊前端 → 构建桌宠前端 → 构建两个 exe →
**把工坊 exe 复制到 `build\bin\`**（桌宠就是在那儿找它的）。

单独构建：

```powershell
cd tools\voice-studio; wails build     # 工坊（会生成它自己的绑定）
wails build                            # 桌宠
```

> 工坊是**嵌套的 Go 模块**（`module PetPC/tools/voice-studio`，
> 用 `replace PetPC => ../..` 指向父模块）。这样它能**零复制**复用
> `internal/voice`、`internal/tts`、`internal/store`，
> 而 `internal/` 的可见性规则允许它这样做（导入路径在 `PetPC` 前缀下）。

## 11. 实现要点

### 11.1 播放路径上没有合成

`internal/voice`（播放）**不导入** `internal/tts`（合成）。
`check-frontend.cjs` 有检查专门断言这件事，所以将来也不会有人不小心把
一次网络请求放进计时器回调里。

### 11.2 引擎的"当前角色"是服务端状态

`/set_gpt_weights` 和 `/set_sovits_weights` 改的是**引擎内部**状态，
之后的 `/tts` 都用这个状态。所以**必须先切换、再合成**，而且**两个并发渲染会串台**
（A 的音频被当成 B 的）。`tts.Client` 用一个锁把"切换 + 合成"整体串起来。

批量生成时只切换**一次**，然后连着合成 5 条 —— CPU 上省下 4 次加权重载。

### 11.3 引擎进程只杀自己启动的

`tts.StartEngine` 返回一个 `*tts.Process` 句柄，**谁启动谁负责停**。
如果端口上已经有服务（用户自己开的、或另一个程序开的），就直接用，
并在界面上显示"外部服务"—— **不会去杀一个不是自己启动的进程**。

启动时用 `HideWindow`，否则每次启动都会闪一个黑色终端窗口。

### 11.4 锁的教训

这次改动**踩了两次自死锁**，都值得记下来：

1. `Studio.engineReady` 锁住 `s.mu` 之后调用了同样会加锁的 `clientLocked()` —— 测试全部挂起 90 秒直到超时打印 goroutine 栈
2. `voice.Store.save()` 调用 `markLoaded()`，而 `save()` 的所有调用者都已经持有 `s.mu`

所以现在成对存在 **`markLoaded()` / `markLoadedLocked()`**，
并在注释里写明"调用者必须/不得持锁"。

## 12. 测试

```powershell
# 单元测试（不需要引擎）
go test ./internal/voice/ ./internal/tts/ .     # 桌宠
cd tools\voice-studio; go test .                 # 工坊

# 端到端（自带引擎；也可以用 PETPC_TTS_URL 指向已有的）
$env:PETPC_TTS_E2E='1'
go test -run 'TestE2E' -v -timeout 25m .
```

工坊的测试里，有三条是**这次改动的核心保证**：

| 测试 | 断言 |
|---|---|
| `TestGenerateDoesNotChoose` | 生成不改变桌宠说什么 |
| `TestPetSeesAChoiceMadeAfterItOpened` | **先打开的读者**能看到之后由"另一个进程"写入的采用 |
| `TestSetActiveRoleIsThePlaybackSource` | 工坊选的角色**就是**桌宠解析到的那个（选中态 = 运行时音色） |
| `TestFailedSwitchDoesNotPretendToHaveSwitched` | 切换失败要报错，且界面**不许**假装已切换 |

`internal/voice` 里对应的回归：`TestSwitchingCharacterChangesWhatPlays`（换角色后播的必须换）、
`TestSelectedCharacterWithoutATakeRefusesToPlay`（当前角色没这一句 → 报错而不是放可莉）、
`TestAdoptedTakeFromAnotherCharacterIsRefused`（采用的是别的角色 → 不播）、
`TestDeletedActiveRoleFallsBackToBuiltInNotAnotherRole`（删掉当前角色 → 落回内置，**不**自动挑 `Roles[0]`）。

端到端测试**用真引擎**跑完整流程：启动引擎、按角色渲染全部 5 条、
重新生成并确认旧版本还在、切换版本、检查发现到的角色。
Gated 在 `PETPC_TTS_E2E=1` 后面，因为要几分钟 CPU，**绝不能**成为普通构建的门槛。

不变量（`go test` 与 `.dev/check-frontend.cjs` 都覆盖）：

| 不变量 | 为什么重要 |
|---|---|
| 生成**不**采用 | 否则坏的一版会在你听完之前变成桌宠的声音 |
| 重新生成**追加**不覆盖 | 对比的前提是旧版本还在 |
| **角色解析只有一个入口**（`ResolveCurrentRole`） | 界面和播放读两份来源，正是「选了角色还在说可莉」的成因 |
| 播放只播**当前角色**已采用的版本 | 否则界面显示的角色和实际听到的不是同一个 |
| 当前角色没有这一句 → **报错，不回退内置** | 回退会让你听到界面上没显示的角色，且没有任何提示 |
| 采用别的一版 → 变成「待生成」/「不生效」 | 不替你换掉桌宠的声音 |
| 不存在的角色 ID → **报错，不回退 `Roles[0]`** | 静默换成另一个角色，等于替用户做了一次看不见的切换 |
| 切换角色**不中断播放** | 播放是一次性 WAV，换角色不该打断正在说的话 |
| 写入角色前**先校验存在** | 坏 ID 存下来只会在播放时才暴露，且表现为"声音不对"而非报错 |
| 重置不删音频 | 一键回到内置必须是可逆的 |
| 用户配音不被 `Cleanup` 删 | 那是几分钟 CPU 和一次判断，不可恢复 |
| 播放路径不导入合成包 | 守住"说话不等待网络" |
| 写入前重新读索引 | 两个进程不能互相覆盖版本 |
| 桌宠的 `Config` 没有合成设置 | 否则引擎地址会随每次 state 推到 webview |

## 13. 换台词文字

台词文字**只有一份**，在 `internal/voice/voice.go` 的 `Texts` 里
（`Labels` 是界面上的短名，`BuiltInRole` 是内置音色的角色名）。
改完重新构建即可 —— 工坊会自动用新文字生成，因为它从 `voice.Text(line)` 取。

## 14. 已知限制

- **工坊界面没在真机 WebView2 里点过**：本开发环境无法创建 WebView2 控制器
  （改动前的旧二进制同样失败，与本功能无关）。后端已用**真引擎**端到端验证，
  前端用 `.dev/check-frontend.cjs` 钉住结构（140 项）。首次使用建议按顺序确认：
  启动引擎 → 选角色 → 整套换成这个角色 → 回桌宠听效果。
- **需要本机装着 GPT-SoVITS**（默认 `D:\GPT-SoVITS`）。没有它工坊只能显示"未连接"，
  但**桌宠的内置语音照常工作** —— 配音是可选增强，不是依赖。
- **CPU 推理**：单句 2~5 秒。换 CUDA 版 torch 会快一个数量级，本项目没做适配。
- **不能改单句的"文字"**：工坊换的是**音色和读法**，不是内容。改文字要改代码重新构建。
- **切换角色要重载权重**（约 1.5 秒），所以逐条交替用不同角色生成会比一次一个角色慢。
