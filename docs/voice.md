# 语音插件（com.shixiansi.plugin-voice）

桌宠会说话，说**固定台词**。**语音是插件，不是宿主内置功能。**

| 台词 | 什么时候说 |
|---|---|
| 专注时间结束了，起来活动一下吧。 | 专注阶段结束 |
| 休息结束了，我们继续吧。 | 休息阶段结束 |
| 有些事情到期了，记得看一下。 | 有今天到期的待办 |
| 有事情已经逾期了，记得处理一下。 | 有待办逾期 |
| 现在没有待办，好好休息吧。 | 提醒触发但列表为空（需显式开启） |

5 条，合计 **569 KB**，作为 manifest 的 `assets` **随包分发**，默认音色是**可莉**。
装完即用：不需要联网、不需要装 GPT-SoVITS、不需要先渲染任何东西。

---

## 1. 为什么搬进插件

上一版语音是**宿主自己实现的**：台词清单、角色库、三条开关、渲染好的片段全在
`internal/voice/`，`config.json` 里存 `voiceEnabled/voicePomodoro/voiceReminder`。
这带来两个具体问题，而不是"架构不够漂亮"：

- **宿主必须知道什么叫"台词"**。它得有一张 `Texts` 表、一个 `BuiltInRole` 常量、
  一套"哪一句在什么时候说"的判断。想换台词就得改 Go 源码重新构建。
- **界面没地方放**。配音是个工作面（5 条台词 × 每行多个版本），而桌宠面板是固定
  380×520 的矩形、窗口区域又按它裁剪，**不能长大**——所以上一版为此拆出了第三个 exe
  （`PetPCVoiceStudio.exe`），代价是又一个 Wails module、又一条构建链。

搬进插件之后，宿主那边**只剩两样通用机制**（见 §2），既不知道什么叫台词，
也不再有第三个 exe：插件需要工作面时，挂到**市场窗口**里（980×700 且可缩放）。

---

## 2. 宿主提供的两样东西

宿主**只提供事实**，措辞与声音全是插件的事。

### 2.1 两个边缘事件（`events` 权限）

| 事件 | payload | 现在谁在发 |
|---|---|---|
| `timer.phaseEnded` | `{phase: "focus" \| "break"}` | **没有人发了**（见下面的补记） |
| `reminder.fired` | `{due, overdue, total}` | 宿主，手动「立刻提醒一次」 |

> **2026-10-27 补记：`timer.phaseEnded` 目前没有发射方。** 它唯一的发射者是宿主计时器
> （`completePhaseLocked` → `notifyPluginPhaseEnded`），而计时器整块退休、归
> `plugin-pomodoro` 了。所以语音插件的「番茄钟结束」那一句**现在不会响**。
> 事件名与 `SubscribableEvents` 暂时**保留**——直接删掉会让已装的语音插件
> `events.subscribe` 报错，那比不响更糟。三条候选路（接受 / 用 `plugin.share` 轮询 /
> 新增一条很窄的"插件声明事实"方法）写在
> `openspec/changes/todo-pomodoro-as-plugins/design.md` §4.5 的同名一行里。
> `reminder.fired` 不受影响：提醒气泡仍由宿主发（只是排期在待办插件那边）。

两者都是**边缘事件**，与 `timer.changed` 有本质区别：后者是**状态广播**（倒计时一动就发），
想知道"专注刚刚结束"的插件得自己记住上一帧、再判断跳变——也就是每个插件各自把宿主
**已经算出来**的结论重算一遍。这两个事件直接把结论送出来。

`phase` 只有 `focus` / `break` 两个值，而不是 `short_break`/`long_break`/`idle` 全套：
对一个只想"挑哪句话"的插件来说，需要的唯一信息就是**是工作结束还是休息结束**，
而这个分类宿主本来就持有（`store.IsFocusPhase`，随计时器一起删除；插件侧是 `machine.js`）。

**payload 里没有任何措辞。** 该说什么、用谁的嗓子、要不要出声，宿主一概不知道。

> 这也是"常驻帧"（`background: true`）存在的原因：插件的界面通常关着，
> 而番茄钟到点时用户不一定会开着面板。没有常驻帧，订阅了也收不到。

### 2.2 `audio.*` 能力（`audio` 权限）

| 方法 | 做什么 |
|---|---|
| `audio.save` | base64 → `<插件私有目录>/audio/<name>.wav`（上限 16 MiB） |
| `audio.list` | 列出 `audio/` 下的 `[{name, bytes}]`，按 name 排序 |
| `audio.remove` | 删一个；不存在不算错 |
| `audio.play` | 播放 `audio/<name>.wav`（按**路径**交给 winmm） |
| `audio.stop` | 停 |
| `audio.import` | 把 manifest 的 `assets` 里**声明过**的包内文件复制进 `audio/` |

`name` 的取值集合是 `^[A-Za-z0-9_-]{1,64}$`（与 `storage` 的 key 同一套规则）——
它最终会变成一个文件名，所以分隔符和 `..` 会在变成路径之前就被拒掉。

**为什么 `import` 必须存在**：播放器工作在插件的**私有目录**上，而包是**只读**的——
`audio.play` 收的是名字，不是包内路径。插件当然可以自己 `net.fetch` 自己的资源
（资源路由带 `Access-Control-Allow-Origin`，不透明源的 iframe 也能取）再把字节交给
`audio.save`，但那样整段音频要**过两遍桥**：先以 ArrayBuffer 取回，再以 base64 送出去。
`import` 让宿主直接复制文件，插件只报一个名字。

**`audio` 不是 `storage` 的加宽**：两者装的数据不同。`storage` 是少量**文本**（插件自己的
JSON），`audio` 是**二进制、几百 KB 量级**。只想记住一个设置的插件，不该为此被授予一个
它永远不用的音频出口。

### 2.3 没有单独的 `background` 权限

常驻帧由 manifest 的 `background` 字段申请，由**既有的 `events` 权限**门控。

`internal/plugins/capability.go` 的注释把理由写死了：门禁里有一条「权限表与方法表逐项一致」
的断言（`TestCapabilityTableIsComplete` 一类），**每个权限都必须被某个方法使用**，
**每个方法也都必须命名一个已声明的权限**。一个只用来"批准后台运行"、背后没有任何方法的
权限会正好违反它——那就是"用户被问了一个什么也不做的开关"。
而"把事件送到我这儿来"本来就已经说清了常驻帧想要什么。

## 3. 界面：配音工坊在市场窗口里

**桌宠面板没有任何语音入口，也没有第 5 个 tab。** 工坊是**这个插件自己的一个 HTML 文档**
（`market/plugins/com.shixiansi.plugin-voice/panel.html`），由**插件市场程序**挂在
「该插件的设置区」：

> 桌宠面板 → 设置 → **打开插件市场** → 选中「语音插件」→ 右侧就是工坊

两栏：**左栏角色**（点一下即切换），**右栏五条台词**
（每条显示「现在：…」徽章 + 试听 / 生成 / 用这版 / 清除），外加「整套换成这个角色」，
顶部三个开关。

> **为什么不在桌宠面板里**：面板是固定 380×520 的矩形，窗口区域按它裁剪，**长不大**；
> 而工坊是个工作面。市场窗口是 980×700 且可缩放，塞进去不用重排。
>
> 这也是插件机制的**通用**能力，不只对语音有用：**插件的界面可以由市场托管**。
> 上一版的 `PetPCVoiceStudio.exe` 因此被删掉了，`tools\build-all.ps1` 还会把
> build 目录里遗留的旧 exe 删掉——一个残留的二进制是"用户仍能运行、且会写出
> 已经没人读的旧库格式"的东西，比占地方严重得多。

### 3.1 市场托管的能力表是它自己的

两个宿主程序（桌宠、市场）**共用同一套调度器与资源路由**（`internal/plugins/dispatch.go`、
`asset.go`），但**能力表各是各的**，这是刻意的：

| 程序 | 提供 | 不提供（以及为什么） |
|---|---|---|
| 桌宠 | `audio.*`、`storage.*`、`config.*`、`net.fetch`、`todos.*`、`bubble.say`、`surface.*`、`llm.chat`、`events.subscribe` | — |
| 市场 | `audio.*`、`storage.*`、`config.*`、`net.fetch` | `todos.*`/`bubble.say`/`surface.*`/`llm.chat`/`events.subscribe`——市场没有待办文件、没有可以画气泡的宠物窗口 |

从市场调用后者会得到「本程序不支持该方法」。这比一张共享的表更诚实：共享表会宣称
这些方法到处可用，然后在更深的地方以 nil dereference 的形式失败。

> `timer.*`（`timer.state` / `start` / `pause` / `resume` / `stop`）曾经在桌宠那一行里，
> 现在**两个程序都不提供了**：番茄钟插件自己计时，宿主没有计时器可以借给谁。
> 权限数因此从 17 降到 15（`openspec/changes/todo-pomodoro-as-plugins` 阶 2）。

`events.subscribe` 值得单独说：语音插件**确实订阅**，但它是在**桌宠挂的那个常驻帧里**订阅的。
从市场订阅是这个程序兑现不了的承诺——它没有提醒调度器（番茄钟也没有了，见 §2.1 的补记），
只会记下订阅然后永远不发任何事件。所以拒绝它，并且说清楚。所以拒绝它，并且说清楚。

## 4. 生成即采用（与旧工坊不同）

插件的第一版**没有沿用**旧工坊「生成 ≠ 采用」那套 take 列表。当前行为是：

```
点角色      → 立刻换音色。该角色没录过的句子退回包内自带的片段（不静音）
生成        → 渲染这一句，写盘成功后**立刻采用**
改回内置    → 该句回到包内自带的片段
整套换成这个角色 → 5 条里缺的全部生成并采用
```

| 动作 | 效果 |
|---|---|
| 左栏**点角色** | 换音色：改 `settings.activeRole` 并保存。随后**再生成**的句子会用这个角色的权重。角色列表来自迁移写入的 `roleNames`，每个角色后面标着「已录几条 / 共 5 条」 |
| 某一句**生成** | 先切引擎权重（`set_gpt_weights` → `set_sovits_weights`），渲染 → `audio.save` → 宿主确认写盘成功 → **采用这一版** |
| **改回内置** | 删掉这一句的采用记录，回到包内片段（**不删**已生成的音频文件） |
| **整套换成这个角色** | 为每条台词挑一个属于当前角色**且文件确实在盘上**的 take 并采用，**纯本地操作**（不碰引擎）。该角色没录过的句子**保持原样**，不会被指向不存在的文件 |

> **读这一节时请注意**：「点角色」改的是**之后生成的句子**用哪个音色——
> 已经生成好的片段不会因此重渲染（那要几分钟 GPU）。
> 想把**现有**的 12 段整体换成某个角色，用左栏下面的「整套换成这个角色」。

**采用发生在"宿主确认写盘成功"之后，不是发出请求时。** 回复先被记为 pending
（`savingLine`），只有 `audio.save` 的确认回来才写进 `chosen`：
在确认之前采用，等于把桌宠指向一个还不存在的片段；而一次被拒的保存
（没有 `audio` 权限、磁盘满）会让它指向一个**永远不会存在**的片段。

> **这里比旧工坊少一层。** 旧工坊保留**每一版** take，所以「这一句读得不好」
> 可以生成多版、逐版对比、挑一版采用——而**生成永远不会自动生效**。
> 现在插件只记「当前采用哪一版」，**生成即采用**，逐句重试的代价是**上一版被取代**
> （文件仍在 `audio/` 里，但界面上没有入口再选回它）。
>
> 这是当前实现的**简化**，不是"生成即采用更好"的论证。
> `docs/voice-studio.md` 记录的完整工作流（take 列表、试听对比、显式采用）
> 是插件**继承下来但尚未实现**的部分，具体缺口见 §8 第 4 条。

### 4.1 片段缺失时退回内置，而不是静音

`resolveClipFor(lineID)` 是**唯一**的解析点，试听与实际播放都走它：

```js
const chosen = settings.chosen[lineID];
if (chosen && clips.some((c) => c.name === chosen)) return chosen;
return `${BUILTIN_PREFIX}${lineID}`;
```

它**对着宿主返回的清单校验**，而不是信任自己存的 `settings`。
这一条是必需的：用户可能在插件外面删掉一个片段，而 `settings.chosen` 活得比文件长——
只信自己的记录就会 `audio.play` 一个不存在的名字，结果是**一声不出**。

> 这与旧工坊的策略**相反**，所以值得说清：旧工坊在"当前角色没录过这一句"时
> **不出声**（并在界面标「待生成」），理由是"一边选着纳西妲一边放出可莉"
> 正是最初被报上来的困惑。现在的插件选择**退回包内片段**——
> 因为它有**随包分发**的音频，装完即用是它的核心承诺（见 §1）。
> 两者都是刻意的，只是承诺不同。

### 4.2 包内自带的 5 条就是"默认音色"

`resolveClipFor` 的后半截（`builtin-<line>`）就是默认音色，而它的元数据在
`settings.takes` 里——"这个片段属于哪个角色"是**只有插件知道**的信息，
宿主能列出的 `audio.list` 只有 slot 名和字节数。

**但这个字段目前是写进去了却没人读**：迁移（`voice_migrate.go`）**确实会**把
`takes` / `roleNames` 写进 `voice-settings`，可是插件的 `app.js` 里
`settings.takes` 与 `settings.roleNames` 各有 **0 处引用**——
一次都没有读过。插件的 `LINES` 表是硬编码的 5 条，`roles` 数组也从不填充。

直接后果有两个，都在 §8 里记着：**左栏角色列不出来**，
以及**「整套换成这个角色」没法知道"哪些句子已有该角色的版本"**（那个按钮还没接线）。

## 5. 引擎由你自己启动

角色的声音由**本机 GPT-SoVITS** 合成（`config` 里的 `ttsBaseUrl`，默认
`http://127.0.0.1:9880`；权重路径与参考音频也在那里填）。

**插件不会替你启动引擎。** 这是明确的取舍：**"启动一个进程"这项能力一旦交给任意已装插件，
等于给它们任意代码执行**。所以：

- 工坊顶部的状态指示器只告诉你**服务在不在**；
- 连不上时给出启动命令；
- 引擎未运行时点「生成」**不会发请求**（不是发出去再失败）。

**播放路径永远不需要引擎**：包内自带的 5 条装完即用；引擎只在你想**换角色**、
或重新渲染某一句时才需要。

> 这和当初被停用的**实时合成**（`_archive/README.md`）是两件事：
> 这里每条台词**只合成一次、之后永久复用**，所以"慢/重/不稳定"三条都不适用——
> 而**不稳定反而变成了有用的东西**：生成多版，挑最好的那一版。

### 5.1 `net.fetch` 取音频要显式要 base64

正文默认按**文本**返回。要取二进制必须说 `encoding: "base64"`，因为文本形式是**有损**的：
Go 的 JSON 编码器把非法字节替换成 U+FFFD，一个 WAV 于是"大小看着对、播出来是噪声"。
`base64` 返回原始字节的 base64，插件解码后交给 `audio.save`。

## 6. 老语音库的一次性迁移

上一版把语音库放在 `<数据目录>\voice\user\`（`voice-user.json` + `clips\<台词>\vNNN.wav`）。
首次启动时 `plugins.MigrateVoiceData`（`internal/plugins/voice_migrate.go`）把它**复制**进
`plugin-data\com.shixiansi.plugin-voice\`：

| 旧 | 新 |
|---|---|
| `config.json` 的 `voiceEnabled/voicePomodoro/voiceReminder` | `voice-settings` 里的三个开关 |
| `voice-user.json` 的 `roles` | `voice-settings` 的 `roleNames` |
| `voice-user.json` 的每个 take | `audio\<line>-v<NNN>.wav` + `voice-settings` 的 `takes` |
| `voice-user.json` 的 `lines[].chosen` | `voice-settings` 的 `chosen` |

三条性质与对话迁移（`migrate.go`）相同：

1. **只读来源**——`voice\user\` 原样不动；
2. **先写完再打标记**——中途失败就不留标记，下次启动重试；
3. **标记一存在就不再读**（`.migrated`）。

### 6.1 与对话迁移的两处不同，都是刻意的

**(a) 来源不改名、不删除。** 对话迁移会把 `llm-history.json` 等改成 `.bak`，这里**不会**。
差别在**重建成本**：聊过的历史再聊一遍就有了；而这些片段每一条都是**几分钟的 GPU 时间**，
且需要跑着 GPT-SoVITS 才能重做。它们一共几 MB，而"猜错了"的代价不可恢复——
所以原样留着，迁移只做复制。

**(b) 绝不采用一个片段不在磁盘上的版本。** `chosen` 只在两个条件同时成立时沿用旧的 1-based
下标：那个 take 属于**当前角色**，**且**它确实被复制成功。否则退而取当前角色的
**第一个已复制**的 take。指向一个不存在的文件会让插件**一声不出**——
那比"采用了次一版"糟得多，因为它看起来就是功能坏了，而不是选错了。

一个在 JSON 里被点名、磁盘上却不存在的片段会被**跳过并打印到 stderr**，
而不是让整次迁移失败：其余台词照常能用，为丢一个文件而让用户**什么都没迁过来**更糟。
反过来，一个**解析不了**的旧库会**报错而不是跳过**——静默产出一个空插件
和"迁移成功、但你的语音没了"看起来一模一样。

### 6.2 插件自己差点把迁移结果抹掉（真事故，已修）

这条记在这里，因为它的**表现形式**才是危险的地方。

迁移写完之后，插件在**握手阶段**就把包内那 5 条内置音频 `audio.import` 进来，
并顺手 `saveSettings()` 打了个 `imported` 标记。但那一刻它自己的 `settings`
**还是内存里的空默认值**——`storage.get` 的回复还没回来。于是这次保存把刚迁进来的库
整个覆盖成了 `{activeRole:"",chosen:{},takes:{},roleNames:{}}`：

- 12 段音频**还在磁盘上**；
- 指向它们的**采用信息没了**；
- `.migrated` 标记**还在**，宣告"迁移成功"。

净效果是：桌宠改说内置音色，插件看着一切正常，而用户几十小时的渲染躺在磁盘上没人引用。

修法是给写入加一道**顺序约束**，而不是加一个重试：

- `saveSettings()` 在 `settingsLoaded` 为真之前**直接返回**——写成"排队等读回来再存"
  反而会掩盖调用方**顺序写错**这个事实；
- `settingsLoaded` 只在 `storage.get` 的**回复处理里**置位；
- 会写盘的 `ensureBuiltins()` 因此被移到**回复处理里**调用，`reloadState()` 变成**纯读**；
- 特例：**没拿到 `storage` 权限时**直接置位——那时根本没有"读"可等，
  否则开关会永远静默失效（存的请求会被拒，这是正常答复）。

回归用例在 `market/tests/plugin-voice.test.js` 的
「nothing is written before the stored settings have been read」一节：
断言握手后、回复到达前**一条 `storage.set` 都没有**，且回复到达后的每一次写入
都带着**读到的** `activeRole` / `chosen` / `roleNames`。

顺带修掉的另一个 bug：`ensureBuiltins()` 原本**不看** `settings.imported` 标记，
所以每次启动都会重新导入一遍。多花 569 KB 事小，**把用户删掉的内置片段又装回来**事大。

## 7. 数据放在哪

```
%AppData%\PetPC\
├── plugins\com.shixiansi.plugin-voice\       插件本体（含 lines\*.wav，来自 assets）
├── plugin-data\com.shixiansi.plugin-voice\
│   ├── voice-settings                        三个开关、角色表、takes、chosen
│   ├── audio\builtin-<line>.wav              从包内导入的内置片段
│   ├── audio\<line>-v<NNN>.wav               渲染 / 迁移过来的片段
│   └── .migrated                             迁移标记
└── voice\user\                               旧库：只被读过一次，永不改名、永不删除
    ├── voice-user.json
    └── clips\<台词>\vNNN.wav
```

插件自己的设置走宿主的 `storage`（键 `voice-settings`），
`config.get`/`config.set` 走 manifest 的 `config` 声明（引擎地址与权重路径）。
两者都在插件的私有目录里，**卸载插件会一并删掉**——包括那些片段。
旧库 `voice\user\` 不在卸载范围内，它已经不属于任何插件。

>
> - **左栏角色列表画不出来**：角色数组是模块级 `[]` 且**从未赋值**，`renderRoles()`
>   在启动路径上**从未被调用**（唯一调用点在它自己的点击 handler 里）。
>   现在角色来自迁移写入的 `settings.roleNames`，`renderRoles()` 在设置回复到达时与
>   `clips` 回复到达时都会被调用。测试：`the character column` 一节。
> - **「整套换成这个角色」没有接线**：`els` 登记了按钮，但**没有 `addEventListener`**。
>   现在是纯**本地**操作（不碰引擎）：为每条台词挑选属于当前角色**且文件确实在盘上**的
>   take，没录过的句子**保持原样**而不是指向不存在的文件。
> - **`gptPath` / `sovitsPath` 要求填但从不使用**：`generate()` 会检查它们非空，
>   却从不把权重发给引擎，于是**"换角色"不会真的换音色**（引擎常驻一个模型，
>   合成用的是上一次加载的那个）。现在按
>   `set_gpt_weights` → `set_sovits_weights` → `POST /tts` 三步走。
> - **`settings.takes` / `roleNames` 被迁移写入却从不读**：现在它们驱动角色列与逐条采用。

## 9. 已知限制

- **换角色需要本机装着 GPT-SoVITS**（默认 `D:\GPT-SoVITS`）。没有它，工坊只能显示
  "语音服务未运行"，但**包内自带的片段照常工作**——语音是可选增强，不是依赖。
- **引擎是 CPU 推理**：本机 `torch 2.14.0+cpu`，单句 2~5 秒、全套 15~25 秒。
  有 NVIDIA 显卡换个 CUDA 版 torch 会快一个数量级，本项目没有为此做适配。
- **角色切换会让引擎重新加载权重**（约 1.5 秒），所以逐条交替用不同角色生成会比一次一个角色慢。
- **改台词文字要改插件源码**：那 5 句话现在是 `market/plugins/com.shixiansi.plugin-voice/app.js`
  里的 `LINES` 表，改完要重新渲染包内音频并重新打包。工坊换的是**音色和读法**，不是内容。
- **常驻帧最多一个**：`background: true` 的插件由桌宠挂一个隐藏 iframe。两个常驻插件会各要
  一个帧，而"事件投给谁"必须是唯一的，所以没有做多帧调度。
- **市场里调不到宿主能力**：见 §3.1。工坊因此只做本地的事（列角色、试听、生成、采用），
  需要"让桌宠说一句"时它只能靠事件驱动。
- **旧库不会自动清理**：`voice\user\` 保留在磁盘上（见 §6.1）。想回收那几 MB 要自己动手。
