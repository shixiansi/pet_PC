# design: 待办与番茄钟搬进插件（路 A）

## 0. 决定（用户拍的）

- **路 A**：待办数据、番茄钟状态机都搬进插件；宿主的 `todos.*` / `timer.*` 能力退休。
- **左键**：什么都不做（面板不再是入口）。
- **门控进插件**：写总结 / 选待办由插件自己的界面承担，接受"休息前必须写总结"从**硬约束**降级为
  **插件行为**（用户可以关掉那个插件，或换个不守规矩的插件）。

## 1. 拆成什么

| 插件 | 拥有 | 权限 | 落点 |
|---|---|---|---|
| `com.shixiansi.plugin-todo` | 待办列表、提醒调度（挑条目/说话/抖动） | `storage` `plugin.config` `events`? `pet.bubble` | 浮层面（面板那一列，380×520）+ 常驻帧（后台跑提醒） |
| `com.shixiansi.plugin-pomodoro` | 番茄钟状态机、阶段、记录与统计、两道门控 | `storage` `plugin.config` `events` `pet.surface` `pet.bubble` `timer.*`→无 | 浮层面（计时 + 记录 + 门控输入） |

两个插件都需要 `llm.*` 吗？不需要——门控只是输入框。

## 2. 宿主留下什么、删什么

**留下**：窗口 / 宠物 / 区域裁剪（§3.2 的三态）/ `pet.bubble` 能力 / 托盘 / 显示隐藏热键 / 插件系统与市场 / `events` 总线。

**删**：

| 去处 | 内容 |
|---|---|
| `internal/pomodoro/*` | 状态机整体 → 复制进 `plugin-pomodoro`（Go 侧删掉使用方，包本身可留作参考或直接删） |
| `app_pomodoro.go`（53KB） | 绑定、记录、统计、气泡门控 |
| `app_reminder.go`（20KB） | 提醒调度 → 搬进 `plugin-todo` |
| `internal/store` 的待办族 | `todos.json` 的读写与迁移 |
| 前端面板 | 三个 tab、左键开关、`#chat-slot` |
| 权限表 | `todos.read` `todos.write` `timer.read` `timer.control` 退休（17 → 13） |

**`panelSlot` 一起退休**：面板没有了，槽位就没有宿主。对话插件的"完整记录"视图改走它自己的
浮层面（同一条 380×520 的面板列）——这是本次改动**必须先处理**的连带影响，否则对话插件会失去它
唯一的记录视图。

## 3. 数据迁移（不能丢用户的待办）

`todos.json` 与 `settings.json` 里与待办/番茄钟有关的键（`focusMinutes`、`shortBreakMinutes`、
`longBreakEvery`、`reminder*`…）要迁进两个插件的私有 `config` 与 `storage`，一次性、幂等、
失败不改任何东西。现成的先例是 `plugin-migrate`（对话插件的 AI 配置迁移），照它的做法：
宿主在首次启动时检测到"老数据 + 插件已装"就写一份，然后打标记，永远不再写第二次。

## 4. 硬约束与代价（写进 README，不许含糊）

1. **门控不再是硬约束**。插件可以被停用、可以被换掉；停用之后没有"休息前必须写总结"。
   这是路 A 的必然结果，不是 bug。
2. **待办与提醒在同一个插件里**（提醒读待办），所以停用待办插件＝同时失去提醒。
3. **`AGENTS.md` §1 的立场要改写**：从"待办/番茄钟/提醒是主角，AI 是沙箱插件"变成
   "宿主只提供窗口、区域、气泡、权限与事件；一切界面与业务都在插件里"。§3.1 的权限表数字、
   README 的能力表、`.dev/check-frontend.cjs` 里的硬编码词表、`tools/plugin-market/cc` 的 dev 桩
   都要同步（那一节列的七处）。
4. **区域裁剪不受影响**：插件仍然只能用声明矩形，宿主仍然只裁矩形并集（§3.2 一字不改）。

## 4.5 现在的过渡态（读这一节再动手）

阶 1、阶 2 的前半已经落地（两个插件、槽位入口、状态机移植），**但宿主那套还在跑**，于是有三处
"两份同时存在"。逐条列清楚，免得下一个人以为是 bug：

| 现象 | 原因 | 收尾动作 |
|---|---|---|
| 提醒会**发两次** | 宿主 `app_reminder.go` 的调度器 + 待办插件的常驻帧，读的是同一份待办 | 删宿主的 `startReminderLoop`/`tickReminder`/`setNextReminder`/`makeUpMissedReminder`/`noteBreakReminderOwed`（保留 `RemindNow` 手动那条），然后把插件的 `remindEnabled` 默认值改回 `true`。**现在插件侧默认关**，所以只有一个在发 |
| 待办/番茄钟**面板 tab 还在** | 阶 3 才删 | 阶 3 |
| 番茄钟**两套计时器**（宿主 + 插件 2.0.0 源码） | 插件 2.0.0 已自持状态机，但**还没打包/安装**（打包要写 `market/dist` 与 `%APPDATA%`，需提权，用户尚未批准） | 跑 `market/tools/package.ps1` + 安装五个文件；在那之前**已装的仍是 1.0.0**（驱动宿主计时器，行为不变） |
| **`timer.phaseEnded` 没有发射方了** | 它唯一的发射者是宿主计时器（`completePhaseLocked` → `notifyPluginPhaseEnded`）。宿主计时器删掉之后，**语音插件的「番茄钟结束」那句不会再响**：它订阅的正是这个事件，而插件不能自己发宿主的 事件 | 未定。三条路：(a) 接受，番茄钟结束时由番茄钟插件弹一句文字气泡（它已有 `pet.bubble`）；(b) 番茄钟插件用 `plugin.share` 写一个「阶段结束」的时间戳，语音插件的常驻帧轮询它（≤2s 延迟，成本可忽略）；(c) 新增一个很窄的「插件声明一条事实」方法 + 权限——最贵，且要动 §3.1 的七处。**在选定之前，事件名与 `SubscribableEvents` 保留**：删掉会让已装的语音插件 `events.subscribe` 直接报错，比不响更糟 |

**宿主侧退休清单**（阶 1/2 的收尾，一次做完）：
`app_reminder.go` 的调度部分、`app_pomodoro.go` 的状态机外壳与门控、`internal/store` 的待办族、
面板的待办/记录 tab、`todos.*` 与 `timer.*` 两条权限（§3.1 的七处 + README），
以及对话插件的三个待办工具（`todo_list`/`todo_add`/`todo_complete`）。

## 5. 台阶（每一阶都能单独交付、单独回退）
### 阶 1：待办插件接管数据与提醒

- 新插件：`storage` 存待办；浮层面画列表（面板那一列）；常驻帧跑提醒循环（读自己的列表、
  `pet.bubble.say` 说话）。
- 宿主：删 `app_reminder.go`、删待办的 store 读写与面板 tab、迁数据、退休 `todos.read/write`。
- 验收：老待办一条不少；提醒照旧按间隔挑条目；`todos.*` 从权限表消失后，
  其它插件（QQ 桥、bilibili）若用过它——**先查**（`plugin-qq` 用了 `todos.read` 吗？用完再说）。

### 阶 2：番茄钟插件接管状态机与门控

- 移植 `internal/pomodoro`（阶段、结转、休息）到插件；浮层面画计时与记录；
  两道门控变成插件自己的输入界面。
- 宿主：删 `app_pomodoro.go` 的门控与统计、退休 `timer.*`、托盘与热键里番茄钟相关的项改成
  "让插件自己处理"（或直接删掉对应菜单项）。
- 验收：阶段与结转行为与搬之前逐条一致（把 `machine_test.go` 的用例搬过去当规格）。

### 阶 3：面板退场

- 删前端面板与 `panelSlot`；对话插件的记录视图改走自己的浮层面；左键解绑；
  README / `docs/*` / AGENTS 立场同步。
- 验收：左键无反应；对话插件仍有记录视图；`check-frontend.cjs` 与新权限表一致。

顺序的理由：阶 1 不碰时序；阶 2 有一个可搬的参照实现（`machine.go` + 它的 20KB 测试）；
阶 3 是纯删，做完就回不去了，所以放最后。

## 6. 风险

- **`app_pomodoro.go` 有 53KB**，门控、记录、统计、断言缠在一起；搬的时候必须先把它拆成
  "状态机（可搬）"与"宿主外壳（删除）"两半，否则会把宿主假设带进插件。
- 其它已发插件可能依赖 `todos.*`（bilibili/qq 的 manifest 里有 `todos.read`），
  退休前要逐个确认，否则它们会静默失去功能。
- 三个权限退休 = `AGENTS.md` §3.1 的七处同步 + README 的能力表与标题数字，漏一处门禁就红。
