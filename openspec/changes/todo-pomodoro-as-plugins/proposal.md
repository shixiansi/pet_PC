# proposal: 待办与番茄钟交给插件，宿主不再有面板

## 用户要的

> 把待办和番茄钟也全部整成插件，左键点击的面板不再显示

## 这件事有多大（先看清单）

今天宿主自己拥有的、和这两件事有关的代码：

| 位置 | 内容 | 体量 |
|---|---|---|
| `internal/pomodoro/machine.go` | 番茄钟状态机（阶段、结转、休息） | 16KB + 20KB 测试 |
| `app_pomodoro.go` | 状态机的宿主外壳：绑定、事件、记录、统计、气泡门控 | **53KB** |
| `app_reminder.go` | 提醒调度（读待办、挑条目、决定说不说） | 20KB |
| `internal/store` | `todos.json`、记录、设置的读写与迁移 | 待办 1 族 + 设置 |
| 前端面板 | 待办 / 记录 / 设置三个 tab，左键开关，380×520 | `main.js` + 样式 |
| 托盘 / 全局热键 | 开始/暂停/跳过/显示隐藏、`Ctrl+Alt+S/H` | `app_tray*`、`app_hotkey*` |
| 气泡三态 | 选待办 / 写计划 / 写总结——**带输入框、且是计时器的门控** | `app_bubble*` |

## 一个绕不开的硬约束

`AGENTS.md` §1 写的立场是「**待办 / 番茄钟 / 提醒是主角，AI 是沙箱插件**」。
这不是风格，是权限模型：插件只能做用户逐项授权的动作，而**番茄钟的门控**（休息前必须写总结、
专注前必须选待办）依赖宿主能**拦住**它——插件做不到"拦住宿主"。

具体两条，A 方案必须正面回答：

1. **气泡不能由插件提问**。插件只有 `pet.bubble`（说一句话），没有"带输入框、等你回答"的能力。
   而写总结/写计划正是那种气泡，且 `OpenPluginSurface` 会**拒绝**在有提问时打开浮层面
   （提问是计时器的门控，`reminder-pomodoro.md` §4.5.1）。
2. **提醒读的是待办**。`app_reminder.go` 每次挑条目都查 todo 列表；两者不能只搬一个。

## 两条路（这是需要你拍板的地方）

### 路 B：**界面**搬进插件，数据与状态机留在宿主（推荐先做）

- 两个官方插件：`todo`（读 `todos.read/write`）、`pomodoro`（读 `timer.read`、驱动 `timer.control`、订阅 `events`）。
- 宿主**已经**提供了这三组能力——插件今天就能画出待办列表、开始/暂停番茄钟，不需要新权限。
- 宿主删掉**面板 UI**（三个 tab、左键开关），保留 `internal/pomodoro`、提醒、气泡门控、托盘、热键、存储。
- 插件界面放在哪：浮层面矩形可以声明成**面板那一列**（`dx: 160, dy: -60, w: 380, h: 520` 一类）——
  浮层面打开时面板本来就是关的，那块区域是空的。这就是"面板不再显示"最自然的替代。
- 代价：门控（写总结/选待办）仍然是宿主的气泡，插件改不了它。**这条要写进 README**，否则
  「番茄钟是插件」会让用户以为换个插件就能改规则。

### 路 A：数据 + 状态机整体搬进插件

- `internal/pomodoro`、待办存储、记录、提醒调度搬进插件（`storage` + `events` + `background`）。
- 宿主的 `todos.*` / `timer.*` 能力**删除**（它们变成"插件之间的私事"），权限表从 17 项缩到 13 项左右
  ——按 `AGENTS.md` §3.1，那是**七处同步 + README**。
- 门控必须改形：插件不能再"拦住宿主"，只能自己弹自己的界面。这会把"休息前必须写总结"从
  **硬约束**降级成**用户可关的插件行为**——这是产品决定，不是重构。
- 记录/统计/提醒要跟着搬；`app_pomodoro.go` 那 53KB 会大半变成插件代码。

## 建议的顺序

1. **B 的第一步**：新增 `com.shixiansi.plugin-todo`（面板那一列的浮层面，读写既有待办），
   宿主删除"待办"tab；左键不再开面板。这一步不动任何数据与门控，可回退。
2. **B 的第二步**：`com.shixiansi.plugin-pomodoro`（计时、阶段、记录入口），宿主删除对应的面板 tab。
3. 到这一步再看：门控气泡是否也要搬（＝路 A 的核心），以及 `todos.*`/`timer.*` 权限是否要退休。

## 明确不做（除非你要求）

- 不在同一次改动里同时搬数据、状态机、门控和权限表——那样出问题时无法判断是哪一层坏了。
- 不动提醒（它读待办，跟着第 1 步之后才有意义）。

## 需要你回答

1. **A 还是 B**？（数据/状态机搬不搬）
2. 面板没了以后，**左键点击桌宠**要做什么：什么都不做 / 打开待办插件 / 打开托盘同款菜单？
3. 番茄钟的"写总结/选待办"门控，是否可以接受**留在宿主**（路 B 的代价）？
