# design: 宠物头顶的一行字（`pet.badge`）

## 1. 为什么是"宿主画、插件给字符串"

| 方案 | 问题 |
| --- | --- |
| 浮层面块（`surface: [...]` + `surface.blocks`） | 槽位一次一个：时钟开着，待办列表和番茄钟主卡片就打不开 |
| 气泡（`bubble.say`） | 不是持续显示，还会盖掉提醒 |
| **宿主在宠物框内画一行字**（选中） | 不占槽位、一直在；代价是宿主多一个能力 |

选中的方案唯一要小心的是**别让宿主知道番茄钟**。所以能力的形状是 `{text: string}`，而不是
`{mode:"countdown", endsAt:…}`：解析、格式化、什么时候清除，全在插件里。宿主这边 `24:59` 与
`3 项` 没有任何区别。

## 2. 为什么不新增第 14 项权限

`AGENTS.md §3.1` 那张"加权限要同步七处"的清单是这次决定的直接依据：新增一项要动
`capability.go`（常量/顺序/文案）、一个注册它的方法、`manifest_test.go` 的 `want` 与测试名、
`check-frontend.cjs` 的硬编码词表、`bridge.ts` 的 `LABELS`、README 的表格与标题——外加
**每个已装插件升级时再弹一次授权**。

`pet.surface` 已经表达"这个插件可以在宠物身上画自己的像素"，徽章是同一授权换了个矩形。所以
借用，并在三处写清这件事（`app_pet_badge.go` 的文件头、手册的能力表、自检工具的表注释）——
借用的代价是名字不够精确，收益是升级不需要用户重新点一遍授权。

## 3. 为什么"读时过滤"而不是"监视插件列表"

插件被停用/卸载后就再也不调用 `pet.badge` 了，它留下的字符串会一直挂在宠物头上。

两种修法：

- 监听插件列表的变化（文件监视或轮询）→ **这是刚被删掉的那个模式**。上一轮用户的原话是
  "怎么是哪个定时器一直在读"，同样的批评适用于这里。
- **把文字当成派生值**：谁读谁过滤，`liveBadge()` 跳过已经不在/已停用的 id。于是任何一次刷新
  （`PetBadge()`，页面重载、宠物隐藏再显示）都自动修正，不需要任何常驻机制。

选后者。代价是"停用之后要等下一次读才消失"，而读发生在每次页面刷新与显示切换上——一个停用的
插件不会在屏幕上留一分钟以上。

## 4. 事件只在可见文字变化时发

计时器每秒算一次，但 `24:59` 会连续 60 次相同。`setPetBadge` 比较 `last`，只在变化时
`emitEvent`。没有这一步，一个番茄钟每小时会推 3600 次、页面重绘 3600 次，而屏幕上只变了 60 次。

插件侧同样只推变化（`pushBadge` 里的 `badgeText` 比较）：一次推送就是一次跨 iframe 的 IPC。

## 5. 几何：为什么长在 `#pet` 里

`AGENTS.md §3.2`：没有浮层面和气泡时，窗口区域被裁成宠物那个矩形。头顶的时钟如果挂在
`#pet` 外面，会被原生区域切掉；把区域放大来容它，就会在宠物旁留下一条页面从不绘制、却会吞掉
桌面点击的窗口。所以它是 `#pet` 里的一个绝对定位元素，`top: 2px`、水平居中，并且用
`font-variant-numeric: tabular-nums`（否则 `24:59` 与 `11:11` 宽度不同，时钟会左右抖）。

## 6. 已知取舍

- 文字上限 16 个字符：够 `24:59` 或 `24:59 专注`，不足以盖住宠物。
- 同一时刻只显示"最后一个设置的那一行"：两个插件都想要头顶时，后设置的那个赢，前一个不报错
  （它无从知道自己被盖住了）。目前只有番茄钟用这个能力。
- 徽章不随宠物隐藏而清空：状态还在，宠物回来就还在——这是对的，计时没停。
