# design: 对话浮层面的三块固定盒子

## 1. 角色怎么定

`surface.rectIndex` 是**声明下标**，宿主已经把它原样传给每个帧（`PluginFrame.initMessage`），
所以"我是谁"是静态事实，不需要运行时猜：

| rectIndex | 角色 | 根 class |
|---|---|---|
| 0 | 提问框 | `view-question` |
| 1 | 回复框 | `view-answer` |
| 2 | 输入框 | `view-input` |
| （panel 槽位） | 面板 | `view-panel` |

删掉的猜法：`isCardBlock()` / `isBarBlock()` / `isReplyCard()` / `visibleComposer()`。
它们存在的原因是"一块盒子有两种用途"，用途固定之后它们没有对象。

**握手前**（`init` 到达之前）的根 class 是 `view-boot`：全透明、什么都不画。
以前默认是 `view-panel`，于是每个 300×48 的帧在握手前会先画一帧"迷你面板"（标题栏 + 列表 +
输入框）—— 一次可见的闪动。`view-boot` 把第一次绘制变成空白。

> 不能把角色放进 URL（`?block=answer`）来彻底消掉这一帧：宿主拼 iframe 的 `src` 时不会加查询串
> （`plugin-host.js` 的 `createElement`），只有控制中心会加 `?theme=`。等哪天宿主愿意加，
> `view-boot` 仍然是对的兜底。

## 2. 几何：三块都塞进宠物周围

默认几何（`internal/store/store.go`：宠物 150×200、面板 380×520；`app.go` 把宠物竖直居中）：

```
窗口 540×520（逻辑 px，与 DPI 缩放无关）
petY = (520 - 200) / 2 = 160      → 头顶 160、脚下 160
```

| 块 | dx | dy | w | h | 落地 y | 说明 |
|---|---|---|---|---|---|---|
| 提问框 | -75 | -156 | 300 | 48 | 4..52 | 2 行，超出用 `-webkit-line-clamp:2` + 省略号 |
| 回复框 | -75 | -100 | 300 | 100 | 60..160 | 90px 气泡 + 10px 尖角带，底边**正好**压宠物头顶 |
| 输入框 | -75 | 208 | 300 | 56 | 368..424 | 脚下 8px 间隙，无尖角 |

> **【已调整】** 提问条后来改成 **300×40 / dy -148**（文字垂直居中），回答气泡改成**顶部对齐**，
> 见 `surface-hidden-keeps-frames` design §4.1。回答气泡仍是 100，底边仍压在宠物头顶。

- 头顶合计 156/160，留 4px；脚下合计 56/160，留 104px。
- `dx: -75` 让三块的中心落在宠物的中心上（宠物 150 宽，300 宽的块各外扩 75）；
  宠物贴窗口边时宿主会 clamp，`rect.tailX` 因此不是 50%——尖角照旧用 `tailX`。
- 回复框的底边 `dy + h = 0`：尖角的顶点落在宠物头顶上，这是"尖角必须在被裁的矩形之内"
  那条规则（见 style.css 头注释）的直接结果。
- `maxH` **去掉**：增长路径在这个预算下必然是负收益（见 §6）。

## 3. 谁画什么、谁写什么

| 帧 | 画 | 发请求 | 写转写 |
|---|---|---|---|
| 面板 | 全部转写（提问 + 回答） | 是（面板里的输入框） | 发送帧 |
| 提问框 | 最后一条 `user` | 否 | 否 |
| 回复框 | 当前/最后一条 `assistant` | 否 | 否 |
| 输入框 | 只画输入框 | 是（浮层面里的输入框） | 发送帧 |

"发送帧"用 `ownRequestId` 判定，不用 holder 上的 `owner` 标志：输入框作为发送方**不画任何回答**，
它只需要知道"这条请求是我发的"，好把答案写进转写。

## 4. 事件流（这一节就是"流程"）

```
用户按发送（输入框或面板）
  ├─ remember('user', text)          → storage.set
  ├─ ownRequestId = requestId
  ├─ request('llm.chat', {...})
  └─ busy = true                     → 发送键禁用（同一时刻只允许一条）

llm.delta（三帧都收到）
  ├─ 回复框：holder 不存在就建一条，清掉上一条回答，入队打字机（50ms/字）
  ├─ 面板：   在自己那条流式行上追加
  ├─ 提问框：本轮第一次收到 llm.* → storage.get 读一次，画最后一条 user（一次，之后不再读）
  └─ 输入框：什么也不画

llm.done
  ├─ 回复框：用 payload.text（权威全文）替换已显示的内容；打字机队列没吐完就吐完再校正
  ├─ 面板：  同上，替换那条流式行
  ├─ 发送帧：立刻 remember('assistant', full)  → storage.set   ← 不再等打字机
  └─ 发送帧：ownRequestId = null，busy = false
```

关键差别（相对现状）：

- **没有替换**。提问留在提问框，回答进回复框，两块永远不会互相变成对方。
- **没有轮询**。回复框自己收 delta，不需要从磁盘读第二遍；`storage.get` 只出现在"打开时读一次"
  和"提问框每轮读一次"。
- **没有延迟落盘**。写入不再挂在打字机队列清空的那一刻——那条路在"done 到达时队列已空"的
  情况下会永远不执行（旧 `afterTyping` 泄漏），导致这一轮答案根本没进转写。

## 5. 为什么这一版还不能"只改盒子的隐藏和显示"

> **【已跟进】** 这一节描述的限制已经**不存在**了：`surface-hidden-keeps-frames` 把"隐藏"
> 从"删块"改成"保留视图条目、只把它从窗口区域里去掉"，前端也改成按声明下标对位，于是隐藏
> 一块不再重建任何文档。对话插件现在**空闲时只留输入框**，一发消息两块内容盒子回来
> （见该变更的 design §3）。下面保留的是当时的推理，它解释了为什么要先做那一步。

用户提的方向是"整个过程只改变盒子的隐藏和显示"。**方向对，但当前的隐藏语义会把它做坏**：

1. `surface.blocks {hidden:[i]}` 把块从 `view.Rects` 里**删掉**（`computePluginSurfaceSized`），
2. 前端判断条件是 `surfaceFrames.length !== rects.length`（`plugin-host.js`），块数一变就
   `clearSurface()` —— **所有**帧 `destroy()`，再按新数组重建，
3. 帧与矩形的对应关系是**按数组下标**的（`surfaceFrames[i] ↔ rects[i]`），隐藏第 0 块后
   原来的第 1 块会落到下标 0（历史上因此把输入胶囊画成过结果条）。

于是"切换一次可见性"＝三份文档全部重新加载、重新握手。后果是具体的：输入框打到一半的草稿丢失；
回复框正在直播的文本丢失（新文档还没收到第一条 delta 就已经过了那几条事件）。

而发送的瞬间恰恰就是"要切换可见性"的瞬间，正是最不能重建的时刻。
所以这一版**三块常显，一次 `surface.blocks` 都不调**。代价是空闲时提问框那一带（300×48）
是透明但会吃点击的矩形；它既不盖宠物也不盖面板。

正确形态是"隐藏＝保留帧、只是不进 region"（view 里条目带 `visible:false`，前端按声明下标对位），
那是宿主改动 + 一条被测试钉住的契约（`app_plugin_surface_blocks_test.go`），作为**第二步**。

## 6. 已知边界与为什么不现在解决

**A. 头顶预算与 `PetScale`。** `petY = (520 - 200×PetScale)/2`，默认 1.0 时是 160。
`PetScale > 1.04` 后三块的上方部分会越过窗口顶边被裁（今天那张回复卡在 `dy=-166` 下已经被裁掉 6px，
是同一机制）。要根治只能改"宠物在窗口里的竖直位置"或"回答框挪到宠物侧边"，两者都超出本变更。

**B. 输入框的 `dy` 依赖宠物高度。** `dy` 是从**宠物左上角**量的，脚下那块只能写死
`200 + 8 = 208`，于是它只在 `PetScale = 1` 时正好贴在脚下；`PetScale` 变大就会压到宠物身上。
彻底的解法是给 manifest 的矩形加一个锚定字段（例如 `anchor: "pet-bottom"`，几何里改成
`petH + dy`），那要动 `internal/plugins` 的解析/校验、`computePluginSurfaceSized`、
`mirrorDeclaredRects`（只处理水平，不受影响）和它们的测试。本变更刻意不做：
用户现在的 `petScale` 是 1.0，而这块新增能力会牵到宿主的清单契约。
**如果哪天要动 `PetScale`，先做这个字段。**

**C. 回答框固定 100px（≈4 行）。** 超出从顶部裁（`justify-content: flex-end` + `overflow:hidden`，
保留"最新的话先说"的读法）。全文在面板里。这也顺带去掉了旧 `requestCardHeight()` 的测量问题：
`flex-end` 溢出的部分在顶部，`scrollHeight` 读不到，量出来的数天然偏小——那块代码是错的，
现在整段删掉。

## 7. 打字机留在回复框里

`50ms/字` 的节奏是用户明挑的（旧 `app.js` 里写着 "FIXED 1 char / 50ms, the user's choice"），
所以保留，但**只保留为显示效果**：它不再影响落盘（落盘在 `done`），也不再和别的帧对时序
（面板与浮层面互斥，同一时刻只有一个在画字）。`done` 到达时若队列还没吐完，先吐完，再用
权威全文校正一次——旧代码"先把 full 写进节点、打字机继续追加"会得到重复文本。

## 8. 测试与门禁

- `market/tests/plugin-app.test.js`：角色三态、提问框/回复框各画什么、回复框直播、输入框不再是
  结果区、`done` 立即 `storage.set`、非发送帧不写、manifest 几何与头顶预算断言（156 ≤ 160）。
- `go test ./...`：`TestBuiltinSampleAgreesWithTheMarketCatalogue` 要求
  `market/dist/com.shixiansi.plugin-chat-1.6.0.zip` 与 `internal/plugins/sample/` 里那份**字节相同**，
  并由 `embed.go` 的清单点名。打包走 `market/tools/package.ps1`（时间戳固定，可重现）。
- 真机：装插件重启（`tools/install-fixed-chat-plugin.ps1` 复制四个资源文件），看
  输入框占位符上的构建标记、三段盒子的形状、尖角只在回复框、发送后提问上移且回答在下面直播。
