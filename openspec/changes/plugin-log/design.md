# design.md — plugin-log

## D1 为什么是方法，不是"给帧开 devtools"

用户不会开 devtools，而报告里贴的永远是 `pet.log`。让插件的话进那份文件是唯一有用的方向。

## D2 为什么强制一行

日志的解析按行、前缀是自由文本。允许换行 = 允许插件写一行 `2026-01-01T00:00:00 INFO …`，
读者无法分辨。所以换行压成空格——测试里专门试了这种伪造。

## D3 为什么借用 `storage`

三个候选：新加一项权限、借 `storage`、借 `events`。新加权限意味着每个用户装插件时被问一次
"允许它写日志"——一个没有人会拒绝、也没有任何后果的同意项，正是 AGENTS.md §3.1 拒绝的那种
"什么也不做的开关"。`events` 是订阅，语义不符。`storage` 是"你自己的数据"，而日志就是插件把
自己的一句话交出去，和写自己目录里的文件同一件事。先例是 `pet.badge` 借 `pet.surface`。

## D4 为什么节流，而且复用调用日志那一个

插件最容易写日志的地方是它的轮询循环。同一个 `Throttle` 键（插件 + 等级）5 秒一行，和宿主记
一次调用的规则一致；被合并的次数返回给插件（`swallowed`），它自己可以决定要不要降频。

## D5 为什么没有 error 等级

`internal/logging` 只有三级，多一个会让"等级"这件事出现两套语义（日志里的 ERROR 与诊断报告的
MinLevel 怎么算）。失败用 WARN 表达，那是这套日志里"没成功但程序活着"的定义。
