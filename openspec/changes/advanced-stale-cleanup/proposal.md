# proposal: 清掉「高级」页里已经不对的信息

## 要解决什么

控制中心的「高级」页报的是**已经搬走或退休**的东西，而它读起来像是在报告当前状态：

| 卡片 | 它说什么 | 实际是什么 |
| --- | --- | --- |
| 密钥 | 读 `llm-key.bin`，说"已设置（DPAPI 密文）"；提示"要改密钥，用桌宠那边的设置" | 那个文件是**旧的宿主对话密钥**，只在一次性迁移时被读一次，迁完改名 `.bak`。现在密钥按插件隔离存在 `plugin-data/<id>/secret-*.bin`，编辑入口是「插件」页。"桌宠那边的设置"这个页面已经不存在了 |
| 模型 | 显示宿主 `store.Config` 的 `llmEnabled` / `llmProvider` / `llmBaseUrl` / `llmModel` / `llmDailyBudget` | 这 13 个 `llm*` 字段是**迁移源**：首次启动就搬进对话插件的私有配置了。这一页展示的值几乎永远是"已关闭 / 未填"——而真正在用的那份在插件里 |
| 数据 | `数据 todos.json` | 列表已经搬进待办插件的 `storage`。这个文件只有一次性迁移读 |
| 对话提醒 | "提醒循环在桌宠里，每 30 秒读一次设置" | 宿主的提醒调度器随宿主计时器一起退休了。现在跑循环的是**待办插件的常驻帧**，读的还是同一份 `settings.json` |

一句话：**这些行没有任何一处会让门禁变红，只会让读它的人去找一个不存在的东西。**

## 做什么

1. 删掉「密钥」卡与「模型」卡（页面 + 它们各自的绑定 + 诊断报告里的密钥段）。
2. 「数据」卡的 `todos.json` 一行换成 `plugins\<id>\ 与 plugin-data\<id>\（插件自己写）`。
3. 「对话提醒」的说明改成"这些是待办插件的参数，循环在它的常驻帧里"。
4. 诊断报告的**文件表**同步收窄：`todos.json`、`llm-key.bin` 不再列出，密钥段整段删掉。
   理由是那张表自己的规矩——**列出来的必须是这两个程序还在写的文件**。
5. `Market.HostKey()` 退休（连同 `HostKey` 类型），`docs`/桩/冒烟检查同步。

## 明确不做

- **不动任一提醒开关的语义**：它们写的还是 `settings.json` 的同一批字段，待办插件照旧读。
- **不删 `store.Config` 的 `llm*` 字段**：迁移还要读它们（`internal/plugins/migrate.go` 的
  `legacyConfigKeys`），删了就是让还没升级的人丢配置。
- **不动 `docs/llm-chat.md`**：那一篇记录的正是"宿主自己的对话长什么样"，是历史，不是当前界面。

## 验证

- `tools/plugin-market`：`go test ./...`（诊断报告的三条断言跟着改：退休文件必须**不出现**在
  报告里、密钥段的字面量必须消失）。
- `cc/scripts/render-smoke.mjs`：断言高级页**没有**密钥卡/模型卡的字样，且提醒说明不再提
  "每 30 秒"。
- `node .dev/check-frontend.cjs`：全绿（它读的是宠物页与 cc 的静态接线，含 dev 桩的权限文案）。
