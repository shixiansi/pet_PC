# 提案：把番茄钟的计时循环挪进常驻帧

## 为什么

番茄钟插件（`com.shixiansi.plugin-pomodoro` 2.0.0）现在的计时循环活在一个 iframe 里：
浮层面打开时 `setInterval(tick, 1000)` 在跑，浮层面关掉，那个文档就被销毁，循环随之消失。
状态本身没有丢——`machine.reconcile(state, cfg, now)` 是从**绝对时间戳**反算的，
下次打开时会把落下的阶段补出来（写记录、起下一段），所以"计时器还在走"这个承诺成立。

丢的是**"刚刚这一段结束了"这个事实的及时性**，而它有一个真实的落点：

`timer.phaseEnded` 现在已经没有发射方。它唯一的发射者是宿主的计时器
（`completePhaseLocked` → `notifyPluginPhaseEnded`），宿主计时器整块退休之后，
语音插件（`com.shixiansi.plugin-voice`）那只订阅就永远收不到东西——**「专注时间结束了」
「休息结束了」两句台词不会响**。事件名与 `SubscribableEvents` 暂时保留，
因为删掉会让已安装的语音插件 `events.subscribe` 直接报错，比不响更糟。

## 三条候选路，以及为什么另外两条不行

| 路 | 做法 | 结论 |
|---|---|---|
| a | 接受，由番茄钟插件在阶段结束时弹一句文字气泡（它已有 `pet.bubble`） | **不解决问题**：弹气泡的代码同样要在一个活着的帧里跑。浮层面关着时插件没有脚本在转，它既弹不出气泡，也发不出事实 |
| b | 番茄钟插件用 `plugin.share` 写一个"阶段结束"的时间戳，语音插件的常驻帧轮询它 | **可行，但仍要一个活着的写者**：`share.set` 是插件主动写的，写者不存在时什么都不会发生。这条只有在番茄钟插件**常驻**之后才有意义 |
| c | 新增一条很窄的"插件声明一条事实"方法 + 权限，宿主收到后 fan-out 给订阅者 | 最贵：要动 `AGENTS.md` §3.1 的七处清单，而它解决的是"插件怎么宣布"，不是"插件什么时候有机会宣布"——和 a/b 卡在同一处 |

三条路的共同前提是同一件事：**"阶段结束"必须由一个一直在跑的代码产生**。
宿主不再跑计时器（这是 `todo-pomodoro-as-plugins` 的既定结论，不再回退），
所以那个代码只能是插件自己，而插件现在只在浮层面打开时跑。

## 所以真正要做的

给番茄钟插件一个常驻帧（manifest 的 `background: true`，它已经声明了 `events` 权限，
这正是常驻帧的闸门），让**计时循环活在无界面的那一帧里**，浮层面只当视图。
这样阶段结束会被及时看到：插件写记录、发布事实（路 b）、语音插件轮询到之后就说话。

## 代价，明写在这里

- **两个帧不能同时计时**。浮层面打开时，同一个插件会有两个文档、两个 JS 上下文。
  两个上下文各自 `reconcile` 会把同一段结束翻译成**两条记录**、两次 `share.set`，
  还会各自对 `storage` 里的同一份 JSON 做读-改-写（丢更新）。
  所以必须指定**唯一写者**：常驻帧拥有状态与循环，浮层面变成纯视图 + 一个命令通道。
- 命令通道最省的做法仍是 `plugin.share` 落在**插件自己**的键上（`share.set` 自己的名字
  不需要额外声明）：浮层面写 `command: {op:'start', todoId}`，常驻帧每秒读一次并清空。
  代价是最多 1 秒的操作延迟，与现在的 1 秒 tick 同量级。
- 记录 id 不能再是随机数：两个上下文都可能写下同一条阶段结束。让 id 由
  **阶段结束时刻**派生（如 `rec-<endedAtMs>`），重复写入就是同一个 id，去重而非分叉。
- 插件的前端测试要跟着改：`market/tests/plugin-pomodoro-machine.test.js` 测的是纯状态机，
  不受影响；但浮层面的行为测试要覆盖"我只发命令、不写状态"。

## 不做什么

- 不为它恢复宿主的计时器。宿主一旦重新拥有计时器，"谁是计时器的所有者"就又变成两个答案，
  而 `todo-pomodoro-as-plugins` 存在的理由正是消灭这个二义性。
- 不新增"插件声明事实"的宿主方法（路 c）。等"插件常驻"这件事成立之后，
  一件 `share` + 语音侧轮询已经够用；真到了需要宿主 fan-out 的那天再说，
  那时 `timer.phaseEnded` 这个名字本来也还在。
