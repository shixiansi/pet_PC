# proposal: 插件浮层面的块可以显示/隐藏

## 要解决什么

对话插件的浮层面要做成这样（用户的原话）：

> 默认只出现输入框，不显示上次的会话结果；输入完毕后，问题在上面、回答在下面，显示完毕后把
> 问题替换掉成对话结果，下面继续显示对话框。

这句话里有一个当前架构给不了的动词：**结果区是在对话开始后才"长出来"的**。

现在的规则是：插件在 `manifest.json` 的 `surface` 里**一次性声明**若干矩形，宿主打开浮层面时
按这组矩形裁剪窗口、并在每个矩形里挂一个 iframe。于是：

1. 那个结果区必须**打开时就声明**，否则它不存在；
2. 一旦声明，它**空闲时也在**——视觉上可以透明（画布与帧都已透明），但**点击会被它吞掉**，
   因为 `pointer-events` 挂在父文档的 iframe 元素上，插件改不了自己的帧元素。

Coopanion 不受这个限制，因为它是一个窗口一个文档、窗口随手改大小。我们不行：窗口区域
（`SetWindowRgn`）必须在打开的那一刻确定，而且它是"恰好盖住可见的东西"这条不变量的一部分。

## 做什么

给插件一个**只读自己声明**的能力：请求宿主隐藏 / 显示它已经声明过的某几块。

- 方法：`pet.surface.blocks`，payload `{"hidden": [0]}`（矩形的声明下标）。
- 权限：由**现有的** `pet.surface` 门控，不新增权限——它做的事没有超出"用浮层面"的授权范围。
- 宿主：把隐藏的块从 region 与 layout 的 `rects` 里去掉；页面因此不再为它挂帧（页面按 view 的
  `rects` 建帧），点击自然不会被吞。
- 插件：空闲时 `hidden=[0]`（只留输入胶囊），用户发送时 `hidden=[]`（结果区出现），
  答完仍 `hidden=[]`（结果区显示回答），关闭浮层面时恢复默认。

## 明确不做

- **不接受插件给的坐标或尺寸。** 能提交坐标就等于能把窗口扩到整屏、盖住任务栏，
  那是与"用户授权的是能力，不是屏幕"直接冲突的一类问题。插件只能在自己声明的块之间选择
  显示哪些，几何仍由清单与宿主决定。
- 不新增权限（见上）。
- 不做"运行中改清单声明"。声明仍是编译期固定的集合，变的是**可见性**。

## 影响的不变量

`AGENTS.md §3.2` 的"三选一"（面板 / 气泡 / 浮层面同一时刻只有一个可见）**不变**：这里变的是
浮层面内部有几块可见，不是谁占用那个槽位。

但有一处需要补：区域现在要能按"块集合的子集"重算，`verify-plugin-surface` 要加一条断言——
**被隐藏的块不得出现在 region 里**（否则它会继续吞点击，这个能力的全部意义就没了）。

## 验证计划

- Go：`computePluginSurface` 跳过 hidden 下标；`pluginSurfaceGeometry` 的 region 不含被隐藏的
  矩形；隐藏后 `rects` 的下标仍保留声明序号（页面靠 `Index` 认领自己的块）。
- 门禁：`verify-plugin-surface.ps1` 增加"隐藏块不在 region 里"的检查。
- 插件（market/，独立仓库）：`idle → hidden=[0]`、`send → hidden=[]` 的 vitest 用例；
  真机确认空闲时结果区那一带**点得到桌面**。

## 顺序

1. 宿主：方法 + surface 状态 + region/layout 重算（Go 测试在这里落地）。
2. 插件：三段状态机（idle / 问答中 / 答完），调用上面的方法。
3. 真机 + 门禁复跑；`AGENTS.md §3.2` 补一句"块可见性可请求，几何不可请求"。
