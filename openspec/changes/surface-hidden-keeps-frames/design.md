# design: 隐藏＝不进区域、不销毁文档

## 1. 数据的形状

`PluginSurfaceRect` 多一个字段：

```go
Hidden bool `json:"hidden"`
```

- `computePluginSurfaceSized` 里，`hidden[i]` 的块**照常算几何、照常进 `view.Rects`**，只是
  **不 append 到 `regions`**。
- 于是 `regions` 和 `view.Rects` 的下标**不再一一对应**（隐藏块只出现在后者里）。原来那条
  "regions 与 view.Rects 同序追加，所以 index k 同时指两处" 的注释已经不成立，改成一个
  `regionOf[k]` 的影子数组（-1 表示该块没有区域），长高那条路径用它取真正的矩形。
- 全隐藏 ⇒ `regions` 为空 ⇒ 沿用既有的 `(nil, nil)`：没有可裁的区域，就没有浮层面。
  "把每一块都藏起来"和"关掉浮层面"是同一件事，不该产生一个页面没地方摆的 layout。
- 长高（`sizes`）跳过隐藏块：没有区域可长，接受请求只会让页面把一个帧摆到窗口没裁的地方去。

## 2. 帧的对应关系：声明下标，不是位置

`PluginHost.surfaceFrames` 从数组变成 `Map<index, PluginFrame>`：

- 建帧时 `rectIndex: index`（`rect.index ?? 位置`），键与值用同一个下标；
- 重建条件从 `surfaceFrames.length !== rects.length` 改成**键集合**比较
  （`size` 相等且每个下标都在）——这样"隐藏了一块"不会看起来像"浮层面换了"；
- 隐藏块的元素样式：`visibility: hidden` + `pointer-events: none` + `dataset.hidden = '1'`。

用 `visibility` 而不是 `display: none`：`display: none` 的 iframe 视口会塌成 0，文档在
重新显示的那一刻要整篇重排（滚动过的消息列表也会丢掉位置）。`visibility` 保留布局，
隐藏/显示是单帧开销。这两种都不会卸载文档，所以"帧还活着"成立。

`dataset.hidden` 不是装饰：DOM dump 和真机排查都要能一眼看出"这块是被隐藏的"，
而不是"这块没渲染出来"。

## 3. 插件侧：三个状态，两次切换

`surface.blocks` 的 payload 是**整个隐藏集合**，不是"把我这块切一下"。三块是三个文档，
谁都能调，于是最容易写出的版本是"每块自己决定自己"——而那样 A 帧的请求会把 B 帧刚写进去的
意见覆盖掉，两块在一瞬间不同步，就会有一块凭空消失。

所以约定是：**每个调用者都必须能算出同一个集合**。用户要的流程正好是三个状态：

| 状态 | 看到什么 | 隐藏集 | 谁切 |
|---|---|---|---|
| 空闲、没有可读的回答 | 只有输入框 | `[0,1]` | 内容帧，读回转写后 |
| 空闲、上一条回答还在 | 回答气泡 + 输入框 | `[0]` | 内容帧，读回转写后；以及回答框**打完之后** |
| 提问中 | 提问条 + 回答气泡 + 输入框 | `[]` | 内容帧，在本轮第一条 `llm.*` 时 |

**收提问条的时机是"回答显示完 + 1 秒"，不是 `llm.done`。** 这里连着踩了两次：

1. 第一版在 `done` 就收。`done` 只说明传输结束，而回答框还在按 1 字 / 50ms 打字，
   于是提问条在回答还没显示完时就消失了——正好相反，那几秒里提问条还是"这段话在回答什么"
   的唯一上下文。
2. 第二版改成打完最后一个字就收。用户说"消失得太快"，于是加了 **1 秒宽限**
   （`END_DELAY_MS`）：这一秒里问题与它的回答并排存在，一轮对话读起来是一问一答，
   而不是"答完就闪走"。定时器会被下一轮取消（`noteExchange` 里 `cancelEndTimer`），
   否则上一轮的收尾会把刚开始的新问题的提问条收掉。

具体：

- `done` 到达时若打字队列还非空 → 置 `endWhenDrained`，由打字机的排空分支调用
  `endExchange()`（只有回答框有这个能力，它是唯一知道"显示完了"的帧）；
- 队列已空（非流式回答）→ `done` 当场进 1 秒宽限；
- `llm.error` 例外：错误行一贴上去就算结束，没有东西要打字，同样有 1 秒宽限。

同一个教训在 1.5.x 的存储侧出现过镜像版本：写转写要等打字机，而"只收到 `done`"的回答
永远等不到回调，于是这一轮根本没落盘。三个 bug 是同一个错误——把"显示完了"和"请求结束了"
当成同一个事件；现在三处都分开了（落盘在 `done`、收提问条在显示完 + 1 秒）。

## 3.1 回答文本两端去空白

模型经常以 `\n\n` 开头，而回答框是 `white-space: pre-wrap`，所以那是真的两行空行：
真机上量到 90px 气泡里有 40px 空带。所以显示端**跳过前导空白**（逐字渲染时，节点还是空的就丢掉
空白字符，这样流式和一次性两种到达方式都治），并在 `done` 处对权威全文 `trim`，落盘的也是修好的
那份。中间的段落空行不动——那是模型的排版，不是噪声。

`[]` 由谁发都一样（内容帧由事件得知），`[0]` 也是纯状态（`asking=false`），所以重复调用幂等。
三个变量是每帧自己的，但三帧从同一批事件到达同样的值：

- `asking`：新的 requestId 的第一条事件 → true；回答**显示完** / `error` → false。发送帧
  **不置**它——发送那一刻没有任何东西可以发（见下）。
- `hasAnswer`：**粘性**。`init` 时从转写里读出来（有没有 assistant 条目），之后 `done`/`error`
  一律置 true。粘性很关键——它让"回答已存在"这个判断不依赖哪一帧的转写副本更新得快：
  `done` 时发送帧刚写完转写，而另外两帧的副本还是旧的，若按副本判断，它们会把回答气泡藏掉。
- 一轮对话进行到一半时**不再切换**：区域每动一次就是一次 `SetWindowRgn` + 一次布局推送，
  而"最新一行"是靠回答气泡自己滚动，不需要改区域。

**发送那一刻不发任何请求。** 输入框是另一个文档，它没法把问题画进提问条；提前把提问条显示出来，
只会闪一下它上一轮留下的旧问题（那一次读盘要几十毫秒到第一个分片之间）。所以两个内容盒子一起
在第一个分片到达时出现——那一刻提问条正好也读回了自己的新文本。

提问条自身的渲染也跟着 `asking` 走：`asking` 为假时它**不画**上一句（否则下一次提问时，
在转写读回来之前会闪一下旧问题）。

## 4. 与"常显"的关系

1.6.0 的 `design.md` §5 写着"三块常显，一次 `surface.blocks` 都不调"，理由是"隐藏会重建全部帧"。
这一条**已经不成立**（本变更就是修它），所以那一段的效果被本变更取代：现在空闲时只显示
输入框，提问期间三块都在，答完提问条收起。

## 4.1 同轮一起调整的两处版式

- 提问条 **48 → 40px**、文字**垂直居中**：一句话占 48px 且贴顶，像是"没画完的盒子"。
  40 - 8（上下 padding）= 32，正好两行 16px，所以那两行是盒子的真实容量，不是接近它的数字。
- 回答气泡**改为顶部对齐**（原来是 `justify-content: flex-end`）：短回答贴在气泡底边、
  上面留一条空白，读起来像渲染失败。改成顶部对齐后，长回答改为在气泡内滚动
  （`overflow-y: auto` + 隐藏滚动条 + 逐字滚动到最新一行），流式时仍然看得到"正在打"。

## 4.2 回答框的高度也是算出来的

用户的原话是"不能不固定回答框，而是根据回答撑长或缩小高度"。做法：

- manifest 只给**下限 56**（两行，再小尾巴 + 圆角就吃掉整个盒子）和**上限 152**（宠物上方
  160px 减 8px 余量）；
- 插件量**行元素**的 `getBoundingClientRect().height`（不是滚动容器的 `scrollHeight`：盒子偏高时
  后者只回报盒子自身，短回答就永远缩不回来），加 20px 的 chrome（6 上 + 14 下，其中 10 是尾巴带），
  夹进 [56, 152]，通过 `surface.blocks {sizes:{1:h}}` 申请；宿主向上长高、底边不动，所以尖角
  一直压在宠物头顶；
- 流式中每 4 个打字 tick（~200ms）量一次，队列排空后再量一次（权威全文可能更长或更短）；
- **`surface.blocks` 只有一个调用者**（回答框）。payload 会整份替换隐藏集和尺寸表，所以提问条
  或输入框发一次就会把高度打回下限——这是"每帧各算各的"那个设计被推翻的原因；
- **提问条与回答共用宠物头顶那 160px**：回答 > 100 时提问条让位（回答是用户正在读的东西），
  回答回到 ≤ 100（下一轮短问答）时它再回来。所以"1 秒宽限"只适用于两者能并存的那些轮次。

iframe 的尺寸变化不会产生新的 `init`，只有一次 `resize`，所以气泡的 SVG 路径改用
`window.innerHeight` 并按 `resize` 重画——否则尾巴会留在旧高度上。

## 5. 遗留

- 隐藏/显示仍然会触发一次 `SetWindowRgn` 与一次 layout 推送（`applySurfaceBlocksThrottled`
  有 500ms 地板，两次调用会被合并）。每轮对话最多两次，不再是每字符一次。
- 插件之间没有通道这件事没有变：提问条仍然靠读一次转写知道自己该画什么。
