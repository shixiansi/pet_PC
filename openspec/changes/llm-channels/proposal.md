# proposal: 模型渠道（`llm.chat` 的 `provider` + `llm.providers`）

## 现状（已实读代码确认）

"模型配置一处、全局生效"这件事**已经成立**，而且不需要插件互相调用：

- 一个插件在 manifest 里声明 `"shareLLM": true`，别的插件申请 `llm.borrow` 就能用它的端点与密钥
  （`resolvePluginChatCredential`：**自己配置优先，否则借**；密钥只在宿主进程里）；
- 借出方的配置**每次调用现读**，所以改模型/地址，下一次请求就换。

但它有一个说不过去的缺口：**`findLLMLender` 是"按 id 排序取第一个就绪的借出方"**。那是为了
让答案不依赖安装顺序，**不是一条策略**。于是：

- 用户同时有 OpenAI 和本机 Ollama 两个渠道时，不能指定某个群用哪一个；
- 没有任何办法列出"现在有哪些渠道、默认是哪个"（`llm.profile` 只说"我这次会用谁"）；
- 换渠道只能靠删/停插件——而停掉一个渠道会让别的借用者一起断。

## 方案

两处很小的宿主改动，都在 `llm.borrow` 这一份同意之内：

| 改动 | 形状 |
| --- | --- |
| `llm.chat` 增加可选 `provider` | 值是**提供方插件的 id**。点名之后就用它，**不回退**到默认渠道 |
| 新方法 `llm.providers` | `{providers:[{id,name,model,ready,self}], default, own}` |

配合一个**纯渠道插件**（`com.shixiansi.plugin-llmchannel`）：它只保存一套连接（预设/地址/模型/密钥），
自己从不对话。想同时用两个端点，就装两个它、填不同的渠道。

## 三条硬规则

1. **点名不等于扩大授权。** `provider` 仍然要求 `llm.borrow`，被点名的插件仍然必须已安装、已启用、
   已配置、声明了 `shareLLM`。用户当初同意的是"用别的插件配置好的模型"，选哪一个属于这句话内部。
2. **点名失败就失败，不回退。** 否则"成功了，但花的是另一个账号"会变成一个事后查不出来的现象。
3. **列表里没有端点、没有密钥。** 这与 `llm.profile` 已经画好的线一致：你知道"用谁的配置"，不知道
   "它连哪儿、什么钥匙"。

## 非目标

- **不做插件间的 provider 注册表**（那是 DSH 那种 `ctx.llm.registerAdapter` 的形状）。PetPC 的插件是
  沙箱文档，注册不进宿主；渠道只能是"声明 + 宿主解析"。
- 不做负载均衡、故障转移、按价格路由。
- 不为渠道单独加权限（理由见上）。
- 不定义"每个渠道下有哪些模型名"：模型名仍然是一个字段 + 每次调用的 `model` 覆盖；一个渠道插件要
  提示可选项，用它自己的 `select` 配置项即可。

---

## 第二步（同一轮追加）：渠道表与密钥库

`provider` + `llm.providers` 只解决"多个**插件**各一个端点"。用户的真实要求更近一层：**一个插件里
多个渠道、每个渠道多个模型、每个渠道多个密钥**。manifest 的 `config` 做不到（一个 `llmBaseUrl`、
一个 secret、而且 `ConfigStore` 明确拒绝未声明的键），所以：

- `llm.channels.get` / `llm.channels.set`（挂 `llm.chat`）：表存在插件私有目录的
  `llm-channels.json`，**两个宿主都服务**（编辑界面在控制中心，那里没有模型调用）；
- 每个 key 的明文由宿主用 DPAPI 加密，一个 key 一个文件（`llm-key-<渠道>-<key>.bin`），
  **读接口只回 `{set, mask}`**；
- `llm.chat` 增加 `channel` 与 `keyId`，解析顺序变成：自己的表 → 自己的 config → 借（有表的
  借出方优先按"就绪"判断，表里的地址同样要过 **该插件**的 netHosts 白名单）；
- 插件 `com.shixiansi.plugin-llmchannel` 0.2.0 的**设置界面就是编辑器**：渠道卡片、模型列表、
  密钥行（掩码显示、换 key 只写不读），保存时自动把新地址补进 `hostWhitelist`。

为什么不让插件自己发请求（那样它就"什么都能存"）：`net.fetch` 是**非流式**的，而对话插件的
打字机效果、以及"一次请求一次预算"的记账都在宿主的 `llm.chat` 里。让渠道插件自己说话，等于把
流式、预算、密钥边界一起搬进插件。
