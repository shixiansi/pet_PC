# proposal: 对话入口改成「悬停出现的按钮」

## 要解决什么

用户的原话：

> 现在添加鼠标悬浮显示对话按钮，点击后显示对话框，而不是现在的双击显示。

现状（2026-10 之前）是：**双击桌宠**打开对话插件的浮层面。这条路径有两个代价：

1. **双击是不可见的手势。** 没有任何提示告诉用户"双击这只猫"，新用户唯一的发现途径是
   README 或别人的口述；而点错了什么都不会发生，看起来像"桌宠不响应"。
2. **它让每一次单击都变慢。** 因为"两击"必须先押住一击才不会退化成"开→关→开"，
   `pointerup` 里的单击要 `setTimeout(200ms)` 才生效（`DOUBLE_CLICK_MS`）。用户点一下
   想开面板，永远等 200ms —— 这个延迟是为双击付的，而双击本身是个多数人不会用的手势。

## 做什么

把入口换成一个**看得见的按钮**：

- 鼠标停在宠物上时，宠物**左上角**浮出一个小圆按钮（对话气泡图标），移开就消失；
- 点它 → `App.OpenChatPluginSurface()`（就是双击原来调的那个绑定，一行不变）；
- 单击桌宠回到「按下即生效」：`pendingClick` / `lastClickAt` / `DOUBLE_CLICK_MS` 与那段
  双击裁决整体删除。

番茄钟在等回答（写总结 / 写计划 / 选待办）时的老规则**保留**：点按钮不顶掉气泡，而是把光标
送进那个输入框（`focusAnswer`）。

## 明确不做

- **不做浮在宠物外面的按钮。** 浮层面与气泡都不在时，窗口区域恰好等于宠物那一块矩形
  （`AGENTS.md §3.2`）。框外的按钮会被原生区域切掉；把区域放大来容它，就会在宠物旁留下
  一条页面从不绘制、却会吞掉桌面点击的窗口。按钮放在**宠物框之内**，这件事就与 Go 的几何
  完全无关，也不用为"悬停"跑一次往返（悬停时让 Go 改区域 → 按钮在区域到达前不可点）。
- **不给按钮加缩放 / 位移动画。** `transform` 会让像素在过渡中途伸出裁剪框。
- **不改 `OpenChatPluginSurface` 的任何语义**（槽位解析、提问待答时拒绝、没有插件时用气泡说明），
  这次只换"谁来触发它"。
- 不改面板的「对话」tab：它仍然是完整记录。

## 影响的不变量

- `AGENTS.md §3.2`「窗口区域恰好覆盖可见的那一个」**不变**：按钮是宠物框内的页面元素，
  区域仍是宠物矩形，Go 一行未改。
- 新增一条页面侧的约束（写进 `style.css` 的注释）：隐藏必须是
  `visibility: hidden` + `pointer-events: none`，否则透明按钮仍然吃点击，宠物左上角会变成
  "打开对话"而不再是"打开面板"。
- 守护这条行为的检查同步改：`.dev/check-frontend.cjs` 的第 6 节（原来是"双击在指针流里裁决"）、
  `.dev/run-frontend-harness.cjs` 的前三个场景、`frontend/src/bubble-plan.test.js` 的双击助手。

## 验证计划

- `frontend/src/pet-chat-button.test.js`（新增）：按钮是 `#pet` 的子元素、未悬停时
  `visibility:hidden` + `pointer-events:none`、`#pet:hover` 才放出来、面板开着时不显示；
  点它只调一次 `OpenChatPluginSurface`、不调 `TogglePanel`、也不启动拖动；单击桌宠**立即**
  `TogglePanel`；`main.js` 里不再有 `DOUBLE_CLICK_MS` / `pendingClick` / `lastClickAt`。
- `frontend/src/bubble-plan.test.js`：把"双击 → 光标进输入框"改成"点按钮 → 光标进输入框"。
- `.dev/check-frontend.cjs`：第 6 节改成按钮的接线与 CSS 断言（含"按钮在 `#pet` 里"）。
- `.dev/run-frontend-harness.cjs`：真浏览器里断言单击立即生效、按钮实测 `visibility:hidden`、
  点按钮开浮层面、提问待答时点按钮被拒。
- 真机：悬停宠物 → 左上角出现按钮 → 点它弹浮层面；移开鼠标按钮消失，那个位置点下去仍是开关面板。
