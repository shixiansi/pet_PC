# design: 一个文件、一次写入、一个快照

## 存储形状

```
<插件私有目录>/
  memory.md                      ← 模型读的那份
  memory-history/
    2026-03-04T14-32-08.md       ← 每次追加之前的那一版
    2026-03-04T14-32-08-2.md     ← 同一秒里的第二次（模型一个回合内调两次工具是正常的）
```

时间戳到秒，同秒用数字后缀，因为**覆盖同名快照等于丢掉用户最想看的那一版**。

## 追加而不是改写

`AppendMemory` 把一条压缩成一行（`strings.Fields` 收掉所有空白）。

这不只是排版偏好：一条带换行的输入可以伪造后面那行的 `日期  正文` 头，
让模型能写出一条**回溯日期**的假记录。压成一行就断了这条路。

## 上限的三个数

| 上限 | 值 | 依据 |
| --- | --- | --- |
| 整份文档 | 8 KiB | 约 2000 个汉字：够记一个人的固定事实，又小到每次请求都塞得下 |
| 单条 | 500 字 | 让"一个回合填满整份文件"不可能 |
| 历史版本 | 20 | 够看出"从周二开始说胡话"，同时有界 |

满了返回错误而不是截断——丢掉用户教过的东西而不说，是这个功能能做的最坏的事。

## 快照失败就放弃这次追加

快照写不进去时不继续：那样会得到一份没有历史可回的文档，而用户以为还有。

## 与工具调用的接口

两个方法都返回**整份文档**而不是 `{ok:true}`。模型下一轮要看到的就是这份文档，
把手上已有的东西递回去，省掉一次只为读回它的往返。

## 注入方式（明确不做自动注入）

宿主**不**把记忆拼进 system prompt。理由与工具目录一致：措辞是插件的事。
插件的提示里写"先调 memory_read"，宿主只保证这个调用在权限内可用。

代价是依赖模型记得去读——但自动注入的代价是每次请求都付这份 token，
而多数对话并不需要记忆。插件可以按自己的判断选择后者。
