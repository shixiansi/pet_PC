# proposal.md — bilibili-plugin（初版需求 v0.1，待确认）

> 一句话：新增一个**常驻后台**的 B 站插件 —— 按你指定的分区/偏好自己去刷视频，把字幕拉下来让大模型
> 摘一遍，觉得「对你有用」才叫桌宠弹一句并把卡片放进收件箱；人设、条数、频率、是否评论都由你设，
> 评论默认**只出草稿、不自动发**。

**这份文件是需求，不是设计。** 状态：**初版，等你过目**。§13 列了 8 个要你点头的决策点，
每个都带推荐默认值；你确认（或直接说「按推荐来」）之后我再写 `design.md`（技术方案）与 `tasks.md`（执行清单）。

**宿主假设**：目标是本仓 **PetPC 桌宠**的插件机制（manifest + 沙箱 iframe + `PluginRequest` 能力表），
不是 `E:\lagrangeV2\xunlu-core` 的 Node 插件 —— 那个仓这次只作为 **B 站接口与登录流程的参考实现**
（`src/plugins/bilibili/model/{Bapi.js,Bilili.js,Blogin.js,biliutils/*}`）。若你要的其实是 xunlu-core 的 JS 插件，
需求主体（§4）不变，§6/§7 换成 Node 侧实现，告诉我我改。

## 1. 要解决的事

桌宠现在会说话、会记待办，但它不知道你**平时在 B 站上看什么**。你要的是：

| 你要的 | 现在为什么做不到 |
|---|---|
| 自己按分类去刷（不是等你喂链接） | 现有插件要么只在面板里等人说话（对话插件），要么只连 QQ（QQ 插件）；没有「自己去逛」的插件 |
| 刷完**看懂内容**再决定值不值得看 | 视频内容在字幕里，字幕不在页面上，要三步接口（`view` → `player/wbi/v2` → 下载字幕 JSON） |
| 用**你的人设**说话，不是通用 AI 腔 | 人设属于插件自己的提示词，宿主不提供 |
| 觉得有用才**发给主人**，别刷屏 | 需要「打分 + 阈值 + 去重 + 时段 + 每日上限」四道闸 |
| 说清**刷多少条**、偏好什么、要不要**评论** | 全是插件自己的配置，宿主没有这些概念 |

一句话：**发现（browse）→ 理解（subtitle）→ 判断（score）→ 汇报（push）→ 可选互动（comment）**。

## 2. 用户故事

1. 我是主人。我在工坊里勾了「知识 / 科技 / 影视」，写了「只看 10 分钟以上的、别推手游和明星八卦」，
   人设是「话少、只讲事实、不许吹」。第二天早上桌宠弹了一句「昨晚刷到 3 条，1 条你可能真想看」。
2. 我是主人。我点开工坊的收件箱，看到那条视频的标题、UP、时长、**摘要三行**和「为什么推给你」，
   下面挂着一条**评论草稿**，我改两个字点「发送」，插件用我的账号发出去。
3. 我是主人。我在工坊的「单条调试」里粘一个 BV 号，点「跑一遍」，它把 cid、字幕轨数、字幕段数、
   摘要、分数全列出来 —— **不推送、不评论**，我只想看看它到底怎么想的。
4. 我是主人。我关掉插件开关，桌宠进程里连一个请求都不再发出，也不再有气泡。
5. 我是主人。我不想让它评论。评论开关关着时，它一条 POST 都不会发。

## 3. 范围与名词

| 名词 | 含义 |
|---|---|
| **一轮（round）** | 一次「取候选 → 筛到 N 条 → 逐条总结 → 判定 → 推送」，N = 每轮条数 |
| **候选池** | 从分区接口一次取回的 20–40 条，经本地规则筛出 N 条 |
| **字幕** | B 站 CC 字幕或 AI 字幕（`subtitle_url` 指向的 JSON），**不是**弹幕 |
| **摘要** | 模型对字幕内容的结构化压缩：3–6 句 + 3 个要点 + 为什么值得看 |
| **有用分** | 0–100，由模型按「主人偏好 + 人设」打分，阈值以上才推送 |
| **收件箱** | 插件私有存储里的卡片列表，工坊里可翻页/查看/删除；气泡只是它的「有新信」提示 |

**只读不搬**：不下载音视频流、不转存、不二次分发；字幕原文**不落盘**（只在内存里压缩，见 §4.5）。

## 4. 功能需求

### FR-1 配置（全部由插件自己持有）

配置分四组，落在 manifest `config[]` 里（市场「设置」弹窗编辑）：
**① 刷什么 ② 怎么说 ③ 刷多少 ④ 要不要评论**。完整键值表见 §5。

- 配置改完**立即生效**：下一轮按新配置取候选；正在跑的一轮不打断。
- 配置里没有任何「宿主级」开关；插件停用 = 全部停止（见 FR-8）。

### FR-2 刷视频：候选从哪来、怎么筛

**来源（可多选，一轮内按配置顺序取，去重后进候选池）**

| 来源 | 接口 | 登录 | 备注 |
|---|---|---|---|
| 分区排行榜 | `GET /x/web-interface/ranking/v2?rid={rid}&type=all` | 否 | 默认来源；一个分区一次约 100 条 |
| 分区最新投稿 | `GET /x/web-interface/dynamic/region?rid={rid}&pn=1&ps=20` | 否 | 时效性来源；部分时段会要 wbi 签名 |
| 关键词搜索 | `GET /x/web-interface/wbi/search/type?...&search_type=video` | 否（需 wbi） | 偏好关键词命中 |
| 指定 UP 主最新 | `GET /x/space/wbi/arc/search?mid={mid}&pn=1&ps=10` | 否（需 wbi） | UP 白名单 |

分区 rid 常用值（工坊做成勾选清单，并允许手填数字）：

| 分区 | rid | 分区 | rid | 分区 | rid |
|---|---|---|---|---|---|
| 动画 | 1 | 游戏 | 4 | 知识 | 36 |
| 科技 | 188 | 生活 | 160 | 美食 | 211 |
| 音乐 | 3 | 影视 | 181 | 鬼畜 | 119 |
| 舞蹈 | 129 | 运动 | 234 | 资讯 | 202 |

**本地初筛（不花钱、不发请求，只是过滤）**

1. 已看过：`seen` 里有该 bvid（默认 30 天内不重复），或最近 N 天推过 → 跳过。
2. UP 黑名单（mid 或名字，逗号分隔）→ 跳过；UP 白名单非空时只留白名单。
3. 时长：`minDurationSec` ≤ 时长 ≤ `maxDurationSec`（默认 60–1800s）。太短没内容、太长烧钱。
4. 播放量：`minPlay`（默认 10000；可设 0 关掉）。
5. 标题关键词：命中 `keywordsExclude` 任一 → 跳过；`keywordsInclude` 非空时必须命中一条。
6. 主人自己的视频（`ownerUID` 命中 `owner.mid`）→ 默认跳过（避免自己给自己评论）。

筛完仍多于 N 条时按「发布时间新 → 播放量高」排序取 N（可配 `sortBy`）。

### FR-3 取字幕：三步接口 + wbi 签名

严格按你给的三步走，**任何一步失败都不静默**（进日志、进收件箱的「跳过原因」）：

```
① GET /x/web-interface/view?bvid={BV}
     → data.aid / data.cid / data.pages[] / data.title / data.desc
       data.owner.mid,name · data.duration · data.stat.view · data.tname
     多 P 视频默认只取第 1 P（pages[0].cid），配置 pageMode = first（默认）| longest

② GET /x/player/wbi/v2?bvid={BV}&cid={cid}&w_rid={md5}&wts={ts}
     → data.subtitle.subtitles[] = [{ lan, lan_doc, subtitle_url, ai_type }]
     选轨顺序：zh-CN → zh-Hans → ai-zh → 其它中文 → 第一条
     wbi 签名：/x/web-interface/nav 取 img_key/sub_key（缓存 30 分钟）→ mixinKey → md5(query + key)
               SubtleCrypto 没有 MD5，插件自带一份（照搬 Bwbi.cjs 的 64 项混淆表）
     ⚠️ **真机实测（v0.1 定稿后）**：匿名请求这一步返回 `subtitles: []`，20 条视频 20 条如此，
        原先文档里的 `need_login_subtitle` 字段**已经不在返回里**（见 §11 第一行的实测记录）。
        即：**要字幕就得登录**。未登录时第②步必然空，插件走降级（§4.4）并在卡片上写明原因。

③ GET {subtitle_url}     ← 常以 // 开头，补 https:
     → body[] = [{ from, to, content }]
```

**降级**：没有字幕轨时（未登录是最常见的原因，见上面的实测）

| 选项 | 行为 | 默认 |
|---|---|---|
| `desc` | 用「标题 + 简介 + 标签（`view/detail/tag`）+ 热评前 5」拼素材，标注「**非字幕**摘要」 | ✅ |
| `skip` | 直接跳过并记一条「无字幕」 | |

> 不做的降级：**不下载音频做 ASR**（几十 MB + 本地模型/云端付费，见 §10）。

### FR-4 从字幕到摘要：必须在 4000 字以内分段

**硬约束**：宿主的 `llm.chat` 单条 user 文本上限 **4000 字**（`app_plugins.go:1402`，system 也是 4000）。
一条 20 分钟视频的字幕轻松 5000–15000 字，**一次调用装不下**，所以：

```
字幕 body[]（from/to/content）
  │ 本地清洗：合并 400ms 内的碎片、去掉 [音乐][掌声] 之类标记、连续重复句去重
  ▼
按时间切块（默认 180s/块，块尾句不切断）
  │
  ├─ 全文 ≤ 3500 字（短片）→ 一次总结（single pass）
  └─ 否则 map-reduce：
       map：每块 → 「≤ 250 字的事实笔记」（块文本 ≤ 3500 字）
       reduce：把 ≤ 8 条笔记 + 标题/UP/时长/简介 → 最终 JSON
  调用次数上限 = summaryMaxCalls（默认 4），超了就只取前 N 块并在卡片上标注「只读了前半段」
```

**最终一次调用要求模型输出严格 JSON**（解析失败 → 重试一次 → 再失败就降级成纯文本摘要 + 分数 0，不推送）：

```json
{
  "summary": "3–6 句，说清这条视频讲了什么、结论是什么",
  "points": ["3 条要点，每条 ≤ 30 字"],
  "useful": true,
  "score": 82,
  "why": "为什么对主人有用（≤ 40 字，第一人称）",
  "tags": ["AI", "工具"],
  "comment": "可选：一句 ≤ 60 字的评论草稿，必须引用视频里的具体细节"
}
```

**人设怎么用**：`persona` 进 system 提示词，管**语气**（摘要与推送那句话怎么说）；
`preferences`（偏好文本）进 system 提示词，管**判断标准**（什么算有用）。
两者分开配，因为「话怎么说」和「什么值得看」是两件事（§13-Q6）。

### FR-5 有用性判定（四道闸，任一不过就不打扰你）

1. `score ≥ pushThreshold`（默认 70）。
2. `useful === true`。
3. 当日推送条数 < `pushDailyCap`（默认 5）。
4. 当前时间在 `activeHours` 内（默认 `09:00-23:00`）；不在时段内只入收件箱、不弹气泡。

在时段内也做**错峰**：同一轮最多弹 1 次气泡（其余静默入箱），两轮之间至少 `minPushGapMin`（默认 90 分钟）。

### FR-6 发给主人：气泡 + 收件箱

宿主只给了 `bubble.say`（一句话，替换式）和插件自己的存储，所以「发给主人」= 两条腿：

| 通道 | 内容 | 约束 |
|---|---|---|
| 桌宠气泡 | 人设语气的一句话（≤ 40 字，如「刷到一条讲你做的那件事的，可能有坑」） | `bubble.say` 是**替换式**的提醒气泡，会被下一条覆盖；不做长文 |
| 工坊收件箱 | 卡片：封面（`pic`）、标题、UP、时长、播放、分区、摘要、3 条要点、有用分、`why`、BV 号、链接（可复制） | 保留最近 `inboxKeep`（默认 200）条；可单条删除、可清空 |

**不在 v1 做**：Windows 系统通知、B 站私信、邮件、QQ 转发（都不是插件已有的能力，见 §7）。

### FR-7 评论：默认关，默认只出草稿

这是**唯一会以你的账号对外发言**的功能，所以设计得最保守：

| 关卡 | 规则 |
|---|---|
| 总开关 | `commentEnabled` 默认 **false**；关闭时**一条 POST 都不发**（验收项） |
| 模式 | `commentMode`：`draft`（默认，只写草稿等你点发送）/ `auto`（自动发） |
| 门槛 | `score ≥ commentMinScore`（默认 85）且评论草稿非空且引用了具体细节（正则要求出现片名/人名/数字之一） |
| 频率 | 每日 ≤ `commentMaxPerDay`（默认 2），两次间隔 ≥ `commentCooldownMin`（默认 30 分钟），同 UP 每天 ≤ 1 条 |
| 范围 | 只评论 `commentRids` 里勾选的分区；UP 黑名单照样生效 |
| 内容 | ≤ 60 字，本地黑名单（广告/引流/联系方式/纯表情）+ 不出现「AI」「作为一个观众」这类自曝句式 |
| 失败 | 412/风控/`-352`/`-509` → 当天自动关掉评论并在工坊红字说明，**不重试** |
| 接口 | `POST /x/v2/reply/add`（form：`oid=aid&type=1&message=…&plat=1&csrf={bili_jct}`，需 Cookie + Referer） |
| 记录 | 发出的评论进收件箱卡片（含评论正文、时间、返回的 rpid），可点击复制链接 |

> **明确不做**：点赞、投币、收藏、发弹幕、关注、私信、转发。这些都是「替你动手」，
> 收益低而风险（账号风控/误操作）高，且你只说了「评论」。

### FR-8 调度与额度

- 插件 `background: true`，在**常驻帧**里跑 `setInterval`；面板/工坊关掉也继续（见 §7 第 3 条）。
- `intervalMinutes`（默认 120）到点跑一轮；`activeHours` 之外不跑。
- 额度（都记在插件私有存储，跨重启有效）：
  - `dailyVideoCap`（默认 12，**含没总结成功的**）
  - `pushDailyCap`（默认 5）
  - `commentMaxPerDay`（默认 2）
  - `summaryMaxCalls`（每片 LLM 调用上限，默认 4）
- 宿主还有一道 `llm.chat` 的**每日请求上限**（对话插件配置里的 `LLMDailyBudget`，默认 200）。
  插件不读它，只在被拒（`已达今日请求上限`）时**当天停止总结**并记一条日志 —— 不撞第二次。
- 插件停用/卸载：常驻帧卸载，定时器随之消失，**不再有任何请求**（验收项）。

### FR-9 工坊界面（在插件市场里，跟 QQ 插件同一个位置）

市场工坊是插件唯一的人看得见的界面（桌宠面板只有一个「对话」槽位，不给别的插件）。

```
┌ 状态条：运行中/已暂停 · 下次 20:40 · 今日 已刷 6/12 · 已推 2/5 · 已评论 0/2 · 模型「借用对话插件」· 账号 已登录(UID) ┐
├ 单条调试： [ BV1xx411c7mD ] [跑一遍]   → ① cid ② 字幕轨 3 条(zh-CN/ai-zh) ③ 412 段 → 摘要 → 82 分（不推送） ┤
├ 收件箱： [卡片] 标题 / UP / 时长 / 摘要三行 / 为什么 / 分数 / [复制链接][评论草稿][删除]  · 分页 20/页          ┤
├ 日志：最近 50 条（取候选 12 → 筛到 3 → 无字幕 1 → 摘要失败 1 → 推送 1）                                        ┤
└ 隐私说明：字幕文本会发送到 <模型端点>；评论只在「自动」模式下才会以你的账号发出。                              ┘
```

界面要求（沿用本仓既有门禁口径）：

- `[hidden]` 权威、不画裁剪框（样式里不许出现 `box-shadow`/`filter`/`transform`）、深浅两套主题（`html[data-theme]`）、
  `?theme=` 首帧生效 + `init.theme` + `theme` 消息三条通道（照 `qq` 插件的做法）。
- 收件箱**分页读**（每次一页），不把 200 条卡片一次塞进 DOM。
- 所有「会让账号发东西」的按钮都是**描边**样式，和「删除」分开摆。

### FR-10 数据、隐私、可清理

| 数据 | 存哪 | 保留 |
|---|---|---|
| 已看过的 bvid | `storage: seen`（JSON） | 30 天 / 最近 2000 条 |
| 收件箱卡片 | `storage: inbox`（JSON，含摘要，不含字幕原文） | 最近 200 条 |
| 额度计数 | `storage: usage`（按日期） | 滚动 7 天 |
| 日志 | `storage: log` | 最近 200 条 |
| Cookie（若登录） | `config: biliCookie`，`secret: true`，加密落盘、只在宿主内使用 | 卸载即删 |

- **字幕原文不落盘**：解析完即丢，只留摘要。
- **日志与错误信息里 Cookie 必须打码**（`SESSDATA=***`），凭据不进日志、不进气泡。
- 工坊提供「清除已看记录 / 清空收件箱 / 清空日志」三个按钮。

## 5. 配置项清单（manifest `config[]`）

> 全部是插件自己的设置；`secret: true` 的项走宿主的加密存储，插件只能看到 `{set, mask}`。

### ① 刷什么

| key | label | type | 默认 | 说明 |
|---|---|---|---|---|
| `rids` | 分区（可多选） | **select·多选** | `36,188,181` | 选项是「知识/科技/影视/动画/游戏…」这些名字，不是一串 rid 数字 |
| `source` | 来源（可多选） | **select·多选** | `ranking` | 选项是「分区排行榜/分区最新投稿/关键词搜索/指定 UP 主」 |
| `keywordsInclude` | 必须包含的关键词 | text | `` | 逗号分隔，留空=不限 |
| `keywordsExclude` | 排除关键词 | text | `手游,明星,吃瓜` | 逗号分隔 |
| `upWhitelist` | UP 白名单（mid，逗号分隔） | text | `` | 留空=不限 |
| `upBlacklist` | UP 黑名单（mid，逗号分隔） | text | `` | |
| `minDurationSec` | 最短时长（秒） | number | `60` | |
| `maxDurationSec` | 最长时长（秒） | number | `1800` | 控制成本的主要旋钮 |
| `minPlay` | 最低播放量 | number | `10000` | 0=不限 |

### ② 怎么说

| key | label | type | 默认 | 说明 |
|---|---|---|---|---|
| `persona` | 人设（说话的语气与人称） | text | 见默认值 | ≤ 2000 字，进 system 提示词 |
| `preferences` | 偏好（什么算对你有用） | text | `` | ≤ 2000 字，进 system 提示词 |
| `summaryLength` | 摘要长度 | **select** | `medium` | 短 / 中 / 长 |
| `pushThreshold` | 有用分阈值（0–100） | number | `70` | |
| `llmModel` | 模型（留空=用对话插件的） | text | `` | 可单独指定更便宜的模型 |
| `llmBaseUrl` | 接口地址（留空=借用） | text | `` | |
| `llmApiKey` | API Key（留空=借用） | secret | — | 走 `secret: true` |

### ③ 刷多少

| key | label | type | 默认 | 说明 |
|---|---|---|---|---|
| `enabled` | 自动刷（关掉=只保留手动「单条调试」） | bool | `false` | 装上默认**不开**，先让你调配置 |
| `perRound` | 每轮刷几条 | number | `3` | 1–10 |
| `intervalMinutes` | 每轮间隔（分钟） | number | `120` | 30–720 |

| `dailyVideoCap` | 每日最多总结几条 | number | `12` | |
| `pushDailyCap` | 每日最多打扰几次 | number | `5` | |
| `minPushGapMin` | 两次推送最小间隔（分钟） | number | `90` | |
| `summaryMaxCalls` | 每条视频最多调用几次模型 | number | `4` | 1–8 |

### ④ 主人与评论

| key | label | type | 默认 | 说明 |
|---|---|---|---|---|
| `ownerUID` | 主人的 B 站 UID（数字） | text | `` | 用于排除自己的视频、显示「这是你的」 |
| `biliCookie` | B 站登录凭据（SESSDATA 等，加密保存） | secret | — | 只有「评论」「需要登录的字幕」用到；**插件页面看不到它** |
| `biliJct` | CSRF 令牌（bili_jct） | text | `` | 只有评论用到；单独无用（没有 SESSDATA 什么也做不了），所以不进加密存储 |
| `commentEnabled` | 允许评论 | bool | `false` | 总开关 |
| `commentMode` | 评论模式 | **select** | `draft` | 只出草稿 / 自动发 |
| `commentMinScore` | 够多少分才评论 | number | `85` | |
| `commentMaxPerDay` | 每日最多评论几条 | number | `2` | |

> **共 31 项**，卡在宿主 `maxConfigItems = 32`（`internal/plugins/manifest.go:178`）之内。
> **其中 4 项是 `select`**（分区、来源、摘要长度、评论模式）：用户的原话是「分区那一栏让人填
> `36,188,181`，谁知道哪个数字是哪个分区」。为此给宿主加了第五种控件类型
> `select`（可 `multiple`），清单里直接列出 `{value,label}`，市场画下拉或复选框组，
> 存进去的仍是逗号分隔的字符串——插件那边一行没改。
>
> 被砍掉的那几项不是需求缩水，而是**把调参变成常量**：筛完的排序固定「新 → 热」、多 P 固定第一 P、
> 气泡固定 ≤ 40 字、收件箱固定 200 条、评论分区跟随 `rids`、评论固定 ≤ 60 字、两次评论间隔固定 30 分钟。
> 理由：那条上限存在的意义是「不让配置表变成无边界表单」，而这些值一年也不会改一次。

## 7. 需要宿主配合的三处（这是本需求真正的「变更面」）

三处都是**既有实现的硬边界**，不是笔误；不改就做不出「登录 + 评论」和「后台定时刷」。

| # | 现状（本仓实读） | 挡住了什么 | 建议改法 |
|---|---|---|---|
| 1 | `net.fetch` 的请求头是**闭集**：`accept / authorization / content-type / user-agent`（`app_plugins.go:595`），**不含 `Cookie` / `Referer`** | 评论接口必须带 `Cookie: SESSDATA=…` 与 `Referer`；`need_login_subtitle` 的视频也必须带 Cookie 才拿得到字幕轨 | 新增权限 **`net.credentials`**（「以你保存的网站登录凭据发请求」）：`net.fetch` 增加 `credentials: "<配置项名>"`，**由宿主**从加密存储里取出该凭据填进 `Cookie` 头（页面永远看不到明文）；同一权限下接受一个受校验的 `referer`。其余插件行为一字不变。这样「能发 Cookie」是安装时明确勾选的一件事，而不是偷偷放宽 |
| 2 | `net.fetch` 的返回只有 `{status, body}`，**不回响应头**（`app_plugins.go:730`） | 扫码成功时凭据在 `Set-Cookie` 里，body 里没有 | 加一个**受权限门控**的开关：`net.fetch` 的 `readCookies: true`（需要 `net.credentials`）→ 返回 `cookies: ["name=value", …]`（属性一律丢掉）。**这条是踩过一次才补上的**：先按「`data.url` 的查询串里带凭据」实现，真机扫成功后返回的 `url` 是空的 —— 见 design §9.2 的实测记录 |
| 3 | `background` 必须搭配 `events` 或 `net.ws`（`internal/plugins/manifest.go:318` 的 `validateBackground`） | 本插件**既不需要事件也不开长连接**，它是「定时轮询 HTTP」——按现规则拿不到常驻帧，自动刷就只能在工坊开着时跑 | 把 `net.fetch` 加入可支撑 `background` 的权限集合（第三类：**轮询型**），并在 `validateBackground` 的注释里写清「它能自己决定何时发请求，因此不需要宿主推事件」；`.dev/check-frontend.cjs` 的对应断言同步 |

> 还有一条**不算变更、但要知道**：`net.fetch` 响应体上限 **1 MiB**（`app_plugins.go:726`）。
> 字幕 JSON 通常 20–200 KB，安全；超了就是超长视频，按「跳过 + 记日志」处理，不特殊化。

**若你不接受第 1、3 条宿主改动**：插件仍可做，但退化为「工坊开着才刷」+「不能评论」——
这大概不是你想要的，所以这两条我列为**前置条件**（§13-Q1/Q2）。

## 8. 数据模型（插件私有存储）

`storage` 的 key 只能匹配 `^[A-Za-z0-9_-]{1,64}$`（`app_plugins.go:747`），所以不带扩展名：

| key | 形状 | 写入时机 |
|---|---|---|
| `seen` | `[{bvid, at, score, title}]`（≤ 2000，> 30 天过期） | 每轮结束时 |
| `inbox` | `[{id, bvid, title, up, duration, pic, rid, score, summary, points[], why, commentDraft, commentSent, rpid, at, read}]`（≤ 200） | 推送/入箱时 |
| `usage` | `{"2026-10-23": {videos, pushes, comments, llmCalls}}`（滚动 7 天） | 每次计数 |
| `log` | `[{at, kind, text}]`（≤ 200） | 出错/关键节点 |
| `state` | `{lastRoundAt, lastPushAt, lastCommentAt, pausedReason}` | 每次调度 |

> 单条 value 没有硬上限（宿主直接写文件），但都按上表封顶，避免工坊一次读 10 MB。

## 9. 一轮的时序

```
定时器到点（activeHours 内、enabled 为真）
  │
  ├─ 读 usage：今日 videos < dailyVideoCap ？否 → 记日志、跳过本轮
  ├─ 取候选：每个来源 1 次请求（≥ 1.2s 间隔 + 抖动）
  ├─ 本地初筛 → 取 perRound 条
  └─ 逐条（串行，避免风控）：
       view → player/wbi/v2(wbi) → subtitle JSON
         ├─ 无字幕 → 降级 desc / skip
         ├─ 清洗 + 切块 → map/reduce（≤ summaryMaxCalls 次 llm.chat）
         ├─ 解析 JSON → score/useful/why/summary/points/comment
         ├─ 入箱（所有条目都入箱，便于回看）
         ├─ 过四道闸 → 弹一次气泡（本轮最多 1 次）
         └─ commentEnabled 且 mode=auto 且过门槛 → 发评论 / draft 则只存草稿
  └─ 写 seen / usage / log
```

失败与风控：单条最多重试 2 次（500ms→2s 退避）；`-352`（风控）/`-412`（请求被限制）/HTTP 412 →
**本轮中止 + 暂停 6 小时**，工坊红字提示「可能需更新 Cookie 或降低频率」，不连撞。

## 10. 非目标（这一版明确不做）

- **不下载音视频**（`playurl` 不碰），**不做 ASR**（要本地模型或付费服务，且几十 MB 流量）。
- **不发弹幕、不点赞投币收藏、不关注、不私信**（只做你点名的「评论」）。
- **不做弹幕总结**（弹幕是噪声，不是内容；如需要是另一个需求）。
- **不做多账号**：一个插件 = 一套 B 站身份。
- **不做全站爬取/榜单挖掘**：只按你指定的分区与偏好取。
- **不发 Windows 通知**（宿主无此能力；气泡 + 收件箱足够）。
- **不把摘要写进对话历史**（对话是对话，收件箱是收件箱）。

## 11. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| B 站接口非官方、会变（字段改名/加签名） | 某天全挂 | 三步各自独立降级；`log` 保留原始错误码；工坊「单条调试」一眼看出挂在第几步；接口路径集中在 `bili/api.js` 一处 |
| wbi 签名/风控（`-352`、`-412`、`-509`） | 拿不到字幕或列表 | 签名实现照搬现成参考；请求间隔 ≥ 1.2s；命中即暂停 6 小时而不是重试 |
| 很多视频没字幕 / 未登录拿不到字幕 | 摘要质量参差 | **实测：匿名 `player/wbi/v2` 一律 0 轨（20/20）**，所以「贴凭据」不是可选装饰而是核心功能的前置条件；未登录时默认「简介+热评」降级并**明确标注非字幕、并在工坊里说清原因** |
| 成本（每片 1–6 次 LLM 调用） | 悄悄烧钱 | `maxDurationSec` + `perRound` + `dailyVideoCap` + `summaryMaxCalls` 四个旋钮；被宿主预算拒了当天停 |
| 评论以你的账号公开发言 | 账号风险/社交风险 | 默认关 + 默认草稿 + 门槛/频率/分区/黑名单 + 风控即停 |
| Cookie 泄漏 | 账号被盗 | `secret: true` 加密存储；只在宿主内使用；日志打码；只发往 `netHosts` 里的 bilibili 域名 |
| 气泡打扰 | 烦 | 每日上限 + 最小间隔 + 活跃时段 + 本轮最多 1 次 |
| 版权 | — | 字幕仅本地压缩为摘要，不落盘、不转发全文、不提供下载 |

## 12. 验收标准（可测）

- [ ] 「单条调试」输入 BV 号能跑完三步，界面依次显示 `cid`、字幕轨列表、`body` 段数、摘要、分数，且**不推送、不评论**。
- [ ] 5000 字字幕（约 10 分钟）能完成 map-reduce，LLM 调用次数 ≤ `summaryMaxCalls`，最终 JSON 可解析。
- [ ] 同一 bvid 30 天内不会二次总结；重复推送为 0。
- [ ] 无字幕视频按 `noSubtitleFallback` 处理，卡片上标注「非字幕」，日志里有原因。
- [ ] `commentEnabled=false` 时**全局零 POST**（用抓包/日志断言）。
- [ ] `commentEnabled=true` + `draft` 时只产生草稿；点「发送」后才出现一条 `reply/add`。
- [ ] 命中 `-352`/`-412` 后暂停 6 小时，且不会在同一轮里继续请求。
- [ ] 停用插件后 30 秒内不再产生任何 `net.fetch`（常驻帧已卸载）。
- [ ] `activeHours` 之外只入箱、不弹气泡；同一轮最多 1 次气泡。
- [ ] `log`/气泡/错误里 `SESSDATA` 已打码；卸载插件后 `biliCookie` 文件消失。
- [ ] 工坊深浅两套主题、`[hidden]` 权威、样式无 `box-shadow/filter/transform`（沿用既有门禁）。
- [ ] `.dev/check-frontend.cjs` 全绿（含新增「插件用到的权限都在词表里」「`background` 第三类依据」断言）。
