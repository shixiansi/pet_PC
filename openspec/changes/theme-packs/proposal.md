# proposal: 主题包 —— 一个能看见的改造

## 为什么现在做

用户给了一份《界面改造方案》（设置面板 + 主题包）。先做的那一层是**令牌地基**
（`openspec/changes/ui-token-foundation/`）：把颜色基准量准、把名字统一、加一条对比度门禁。

那一层做完之后用户的反馈是「**看起来一点变化没有**」——而这是对的：它只改了颜色够不够亮，
没有动任何布局。主题包是那份方案里第一件**一眼能看出来**的事，也是后面所有事的前提：
插件界面、浮层面、商店，全都要先有"一份包"这个东西。

## 做什么

1. **四个内建包**：紫罗兰（默认）/ 樱花粉 / 森野绿 / 极简石墨。每个包写**浅色与深色两套**，
   只覆盖令牌（`--bg*` / `--text*` / `--accent*` / 状态色），不碰布局、尺寸、圆角。
2. **两个窗口一起换**：控制中心的「偏好」页点一下，桌宠的气泡、右键菜单、徽章跟着变。
   同一个字段（`theme.json` 的 `pack`），同一次读取（`Layout.ThemePack`）。
3. **选择存得住**：`theme.json` 从"一个字段"变成"两个字段"，两个写者（桌宠菜单改明暗、
   控制中心改包）都走读-改-写，谁也不抹谁的。
4. **预览卡就是那个配色本身**：卡片自带 `data-theme` + `data-theme-pack`，于是它的底色、
   文字、按钮用的都是那个包的真实令牌——TS 里**一个色值都没有**。
5. **门禁跟着扩**：对比度门禁从"两个明面 × 两套配色"变成"两个明面 × 两套配色 × 每个包"，
   472 个组合。

## 不做什么（这一轮）

- **不做主题商店**。远端索引、sha256、安装、更新、卸载是一整套分发通道，和插件市场一个量级，
  单独立项。这一轮的包是编译进包的，装不进新包，但"选包"这条路已经通了。
- **不做插件文档的注入**。插件帧是 opaque origin 的沙箱 iframe，宿主碰不到它的 DOM，
  只能走"服务 entry 文档时注入 `<style>`"那条路（`internal/plugins/asset.go`），
  那是下一轮。今天的四个包覆盖控制中心与桌宠页。
- **不做圆角/字体/间距的主题化**。包只覆盖颜色：`--pack-radius-card` 那种东西需要每个页面的
  卡片规则先认一个变量，那是布局改动，和"看得见的配色"混在一起说不清。

## 验收

- 「偏好」页有 4 张卡片，点一下整窗立刻变色（浅色与深色都正确）。
- 桌宠的气泡/菜单/徽章同时变色；关掉控制中心再打开，选择还在。
- 手动切明暗不会把包丢掉，选包也不会把明暗丢掉（两边都有 Go 测试）。
- `node .dev/check-contrast.cjs`：472 个组合全部 ≥ 4.5:1。
- `node .dev/check-frontend.cjs`：每个卡片上的包都有两套（两个窗口 × 浅深）色板。
