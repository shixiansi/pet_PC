- [x] **J11 截断标记**：导入时记 `truncated: true`，主人收到一句"其中 N 张太大被截断"；工坊给这类

  - **旧图补标记**：`backfillTruncated` 用一次 `storage.list` 拿到全部字节数，正好

  - **筛选视图**：工坊筛选项里多一项「残图（被截断）」，摘要写「其中 N 张被截断过」；
    判据：`旧上限时代的残图…会被自动标出来`、`残图：被截断的那几张能单独筛出来…`。

- [x] **J12 工坊显示今日用量**：状态卡读宿主写的 `llm-usage`，显示「N 次调用 · 约 M tokens（每次约 K）」；

  判据：`状态卡显示今日模型用量…`、`用量是昨天的就不显示…`。

- [x] **J14 残图补救：从群历史里找回**（用户提的"能不能直接在这里补"）

## P4 真机反哺（1.12 上线后才暴露的）

- [x] **J16 围栏从"可选"改成"必须"**：真机上（1.12 首版）一整晚的回复里没有一个 ```json 围栏，
  于是 notes 一直是空的、`friend.info` 全空、表情永远走随机兜底。提示词改成命令式
  「每条回复都必须以唯一一个围栏结尾，没有要记的就写 `{}`」，并把示例压成一行。
  判据：`the system prompt carries the brevity rules and the directive protocol`（断言"必须"与 `{}`）。

- [x] **J17 取证：`state/probe` + 漏围栏日志**：机器人把最近 3 条**模型原话**存下来，工坊状态卡
  显示「最近一次模型原话」；漏了围栏时日志写一句（每群 10 分钟一次）。
  判据：`模型漏了围栏时：日志说一句，原话也留在 state/probe 里`、`带了围栏就不该冒那句提示`、
  `「最近一次模型原话」显示在工坊里…`、`没有原话时那一块是隐藏的…`。
  为什么：不存原话，就只能靠猜"是模型没写还是我们没认出来"。

- [x] **J18 群列表两列不再空着**：`notes`/`energy` 优先用索引里的字段，没有就由工坊读
  `memory/<群号>/notes` 与 `state/energy/<群号>`（最多 12 个群）。
  判据：`群列表的记忆/能量列：索引里没写就自己读文件`。

- [ ] **J2 群记忆 notes**
  内容：`memory/<群号>/notes` = `[{text, at}]`，上限 `memoryNotesMax`（默认 20，超出丢最旧）；
  `remember` 追加/按文本去重（相似度用"前 12 字相同"判重），`forget` 按子串删除。
  注入：system 里 `【你记得的事】` 段，总长 ≤ 600 字符（超了从最旧开始截）。

- [ ] **J3 群友卡片**
  内容：`memory/friends/<QQ号>` = `{nickname, aliases[], info, lastSeenAt, groups[]}`；
  每条消息更新 `nickname`/`lastSeenAt`/`groups`（系统自动），`aliases`/`info` 由模型写；
  注入只放**本批消息里出现的**人，≤6 人 × 2 行（"昵称(别名): 一句话"）。
  判据：卡片读写、只注入本批相关的人、超过 6 人时按最近发言截断。
- [ ] **J4 社交能量**

  + 随机漂移 ±0.08；被 @ +0.1；回复后按字数消耗 0.03~0.18；模型可用 `energy: -0.05` 微调。
  注入：system 里一句"你现在的状态：…"（5 档）。
  判据：回归/消耗/上下限、注入文案档位、坏值回落默认 各一条。
- [ ] **J5 沉默与敷衍**

  system 里明确"能量低时连被 @ 也可以只回一两个字"。
  判据：silent 时**零** `send_group_message`、notes 仍然写入；非 silent 时行为不变。
- [ ] **J6 消息段与系统通知**

- [ ] **J7 文本 @ 转真 @ + 群内命令**

## P2 插件：表情包

- [ ] **J9 目录化两级检索**
  内容：`index` 每条补 `keywords[]`、`usageCount`、`lastUsedAt`、`truncated`；
  system 给模型 10 个情绪 + 一句"想发表情就选一个 id"；模型返回 `meme: <hash>`；
  我们校验 id 存在才发。没有 memes 字段时保持现在"标签随机"的兜底。
  判据：候选筛选（≤`stickerCandidateMax` 默认 12）、id 不存在时不发也不炸、
  usageCount 递增、旧库（没有 keywords）仍然能用。
- [ ] **J10 自动收藏**
  内容：群消息里的图片/表情包 → md5 去重查 `media/stickers/cache/<md5>`
  （命中免 VLM）→ VLM 出"标签 + 一句话" → 作为候选注入 system →
  模型 `save_meme: <md5>` 才收藏（存进 `media/stickers/`，复用导入管线）；
  上限 `collectMaxCount`（默认 200），超出按"保存旧 + 使用少"淘汰；
  缓存在 `cacheMaxCount`（默认 120）条内，最旧淘汰。
  判据：命中缓存不调 VLM、新图调用一次 VLM、只有 `save_meme` 才落库、
  淘汰顺序、关闭开关（`autoCollectStickers=false`）时完全不碰。
- [ ] **J11 截断修复的落地**
  内容：导入时若 `body` 被截断（宿主返回 `truncated`）就标 `truncated: true` 并提示"这张图太大"；
  工坊里对 `truncated` 的项显示标记与"重新导入"提示；导入命中同一 hash 时**覆盖**旧字节。
  判据：截断标记写入 index、覆盖导入替换字节、工坊渲染标记。

- [x] **J19 内容安全拦截不再把机器人卡死**（真机事故）
  内容：服务商回 `The request contains sensitive content` 时，用**最小上下文**重试（人设 + 规则 +
  这一句提问，不带历史/群记忆/群友/候选），成功后 10 分钟内都用最小上下文；`#忘掉` 连
  `history/<群号>` 一起清；非内容安全错误照旧抛出。同时去掉群名/名片/记忆/描述里的不可打印字符
  （QQ 群名里真有 `\u0011`）。
  判据：`被拦之后用最小上下文重试，群里照样收到回复`、`十分钟内再问一次…`、
  `不是内容安全的错误照旧抛出去`、`#忘掉 连最近的往来一起清…`、`群名里的不可打印字符不会进提示词`。
  事故经过：群里有人让机器人"把''傻逼''记下来"，这句话与它的复述进了 `history`，之后每条请求
  都带着它们，服务商一律拒 → 机器人哑了好几分钟，日志里只有"回答失败"。

- [x] **J20 同群提问改成排队**（用户提的）

  答完按 `cooldownSec` 的间隔接着答；冷却期内的新消息也进队列；不同群互不阻塞。为此把回答主体
  抽成 `takeTurn(groupID, job)`（job 带上这条提问自己的段/引用/发问者/正文），`drainGroupAsks`
  负责取号，每群只留一个定时器。
  判据：`上一条没答完时，第二个人的问题排队，答完再答他`、`排队最多 4 条…`、
  `不同群互不阻塞…`。
- [x] **J21 内容安全不再需要人工发指令**（用户问"一定要生硬地发指令吗"）
  内容：把"重试一次最小上下文"改成**阶梯式自我恢复** —— 丢一半旧往来 → 只留两轮 → 完全不带，
  首次成功的那一档**写回 `history/<群号>`**（从此不再带着那些话）；历史本来就空时只试最后一档；
  三档全失败才放弃，建议改成"工坊里点「忘掉这个群」"而不是让用户去群里敲命令。
  判据：`历史里有脏东西：先丢一半再试，成功那一档写回磁盘（以后不再带）`、
  `被拦之后自己缩上下文重试，群里照样收到回复（不需要人发指令）`。
- [x] **J22 自动收藏这条链修通**（真机数据显示"花钱不产出"）
  事故：`pending-index` 满了 10 张、索引里 `collected` 一直是 0、每群每小时还在识图。两个原因：
  协议字段表里没有 `save_meme`（只在待收藏那段出现过一次），以及满了不设闸（照样识图 + 挤掉最旧）。
  内容：① 规则里补上 `save_meme`，待收藏那段改成**要模型表态**（"用得上就填一张，都不值得就写 {}，
  不要不表态"）；② 待收藏满 10 张时**直接跳过识图**并每群 30 分钟提示一次；③ 工坊加「待收藏」收件箱
  （缩略图 + 描述 + 「收进图库 / 丢掉」），让已经花掉的识图钱能变成图库里的一张图。
