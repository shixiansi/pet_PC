# proposal: 令牌地基 —— 一份词表、一颗棋子一个角色、一条算得出来的线

## 为什么现在做

用户给了一份《界面改造方案》（设置面板 + 主题包）。它的第一步不是画界面，而是**先回答"颜色叫什么"**：
主题包只改令牌，令牌不统一，包就只能改一半——控制中心变了、桌宠的气泡没变、插件面板纹丝不动。

而对齐之前，先把现状量了一遍（逐条实算，不靠眼睛）：

| 位置 | 令牌 | 压在 | 实测 | |
| --- | --- | --- | --- | --- |
| 控制中心 | `--text-faint` `#a6b1c0` | `--bg` `#f6f7f9` | **2.03** | FAIL |
| 控制中心 | `--text-dim` `#7a8798` | `--bg` | **3.41** | FAIL |
| 控制中心 | `--warning` `#d97706` | `--warning-bg` | **3.07** | FAIL |
| 控制中心 | `--success` `#059669` | `--success-bg` | **3.58** | FAIL |
| 控制中心（深色） | `--text-faint` `#5a6a7e` | `--bg-raised` | **3.16** | FAIL |
| 控制中心（深色） | `--accent` `#7c3aed` **当文字** | `--bg-active`（导航当前页） | **2.89** | FAIL |
| 桌宠页 | `--text-dim` `#7a8798` | 气泡面板（≈白） | **3.41** | FAIL |

同时，**两份评审文档都写着"配色已全部达 AA"**。这不是谁在说谎：这些数字从来没有被算过，
而"看着挺深"和 4.5:1 之间隔着一整套 WCAG 相对亮度公式。评审报告的结论因此只对了一半——
它量的是插件层 `petpc-ui.css`（那一层确实修好了），而它没有量自己正在改造的那个窗口。

## 做什么

1. **一份权威词表**：令牌的**角色**（哪些是文字、哪些是表面、`--accent` 与 `--accent-ink` 各是什么）
   写下来，三个明面照着它对齐，映射关系进 `design.md`。
2. **照词表改值**：控制中心 `tokens.css`、桌宠页 `style.css` 的深浅两套；新增 `--accent-ink`，
   把"用填充色当文字"的四处改掉。
3. **一条门禁**：`.dev/check-contrast.cjs`。每颗文字令牌 × 每个表面令牌，深浅都算，
   < 4.5:1 就红。接进 `check-all.ps1`、CI，并按 `.gitignore` 的白名单放回仓库。

## 不做什么

- **不动 `market/docs/ui/petpc-ui.css`**。它的 27 份副本是被逐字节打进插件包里的
  （`market/tests/ui-tokens.test.js` 守着），改它 = 重新发布 27 个插件。它的两处已知缺口
  写在 `design.md` §5，是下一个改动的事。
- **不做主题包本身**。这一轮只把地基铺平：包要覆盖的那些名字先定下来，否则包一定做错。
- **不改 `--radius-*` / 字体 / 间距**。它们没有可读性问题，混进来只会让这次改动说不出重点。
- **不碰渲染观感**。除了"更深的灰、更稳的紫"，没有一处布局、尺寸或动效变化。

## 验收

- `node .dev/check-contrast.cjs` 通过：110 个组合全部 ≥ 4.5:1，深浅两套都跑。
- 反向验证过：把 `--text-faint` 改回 `#a6b1c0`，门禁立刻红并打印 `2.03:1`。
- `node .dev/check-frontend.cjs` 仍然绿（它有一条"桌宠页与控制中心同名同值"的配对断言，
  这一轮改的两个文件正好在它的射程里）。
- 控制中心 `npm run check` / `npm run build` 通过。
