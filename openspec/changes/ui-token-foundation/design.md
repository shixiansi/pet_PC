# design: 令牌地基 —— 角色、名字、以及一条算得出来的线

## 1. 现状：三个明面，三套词表

| 明面 | 文件 | 词表 | 谁在改它 |
| --- | --- | --- | --- |
| 控制中心（独立程序） | `tools/plugin-market/cc/src/tokens.css` | `--bg*` / `--border*` / `--text*` / `--accent*` / `--success*` … | 本仓，随便改 |
| 桌宠那一页（被 `SetWindowRgn` 裁过的窗口） | `frontend/src/style.css` | `--panel-bg` / `--panel-border` / `--chip-*` / `--tint` / `--shadow-*` | 本仓，随便改 |
| 插件层（27 个插件共用） | `market/docs/ui/petpc-ui.css` + 27 份 `plugins/<id>/ui.css` | `--accent` / `--accent-strong` / `--accent-on-soft` / `--text*` … | **独立仓**，逐字节复制进 27 个插件包 |

前两个是同一件产品的两面，第三个是别人（插件作者）界面里的那一份。**三者变量名不同**，
所以"主题包只改令牌层、三处一起变"这件事今天并不成立——它需要一个权威词表先说清楚
"这个角色叫什么名字"。

## 2. 命名裁决：向改不动的那个收敛

三套词表里，只有 `petpc-ui.css` 是**贵**的：它的 27 份副本被 `package.ps1` 逐字节打进插件 zip，
`market/tests/ui-tokens.test.js` 守着"逐字节相同"，所以改它 = 重新打包 + 重新发布 27 个插件。
贵的那份决定了标准。

它的约定是：

- `--accent` ＝ **当文字/图标/描边**的强调色（浅 `#7c3aed`，深 `#a78bfa`）
- `--accent-strong` ＝ **填充**（按钮底，白字压上去 7.10 / 5.70）
- `--accent-on-soft` ＝ 压在 `--accent-soft` 上的文字
- `--accent-dim` ＝ 装饰（描边、虚线、选区底）

**被否掉的方案：设计稿里的 `--accent-ink`。** 它和 `--accent` 的角色划分是等价的，但它把
`--accent` 留给了**填充**——正好和插件层相反。于是同一颗 `var(--accent)` 在三处界面里
表示两种东西，将来主题包必须为每个明面各写一份映射，而"映射写错一处"这类错误在界面上
看不出来（它只是某个角落淡了一点）。名字只有一套才谈得上"覆盖"。

所以：**控制中心与桌宠页都改成插件层的三个名字**，并把填充的写法从 `var(--accent)` 换成
`var(--accent-strong)`（控制中心 4 处、桌宠页 1 处、`accent-color` 4 处）。

## 4. 三个明面的映射

主题包将来要按**角色**写值，不是按名字抄。这张表就是"这个名字在那一页是谁"：

| 角色 | 控制中心 | 桌宠页 | 插件层 |
| --- | --- | --- | --- |
| 页面底 | `--bg` | —（透明，露出桌面） | `--bg` |
| 卡片底 | `--bg-raised` | `--panel-bg`（0.97 α）/ `--chip-bg`（0.96 α） | `--bg-raised` |
| 下沉底 | `--bg-sunken` / `--bg-hover` | `--chip-hover` / `--tint` | `--bg-sunken` |
| 选中底 | `--bg-active` | — | `--bg-active` |
| 正文 / 次级 / 提示 | `--text` / `--text-dim` / `--text-faint` | `--text` / `--text-dim` / —（用 dim） | 同控制中心 |
| 强调（文字） | `--accent` | `--accent`（本页暂无文字用法） | `--accent` |
| 强调（填充） | `--accent-strong` | `--accent-strong` | `--accent-strong` |
| 软底 + 其上文字 | `--accent-soft` +（将来 `--accent-on-soft`） | — | `--accent-soft` + `--accent-on-soft` |
| 状态 | `--success/--warning/--danger/--info`（+ `--ok/--warn` 别名） | `--ok/--warn/--danger` | `--success/--warning/--danger/--info` |
| 圆角 | `--radius-*` | `--radius`（14 = `--radius-lg`） | `--radius-*` |

两个"看起来一样但不是同一个东西"的地方，别在写包的时候当成同一颗：

1. **桌宠页的底是半透明的**（`--panel-bg` 0.97、`--chip-bg` 0.96）。它是一个浮在桌面上的卡片，
   所以合成的底色取决于壁纸。白壁纸是最坏情况，这也是门禁的合成规则。
2. **插件层是孤立世界**：它是 opaque origin 的沙箱 iframe，宿主碰不到它的 DOM（见 `docs/plugin-dev.md`
   §几何与主题）。所以主题包想覆盖它，只能走"服务 entry 文档时注入 `<style>`"那条路，
   而注入的规则必须排在插件自己的 `ui.css` **之后**——同特异性、后写者胜。这件事属于下一轮。

## 5. 已知残留（不在本轮，写在这里是为了别当成"已经修完了"）

`petpc-ui.css`（市场仓，27 份副本）：

1. 深色 `--text-faint: #7d8ba0` 压在它自己的 `--bg-active`（`#2c2452`）上只有 **4.10:1**。
   评审报告给的值 `#8e9bb0` 实测 5.04，是对的；本轮控制中心先用了 `#8e9bb0`（在控制中心的
   `--bg-active` 上是 5.86），插件层那 27 份**还没改**。
2. 第 781～788 行两处标签是 `background: var(--accent-soft)` + `color: var(--accent-strong)`，
   深色下 **2.89:1**。评审报告说"深色 soft 组件 3.11:1 已修"——修的是 `.btn.soft` 那两处
   （424 / 610 行用了 `--accent-on-soft`），这两处漏了。正确的写法就在旁边。

这两条都要改 27 份副本 + 重新打包 27 个插件，属于市场仓那一轮，不是这里顺手能带上的。

另外两条评审结论本轮也不动：`market.css` 的字体栈仍是 `"Segoe UI"` 优先；市场两页的卡片/计数。

## 6. 门禁为什么这样写（`.dev/check-contrast.cjs`）

- **词表硬编码、值从 CSS 读。** 和 `.dev/check-frontend.cjs` 里那份权限词表同一个理由：
  它故意不自动跟随，因为"发现词表被改了"正是它的职责。自动推导出来的词表只会跟着一起漂。
- **跑矩阵，不是跑几个已知组合。** `#a6b1c0` 那次事故的性质不是"某个组合不合格"，而是
  **这颗令牌从来没有被算过**。所以是"每颗文字令牌 × 每个表面令牌"，8×4 与 6×3，深浅各一遍。
- **半透明先合成。** 面板压在未知桌面上 → 按最坏情况压**白**；状态软底压在已知的卡片上
  → 点名 `over: 'bg-raised'`。不区分这两种，门禁会把深色的绿色标签算成 1.5:1（它自己看错）。
- **阈值不放宽、不按字号打折。** 占位符、行尾说明、"只是提示"都有人读。放宽这条线等于
  把检查关掉，而它存在的全部理由就是"没有人会去算"。
- **负向验证过。** 把 `--text-faint` 改回 `#a6b1c0`，门禁立刻红并打印 `2.03:1`（记录在 tasks.md）。
