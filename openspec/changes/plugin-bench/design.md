# design: 控制中心里的插件测试台

## 1. 四个决定

| 决定 | 备选 | 为什么 |
| --- | --- | --- |
| **控制中心里的一页**，复用 `plugin-frame.ts` | ① 另写一个 iframe 宿主 ② 在页面里套 `preview.mjs` 起的本地服务器 ③ 只放一个"去哪跑命令"的说明 | ① 这个窗口里就有两个沙箱边界要同步了，第三个必然漂——而漂的那一份是没人发货的那一份（`AGENTS.md §3.3`）；② 需要用户机器上有 node、要先手动起服务，而装插件的人通常没有；③ 用户要的是"直接展示"。**`plugin-preview` 当初拒绝"做成控制中心的一页"的理由仍然成立**——只是那条理由针对的是**排版断言**（换个 rect / granted 就得改代码重建 exe）；这里做的是"位置 + 授权 + 消息"，参数全在页面上，不需要重建 |
| **`init.surface` 变成参数** | 保持写死的 `panel/workshop`，另开一条只有测试台用的通道 | 插件判断"我在哪"就靠这一个字段（手册 §6）。另开通道等于让插件读两套协议；而写死它就意味着这个页面永远看不到桌宠的矩形 |
| **「模拟未授权」在宿主模块里同时决定两半**：`granted = []` **且** 请求在本层被拒 | ① 只清 `init` 里的清单 ② 只拦请求 ③ 真的调 `Grant(id, [])` | ① 会让插件以为自己无权限、而闸门照样放行——两句话互相矛盾；② 反过来的矛盾；③ 改的是用户在世界里的授权，而那是「插件」页上的决定。两半写在 `mountPlugin` 同一处（`deny` 一个变量），物理上无法只做一半 |
| **拒绝发生在闸门之前，并写明"测试台"** | 照样问闸门，再把答案改掉 | 那样日志和 `market.log` 会互相矛盾（一个说拒了、一个说 ok），而这份日志的全部价值就是"原样" |

## 2. 三种位置，各自对应谁

| 页面上的选项 | `init.surface` | 真机上谁这样挂 | 有没有矩形 |
| --- | --- | --- | --- |
| 控制中心 · 工作区 | `{kind:'panel', slot:'workshop'}` | 「插件」页（`PluginFrame.svelte`） | 没有（铺满） |
| 桌宠 · 浮层面第 N 块 | `{kind:'surface', rectIndex, rectCount, rect}` | 桌宠的浮层面（`plugin-host.js` 每块一个帧） | **有**，而且被 `SetWindowRgn` 裁 |
| 桌宠 · 常驻帧 | `{kind:'panel', slot:'background'}` | 桌宠的隐藏常驻帧（`display:none`，照样在跑） | 没有（不可见） |

`kind` 不足以判断"我在哪"（常驻帧的 `kind` 也是 `panel`），所以两条 `slot` 名字都照真机的写法给。
测试台**不猜**用户想测哪个：声明了浮层面的插件默认按浮层面挂（那是最容易出错、也最值得看的一块），
声明了 `background` 的插件在位置下拉里多一项，其余默认工作区。

**停用的插件挂不上，而且这是宿主的规则不是页面的选择**：`ServePluginAsset` 对未启用的插件回 403，
所以它连文档都取不到。页面把这类插件列在下面并写明原因，而不是让它选上去之后显示一块空白。

## 3. 这个页面**量不了**排版，而且必须说出来

沙箱是 `allow-scripts`（不含 `allow-same-origin`），所以帧是 opaque origin：父页面拿不到
`contentDocument`，`getBoundingClientRect()` 一条也读不到。"按钮被下边缘切掉"只能由真浏览器 +
能读 DOM 的页面发现——那是 `market/docs/plugin-testkit/preview.mjs`（它故意不给 iframe 加 sandbox，
就是为了读 `contentDocument` 量排版）。

所以这一页写清了自己量的是什么：**框**（是不是清单声明的那一块）和**握手**（插件在这个框里被告知
了什么）。把这两件事说成"排版检查"会是这份仓库最不能接受的那种文档。

## 4. 为什么改尺寸要重新握手

`init.surface.rect` 是宿主告诉插件"你占多大地方"的那一句。测试台允许改宽高（量"窄一点还放得下吗"），
改完必须**销毁文档重挂**：

- 只改 iframe 的 CSS 尺寸而不重新握手，插件手里那份 `rect` 就是假数字，它按它画完之后被裁的行
  会被记到"插件不会排版"头上；
- 重新握手的代价是插件的 `onInit` 再跑一次——这是插件本来就必须支持的路径（换插件、改授权都会
  重挂），不是测试台发明的。

「重挂」按钮是同一件事的手动版（`tick` 进 key），用来确认"这个文档重新加载一次还是不是好的"。

## 5. 日志里记什么

每条一行：时间、方向、类型、一句话。请求记**方法名 + 载荷字节数**，响应记**方法名 + ok/错误原文**
——和 `market.log` 的口径一致（§3.8：INFO 级不记正文）。这里没有等级的概念（它是会话流水，不是
持久日志），但它同样**不记载荷内容**：这一页的用途是"看谁说了什么"，不是"把插件的对话贴出来"。

上限 200 行，新的在最上面：一个每秒请求的插件不该把这一页撑爆，而"刚发生的那几条"才是要看的。

## 6. 顺手修掉的一个真问题

`plugin-frame.ts` 里 `EventsOn('pet:plugin-event', …)` 是**没有保护**的：它转发到
`window.runtime`，而只有 Wails 窗口有这个对象。在 `npm run dev`（浏览器）和 render smoke（jsdom）里
它抛 `Cannot read properties of undefined (reading 'EventsOnMultiple')`——**在 `$effect` 里**，
于是帧根本没挂上，症状是"这个页面坏了"。

这不是本轮引入的，是本轮**撞上**的：渲染冒烟在这次改动之前就已经因为它在 26/… 条断言之前崩掉。
现在它是 `try { … } catch { 没有宿主事件 }`：浏览器里能挂帧但收不到宿主事件，而那正是浏览器里的
真实情况。`check-frontend` 的一条断言盯着这两个形状，免得它再变回没有保护的样子。

## 7. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 有人把它当排版门禁 | 页面上写着"量不了排版、要 preview.mjs"；proposal 的「明确不做」也写着 |
| 有人以为「模拟未授权」改了授权 | 开关的 `title`、权限清单下方那句、以及拒绝原文里都写着"模拟"；页面上没有 `Grant`/`SetEnabled`（`check-frontend` 那条断言钉住） |
| 两个插件页同时挂一个文档 | 左栏切页会卸载上一页（`$effect` 的 cleanup 销毁帧），整个窗口同一时刻只有一个插件文档 |
| 大矩形（比如 2000 高）把页面撑爆 | 宽高夹在 80–2000，画布自己滚动，缩放 100/75/50% |
| 帧挂在隐藏的常驻帧上看不见，被当成"坏了" | 那一支有一句明确的话：它本来就不可见，右边日志是它在跑的证据 |
| 有人把测试台当第二个宿主改起来 | `check-frontend` 断言这一页里不许出现 `createElement('iframe')`，且必须调 `mountPlugin` |
