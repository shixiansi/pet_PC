# 门禁分诊：`check-frontend.cjs` 在重构期怎么办

阶段 2 的第一件事，不是写 Svelte，是决定这 169 项断言里哪些活、哪些死。不做这一步，
动前端那天它会成片变红，而一个人面对 60 条红只会做一件事：把检查关掉。

## 量到的事实

| 事实 | 数字 |
| --- | --- |
| `check-frontend.cjs` 行数 | 2221 |
| 运行时报告的检查项 | **169** |
| 引用 `mainJs` 的次数 | **91** |
| 引用 `htmlIds` 的次数 | 12 |
| 引用 `htmlIds.has` 或 `mainJs` 的行 | **129** |

也就是说：**这 169 项里的大头是钉在旧前端 DOM 上的**，而 Svelte 编译后既没有那些元素
id，也没有一个叫 `main.js` 的文件带着可被正则扫描的调用点。

> 待钉死的一处：用正则抓"标签位置的字符串字面量"得到 317 条，而脚本自己报告 169 项。
> 差距来自标签之外的字符串参数（`check()` 的第三个参数、`console.log` 的提示）。正式
> 分诊的第一步是给每一项编号并输出，让"169"和"清单"一一对上，而不是靠正则估。

## 四类，以及各自的处置

### 1. 保留并强化（与前端实现无关）

- **绑定名对齐**：现在有两条（"headless harness 的假桥接 == Go 导出集合"、
  "jsdom harness 的假桥接 == Go 导出集合"）。它们钉的是 59 个 Wails 方法名，**新前端
  一样需要**。
  改法：期望集合从 `frontend/wailsjs/go/main/App.d.ts` 生成（那是 Wails 自己的产物），
  而不是手工维护一份列表——手工列表是这轮里最容易腐坏的东西。
- **权限词表**：硬编码的 17 项期望、市场是否解释每一项、市场插件要的权限是否都存在。
  与界面结构无关，原样保留。
- **窗口区域规则**：不许 `box-shadow` / `filter` / `transform`，椭圆必须是
  `border-radius: 50%`。这是**裁剪窗口的硬约束**，Svelte 一样要守，而且违反了的表现是
  "桌宠周围出现玻璃带"这种极难查的视觉 bug。保留，并且新前端的 CSS 要一起扫。
- **插件沙箱不变量**：`iframe sandbox="allow-scripts"`、只走 `postMessage`、只接受自己
  创建的 iframe 的 `contentWindow`。`plugin-host.js` 这次**不重写**，所以这些断言原样有效。
- **音频按文件播放、`SND_MEMORY` 不存在**：钉的是 Go 侧，与前端无关。

### 2. 重写为组件测试（语义保留，形式换掉）

这些断言问的是"点了这个按钮会不会调用那个绑定"，只是目前靠**正则扫 `main.js`** 来回答：
元素 id 存在于 `index.html`、`main.js` 里有对应的 `App.Xxx(`、`EventsOn` 有对应的 Go 侧
emit。

改法：引入 `vitest` + `@testing-library/svelte`，每个页面一个测试文件，断言
**交互 → 绑定调用**。这比扫源码更强：扫源码只能证明"这两个字符串都出现过"，而组件测试
证明"点了它真的调了它"。

数量估计：这是 129 行里的大部分。

### 3. 删除（钉在旧 DOM 的具体形状上）

"某个 class 有一条点规则"、"某处横幅还在不在"、"这一段的 DOM 层级"——这些是旧前端
**实现细节**，重构后本来就不该存在。删掉，理由记进提交信息。

### 4. 迁移到新位置（旧前端删掉之后才做）

"两个前端各自的 style.css 是否都被 import"、"新增 CSS 无 shadow/filter" 这类，要在新
前端（控制中心 + 桌宠）上重跑。等阶段 3/4 有了新文件再指过去。

## 顺序（不可调换）

1. **给 169 项编号并输出清单**，让数字与条目一一对上（一天之内的事，但必须先做）
2. 按上面四类打标签，写进一个 `CHECKS` 表：`{ name, bucket, owner }`，`owner` 是
   `gate | component-test | delete | later`
3. 把 2 类改写成组件测试，**逐条**替换并删掉对应的正则断言（不是一次性重写整个脚本）
4. 之后才动前端。此时门禁里剩下的都是与实现无关的断言，重构期间它仍然是网

## 一个必须抵住的诱惑

重构期最大的风险不是写错 Svelte，是**为了让 CI 变绿而放宽检查**。所以第 1 步就要把
"每一项为什么存在"写进表里——一条检查如果没人能说出它在防什么，那它该被删掉，而不是
被注释掉。
