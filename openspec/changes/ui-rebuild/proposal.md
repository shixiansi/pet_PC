# proposal: 界面重建 —— 独立控制中心 + Svelte

## 为什么现在做

用户的原话：「界面是没变化的」。这句是对的，而且原因不在配色：

- 桌宠窗口被 `SetWindowRgn` 精确裁剪成桌宠形状，设置页只能挤在它旁边那条窄栏里，
  README 自己写着「要滚动才能看全，但**不能**因此把面板撑高」。于是任何新功能都只能
  往这条缝里塞。
- Wails v2 **没有多窗口 API**。这个约束已经逼这个项目造过一个独立程序（插件市场），
  而它是整个项目里唯一「看起来像个应用」的部分。
- 前端是两套手写 DOM：`frontend/src/main.js` ≈2400 行 + `style.css` 1391 行；
  市场前端 `main.js` 1457 + `style.css` 1585。没有组件、文案硬编码、状态靠散落的
  事件处理函数。

所以这不是「美化」，是**把界面从窗口约束里解放出来，再给它一套结构**。

## 两个已定的决定

1. **独立控制中心**：设置、插件、记录、高级配置搬出桌宠窗口，成为它自己的程序。
2. **框架选 Svelte 5 + TypeScript + Vite**。

## 不做什么（这是本提案最重要的部分）

**不重写后端。** 148 个 `.go`、41 个测试文件、17 项权限、169 项静态断言、12 道门禁。
它们是这个项目唯一还没丢的资产：最近 5 个 bug 里有 4 个在本次改造之前就存在，是这套
测试和门禁让它们能被找出来。重写后端会把这份确定性清零，而用户要的观感提升一点也
不需要它。

**不换掉 Wails。** 它是这个产品相对 Electron 的实体优势（10.9 MB vs 上百 MB）。

**不抄 Coopanion 的代码与素材。** 它 AGPL-3.0，形象贴图还单独排除在外。可以学信息
架构、活动气泡这个反馈通道、首次引导的做法；不能抄实现、配色文件或字段命名。

## 验收

- 桌宠面板只剩「今天要做什么」，不再有设置/记录/插件入口
- 控制中心是一个有侧栏、多页面、深色浅色都对的程序
- 两个前端共用一份设计 token 和一套组件，`style.css` 从 2976 行降到 token + 组件
- 59 个 JS 绑定的名字面一个不变（前端随便换实现，契约为零）
