# PetPC 桌宠

Windows 桌面宠物：一个透明、无边框、始终置顶的小窗口贴在屏幕边上，单击展开待办与日程面板。

技术栈：**Wails v2.11**（Go）+ **Vanilla JS + Vite 4**，数据用 **JSON 文件**存储。

> **工具链**：需要 **Go ≥ 1.22**（Wails v2.10+ 的硬性要求）与 Node 16+。
> Wails CLI：`go install github.com/wailsapp/wails/v2/cmd/wails@v2.11.0`

---

## 快速开始

```powershell
# 开发模式（热重载）
wails dev

# 打包
cd frontend; npm install; npm run build; cd ..
wails build -s          # -s 跳过前端构建，前端已在上面构建好
# 产物：build\bin\PetPC.exe
```

双击 `build\bin\PetPC.exe` 即可运行。程序是单文件绿色版，可以随意拷贝。

### 使用

| 操作 | 效果 |
| --- | --- |
| **拖动**桌宠 | 移动位置，松手后自动吸附到最近的左/右边缘 |
| **单击**桌宠 | 展开/收起待办面板（延迟 200ms 执行，用于和双击区分） |
| **双击**桌宠 | 打开/收起**对话插件的浮层面**（再双击一次关闭；插件界面自己的关闭按钮也可以）；**若番茄钟正在等你写总结/写计划/选待办，则改为把光标送进那个输入框**（见下） |
| **Ctrl+Alt+S** | **显示**桌宠（全局快捷键，需在设置里开启） |
| **Ctrl+Alt+H** | **隐藏**桌宠（全局快捷键，需在设置里开启） |
| 托盘菜单「显示/隐藏桌宠」 | 同一件事的鼠标入口，快捷键被占用时的退路 |
| 面板「设置」标签 | 更换图片、调整大小、开关贴边、开关开机自启、番茄钟/提醒的全部选项，以及**打开插件市场** |
| 面板「记录」标签 | 番茄钟历史记录，**按天折叠**（计划/实际两行都可改，**不可删**） |
| 面板「对话」标签 | **对话插件的槽位**：它没装好时显示一句提示，装好并授权后由插件自己渲染界面；`Enter` 发送由插件决定 |
| 设置 → 插件市场 → **打开插件市场** | 启动**独立程序** PetPCPluginMarket：浏览/安装/授权插件，编辑插件自己的配置，并在该插件的设置区**托管插件自己的界面**（含对话插件的 AI 配置与密钥、语音插件的配音工坊） |
| `Esc` | 依次取消编辑 → 关闭气泡 → 关闭面板 |
| 托盘图标 | 单击开关面板；右键菜单含「立刻提醒一次」「开启/关闭番茄钟」「归位」「退出」 |

## 番茄钟与对话提醒

两个**互相耦合**的功能：番茄钟给提醒提供「现在能不能打扰」的判断依据。
完整需求文档见 `docs/reminder-pomodoro.md`。

```
现在是什么阶段？
├─ 专注中（focus，且正在跑）  → 一律不弹；记下「错过」，休息时补一次
├─ 已暂停 / 已停止            → 算非专注 → 可以弹
├─ 休息中（break）            → 可以弹（会立即弹一次）
└─ 番茄钟未开启               → 按间隔弹，受活跃时段限制
```

**番茄钟**：默认关闭，需手动开启。点「开始专注」先弹**选择待办**气泡
（必选；列表为空时允许「不关联待办」）——但**选完待办并不计时**，紧接着会弹
**计划气泡**「接下来想专注做什么？」，由这一句的**应答当刻**起算专注。休息自然
到点时同样弹这个计划气泡，所以两条进入专注的路都会先问一句计划。

计划**可留空**：留空按 `Enter` 或点「跳过」都直接开始（与"跳过"同一条路径，记录
照旧产生）。气泡里 **`Enter` 提交、`Shift+Enter` 换行**（中文输入法选字的回车不会误提交）。
到点后播系统提示音 + 弹**写总结**气泡 + 写入记录；总结气泡上会显示**当初写的计划**，
好让你填结果时有对照。支持暂停/继续/停止/跳过，**停止是可恢复的**（≠ 放弃），
跨重启按剩余时间续算。

> **浮层不会顶掉提问气泡**：总结气泡是休息的门控、**计划气泡是专注的门控**，
> "打开浮层"在区域裁剪上只能**删掉**它（两者共用同一块矩形），所以此时 `OpenLive`
> 直接拒绝，前端把双击改成**把光标送进那个输入框**。提醒气泡与面板不在此列
> （前者不提问，后者本来就能改总结；但面板里没有回答**计划**的入口，所以关闭面板时
> 会把没答的计划气泡重新弹出来）。
> 见 `docs/reminder-pomodoro.md` §8.2、§4.5.2。

**对话提醒**：气泡 12 秒后自动消失（悬停暂停），点击气泡直接打开待办面板。
每次间隔 = 配置值 + 随机 0~3 分钟，避免像闹钟一样准点。全屏（视频/游戏）时静默。

**记录**：每个专注阶段结束都产生一条，**没有删除入口**（store 层不提供
`DeleteRecord`，从类型上杜绝）。每条记录有**两行**：第一行「**计划**：\<开始前写的事\>」，
第二行「**实际**：\<结果\>」，**两行都可改**（「改」→ 两个文本框一次写回）。没有计划的
老记录第一行退回显示待办名，观感与升级前一致。记录页**按天折叠**，只有最新一天默认
展开，折叠状态跨重渲染保留；底部显示条数与累计专注时长。

## 隐藏与显示（全局快捷键）

设置 →「外观与启动」→「隐藏与显示」，默认**关闭**。开启后：

| 快捷键 | 作用 |
|---|---|
| `Ctrl+Alt+S` | 显示桌宠 |
| `Ctrl+Alt+H` | 隐藏桌宠 |

是**两个键而不是一个切换键**，这是刻意的：切换键的状态用户看不见，手一抖就把
「把它找回来」变成「又藏起来一次」——而这功能的全部意义就是救回来。

**为什么是 `Ctrl+Alt` 而不是 `Ctrl+Shift`**：全局快捷键是从**所有程序**手里抢过来的，
所以修饰键的选择直接决定抢错了有多大破坏。`Ctrl+Shift+S` 在绝大多数编辑器里是「另存为」，
`Ctrl+Shift+H` 在好几个软件里是「查找替换」——占掉它们等于把用户真正在用的快捷键弄坏；
反过来若对方先注册成功，桌宠自己的快捷键就静默失效。`Ctrl+Alt` 被占用的软件少得多，
这正是这里要优化的性质。**这条有测试与静态检查钉着**（`TestDefaultHotkeysAreTheDocumentedOnes`、
`the shortcuts avoid the Ctrl+Shift combinations applications already use`），
免得以后被顺手改回拥挤的组合。

隐藏时会把面板、气泡、插件的浮层面一起收起来（它们都贴着宠物画），**番茄钟、提醒、待办
照常在后台运行**，只是隐藏期间**不弹提醒**（气泡画在窗口里，一个看不见的通知没有意义）。
重新显示时窗口区域会重新裁剪。

**唯一的例外是番茄钟的提问**：隐藏期间**专注到点**（写总结）或**休息到点**（写计划）时，
桌宠会**自己显示出来**（`SW_SHOWNOACTIVATE`，**不抢键盘焦点**），答完、跳过或放弃之后
**自动隐藏回去**。原因是这两个气泡都是**门控**——总结不答休息就不开始计时、计划不答专注
就不开始计时——藏着一个停住的计时器却不给任何解释，是唯一真正的死路。
反方向仍然是**拒绝**（见下）：提问**已经在等**的时候按隐藏键会被拒绝，
所以问题永远不会落在看不见的地方。详见 `docs/reminder-pomodoro.md` §4.9。

### 一条硬规则：能藏起来，就必须能找回来

桌宠藏起来又没有退路，是**唯一不可恢复**的故障，所以三种退路**故意冗余**：

1. **`Ctrl+Alt+S`** —— 全局快捷键；
2. **托盘菜单「显示桌宠 / 隐藏桌宠」** —— 鼠标入口，快捷键被别的程序占用时用它；
3. **重启程序** —— 窗口每次启动都显示，所以「隐藏」**不写进 config**，重启必然回来。

配套的实现约束（都有测试守着）：

- **先注册 show，再注册 hide**。`RegisterHotKey` 是**逐个键**可能失败的，
  按这个顺序遇到失败就**中断**：show 失败则一个都不注册，hide 失败则至少 show 还在。
  反过来注册就可能留下一个「只能藏、不能露」的组合——正是要避免的那个故障。
  （`internal/desktop/hotkey.go` 顶部的注释 + `TestShowIsRegisteredBeforeHide`）
- **注册失败要显示出来**，不能默默假装成功。设置页的「快捷键」行会写明
  「未能生效：Ctrl+Alt+H：已被其他程序占用」，因为「我按了没反应」正是这个功能
  最需要解释的失败。
- **关闭开关就立刻归还组合键**，不用重启；退出程序时也显式注销（被死进程占着的
  热键要等 Windows 自己发现）。
- **写总结时不能隐藏**：总结气泡是休息的门控，藏起来等于把计时器永久停住却没有任何
  解释——和 Esc、拖动桌宠一样被拒绝（`docs/reminder-pomodoro.md` §4.5.1）。
  **反过来的顺序是另一半**：桌宠**已经**藏起来之后专注/休息才到点，它会**自己显示出来**
  让你答题，答完再藏回去（§4.9）——因为"拒绝隐藏"只管"提问已经在等"这一种顺序，
  管不到"先藏起来、之后才到点"。
- **默认关闭**：全局快捷键是从**所有其它程序**手里抢过来的，不问自取可能弄坏用户
  编辑器里的快捷键。

> 实现放在 `internal/desktop/hotkey*.go`：`RegisterHotKey` 是**线程亲和**的（热键属于
> 注册它的那个线程，`WM_HOTKEY` 也投递到那个线程的队列），所以这里沿用了托盘图标
> 已经验证过的形状——**一个专用 OS 线程 + 一个 message-only 窗口 + 自己的消息循环**。
> Windows 之外是空实现，保证模块仍然可编译可 vet。
>
> **踩过的坑（两个，都已修 + 已实测）**：
>
> 1. **注册成功 ≠ 会触发**。第一版写好了 `RegisterHotKey`，却**忘了泵消息队列**：
>    `WM_HOTKEY` 投递到线程队列后没人取，于是快捷键"注册得完美、按下去毫无反应"。
>    这类错最阴的地方是日志显示 `active=true`，一切看起来都对。现在循环用
>    `PeekMessage` 排空消息再 `DispatchMessage`，没有消息时才 `Sleep(10ms)` 去等命令
>    ——热键在 peek 到的瞬间就派发，所以这个 sleep 只影响"改设置"的延迟，不影响按键。
> 2. **`HotkeyView.Enabled` 与 `Active` 是两件事**，混起来会让开关"点了就弹回去"。
>    `Enabled` = 用户在 config 里的开关，`Active` = OS 是否接受了注册。第一版让
>    `Enabled` 取自 manager 的零值（false），于是保存一回来面板就把复选框写回关闭，
>    表现就是**开关一直闪、点不开**。现在 `Enabled` 只由 config 决定（`app_hotkey.go`
>    的 `hotkeyView`），并有两个回归测试钉住（`TestHotkeyViewKeepsTheSwitchOn`、
>    `TestEnabledAndActiveAreIndependent`）。

## 大模型对话

**双击桌宠**打开对话插件的浮层（单击仍然只是开关面板）。完整需求文档见 `docs/llm-chat.md`。

对话的**界面与配置自本版起都属于「对话插件」**（`com.shixiansi.plugin-chat`），
桌宠只提供槽位、浮层面几何和传输层：

- **运行界面**：对话插件声明 `panelSlot:"chat"`，于是它占满面板的「对话」tab；
  它同时声明 2 块浮层矩形（宠物正上方的回复卡 + 正下方的输入条），双击桌宠时显示。
  界面是沙箱化的 `iframe`，桌宠读不到它内部，它也只能通过受权限门控的接口与宿主通信。
- **AI 配置**：端点、模型、温度、人设、上下文条数、每日上限与 **API Key** 都在
  **插件市场程序的设置表单**（动作栏里的齿轮「设置」）里编辑（见上一节），存在插件自己的私有目录里。
  桌宠设置页**不再有任何 AI 配置控件**。
- **传输层**：请求仍由宿主发起（`internal/llm`，`llm.chat` 能力 + SSE 帧协议**未变**），
  插件不直接联网——所以「请求从哪里发出去」这件事没有因为搬迁而改变。
- **历史与用量**：历史由插件经 `storage.*` 读写；用量仍由宿主唯一累加与强制上限。
- **密钥**：用 Windows DPAPI 加密，**按插件隔离**存放，界面只显示掩码，
  插件之间互相读不到。旧的 `llm-key.bin` 会在首次启动时迁进插件的私有目录。
- **默认关闭**：不开就是原来的桌宠，一行网络请求都不会发。每日请求上限默认 200 次。
- **失败不拖累其它功能**：断网、Key 失效、地址填错时，错误只出现在对话里，
  番茄钟、提醒、待办全部照常工作。

> 本版**只聊天**，还不能替你改待办/番茄钟。
>
> **为什么对话界面属于插件而不是宿主**：面板是固定 380×520 的矩形，而「宿主自己实现一套对话 UI」
> 与「插件也能提供对话 UI」是同一件事的两份实现——一旦两份同时存在，权限、历史和配置就会各说各话。
> 所以宿主的对话界面整族被删除，只留下**槽位**（面板）与**浮层面几何**（窗口区域）两条通用机制。
> 详见 `docs/llm-chat.md` §8.0。

### 对话浮层面（双击桌宠）

**双击**桌宠弹出对话插件自己的浮层面，一共两块，都**以宠物为中心**：

- **回复卡在宠物正上方**（300×112），**只显示最新的一条回复**——不显示你发过的问题，
  也不显示更早的往来；完整记录在面板的「对话」tab 里。
- **输入条在宠物正下方**（300×56），左边输入框、右边**纸飞机图标**的发送键。

两块都是窗口区域裁出来的矩形，所以卡片与输入框的圆角来自区域本身。浮层面**不改变窗口宽高
与位置**，只是把窗口的**可见区域**换成「宠物 ∪ 声明的两块矩形」——和气泡用的是同一套机制。
所以浮层打开时宠物一像素都不会动。

> 两块声明为 300 宽、以 150 宽的宠物为中心，所以各向宠物两侧外扩 75px。宠物**紧贴窗口边缘**时
> 会被区域裁剪的边界夹回来，实际贴齐宠物外侧边——这是区域裁剪的必然结果（不夹的话多出来的
> 部分根本画不出来）。宠物不贴边时就是完整的 300 宽居中。
>
> 早先这里还有三个「思考泡泡」（椭圆，从卡片指向宠物）；现在去掉了。
> `ellipse` 这个能力本身保留在 manifest 里（椭圆是圆角矩形唯一近似不了的形状），
> 只是官方对话插件不再用它。

浮层面和面板的「对话」tab 是**同一个插件界面的两个视图**：插件在 `init` 消息里收到
`surface.kind`（`'panel'` 或 `'surface'`）、`surface.slot` 或 `surface.rectIndex`，
据此决定渲染哪一块。历史由插件自己保存，两边看到的是同一份——面板显示全部往来，
回复卡只取其中的最后一条回复。

> **关掉对话插件之后**：面板的「对话」tab 显示
> 「对话插件还没装好：在设置里点「打开插件市场」装上并授权它。」，
> 双击桌宠也不再弹浮层，而是用气泡说明原因。

## 大模型对话的历史沿革

面板是固定 380×520 的矩形这件事，决定了这里的每一次演进都是「换承载」而不是「加功能」：

| 版本 | 对话在哪里 | 为什么改 |
| --- | --- | --- |
| 早期 | 无 | — |
| 实时交流浮层 | 面板旁的浮层，宿主自己实现 | 想边看宠物边聊 |
| 对话 tab | 面板第四个 tab，宿主自己实现 | 想要完整、可滚动的记录 |
| **本版** | **槽位 + 浮层面都由对话插件渲染** | 两份实现合一；配置跟着界面一起归插件 |

**主动说话已整体移除**：它需要「有配置源」和「有调度入口」两件事，而配置搬给插件之后
宿主这边就没有配置源了。保留一个没有配置源的后台调度只会变成一个全仓没有调用点、
却仍被门禁引用的死家族，所以调度与手动入口一并删除。插件日后可以用
`llm.chat` + `pet.bubble` 自己实现类似功能。

## 插件与插件市场

插件是**第三方写的 HTML/JS/CSS**，不需要懂 Go 或 Wails；管理插件的是一个**独立的程序**
`PetPCPluginMarket.exe`（源码在 `tools/plugin-market/`），从桌宠的
**设置 → 插件市场 → 打开插件市场** 启动。桌宠本身只负责**运行**插件，不负责装、不负责授权。

### 为什么插件管理是一个独立程序

因为面板是固定 380×520 的矩形，窗口区域按它裁剪，**长不大**。
而市场是个工作面——左边两份列表（已装 / 市场）、右边详情与权限勾选、上面还有地址栏——
硬塞进面板的结果是权限行被右边界切断、地址框只剩半截、对话框和两个列表抢同一块滚动区。
拆成独立窗口后这些问题整体消失，细节见 `docs/plugin-market.md`。

市场窗口是 **980×700 且可缩放**，这一点后来多了一层用途：它**托管插件自己的界面**。
插件的界面是它自己的 HTML 文档，挂在市场的「该插件的设置区」里——
语音插件的配音工坊就是这么进去的（见「语音插件」一节），
所以插件要一个**工作面**时不必再单独出一个 exe。

| 程序 | 做什么 | 产物 |
| --- | --- | --- |
| `PetPC.exe` | 桌宠本体：**运行**插件、承载面板槽位、浮层面与常驻后台帧 | `build\bin\PetPC.exe` |
| `PetPCPluginMarket.exe` | 插件市场：浏览、安装、授权、改插件配置，并**托管插件自己的界面** | `build\bin\PetPCPluginMarket.exe` |

两个程序共用同一份数据目录，但**各写各的配置文件**：桌宠写 `config.json`，
市场写 `plugin-market.json`。市场**从不修改**桌宠的配置——连一个字节都不改，
所以卸载市场或换回旧版本不需要任何回滚步骤。

> **曾经有过第三个程序** `PetPCVoiceStudio.exe`（配音工坊）。语音变成插件之后它被删除，
> `tools\build-all.ps1` 还会把 build 目录里遗留的旧 exe 删掉——一个残留的二进制
> 是"用户仍能运行、且会写出已经没人读的旧库格式"的东西，比占地方严重得多。

### 一个插件长什么样

一个 zip，根目录放 `manifest.json` 和它的前端资源：

```json
{
  "id": "com.shixiansi.plugin-chat",
  "name": "对话插件",
  "version": "1.3.0",
  "author": "shixiansi",
  "description": "在面板里与桌宠旁和大模型对话的官方插件；自己的 AI 配置与密钥由自己保存。",
  "permissions": ["llm.chat", "pet.bubble", "pet.surface", "plugin.config", "storage"],
  "panel": true,
  "panelSlot": "chat",
  "surface": [
    { "dx": -75, "dy": -120, "w": 300, "h": 112, "radius": 14 },
    { "dx": -75, "dy": 208, "w": 300, "h": 56, "radius": 14 }
  ],
  "entry": "panel.html"
}
```

| 字段 | 含义 |
| --- | --- |
| `id` | 反向域名式的小写标识，同时是它在数据目录里的文件夹名 |
| `version` | 语义化版本，如 `1.3.0` |
| `permissions` | 它要哪些能力，安装时**逐项**由你勾选 |
| `panel` | 是否允许注册面板视图 |
| `panelSlot` | 面板视图占哪个槽位；`"chat"` 是桌宠的「对话」tab，留空则是插件自己的通用面板 |
| `surface` | 可选：浮在桌宠旁的矩形（最多 8 块），坐标相对**宠物左上角**（CSS 像素），可带圆角或 `ellipse`。上例的两块就是「宠物正上方 300×112 的回复卡」和「宠物正下方 300×56 的输入条」——`dy` 是负数即在宠物上方，`dy` 大于宠物高度即在下方；`dx: -75` 让 300 宽的框以 150 宽的宠物为中心 |
| `background` | 可选布尔：申请一个**无界面的常驻帧**，生命周期与进程相同。用于"没有界面打开时也要做事"的插件（语音插件听番茄钟结束，QQ 插件守着一根长连接）。**必须同时申请 `events` 或 `net.ws` 权限**，否则解析即失败——常驻帧的用途就是无人看着时收东西，不申请权限就是一个静默失效的配置 |
| `assets` | 可选：包内额外携带的文件（最多 32 项），每项都按相对路径校验。语音插件的 5 条内置音频就是这么随包走的；`audio.import` 只接受**在这里声明过**的路径 |
| `config` | 可选：它要你填的设置项（文本 / 数字 / 开关 / 密钥），由市场程序画出编辑界面 |
| `entry` | 面板视图、浮层面与**插件自己界面**的入口 HTML，相对插件目录 |

`panel`、`surface`、`background` **至少要有一个**——插件总得有个界面落点，或者至少有个宿主会挂起来的文档。

### 十六项权限

| 权限 | 允许它做什么 |
| --- | --- |
| `todos.read` | 读待办列表 |
| `todos.write` | 增删改待办 |
| `pet.bubble` | 让桌宠弹一句话 |
| `timer.read` | 读番茄钟阶段与倒计时 |
| `events` | 订阅待办与番茄钟的变化事件（关闭界面后也会送达） |
| `net.fetch` | 联网，**仅限** manifest 里 `netHosts` 声明的域名（`encoding: "base64"` 可取回二进制；可带一个受控的请求头集合，见下） |
| `net.credentials` | **以你保存的网站登录凭据发请求**（`net.fetch` 的第二道门：payload 点名一个 `config` 里声明为密钥的项，由宿主自己把凭据填进请求头；明文永远不进插件，插件只拿到 `{set, mask}`。单独声明它而没有 `net.fetch` 会被拒绝——一个解锁不了任何东西的开关正是这份清单要防的） |
| `storage` | 在自己的私有目录里存数据（键是**相对路径**：`media/stickers/bytes/<hash>` 这样的文件夹也算，见「插件数据放在哪」） |
| `pet.surface` | 显示自定义浮层面 |
| `llm.chat` | 调用**你已配置**的大模型（流式；可带 `history` 与 `system`，见下） |
| `plugin.config` | 保存你自己的插件配置（宿主存在插件私有目录里，插件之间互相读不到） |
| `audio` | 在自己的私有目录里**保存并播放音频**（最多 16 MiB 一条） |
| `net.ws` | 保持**一条**到声明地址的 WebSocket 长连接（`ws.open` / `ws.send` / `ws.close` / `ws.state`，来帧以 `ws.message` 事件送达） |
| `llm.borrow` | **借用**其它插件已配置的模型与密钥（`llm.profile` 报告借自谁；密钥永远不进插件） |
| `process` | **启动本机程序**（`process.launch {path, args}` → `{pid}`；只接受**绝对路径**、必须是存在且普通的 **`.exe`**、文件 ≤ 512 MiB、参数 ≤ 32 个且各 ≤ 512 字符、不含换行；启动后**不等待**、随即与桌宠解耦） |
| `plugin.share` | 在宿主的中转台上**与其它插件交换小消息**：只能写自己名下的键（`<自己的 id>/<名字>`），只能读 manifest 的 `shareRead` 里逐个点名的 `<别人的 id>/<名字>`，没有通配符；值 ≤ 64 KiB、最多 32 个键，并带着写入时间，好让对方忽略过期的活 |

**`process` 的风险面是这份清单里最大的，所以它是被围起来的而不是被信任的**：插件自己变不出
一个路径来——它只能启动**用户在插件设置里显式填了绝对路径**的那个程序，而且只有在用户**同时
打开了自动启动开关**时才会去启动（QQ 插件的 `clientPath` + `autoStartClient` 就是这样，默认
路径为空、开关为关）；扩展名限死 `.exe`，大小、参数个数与参数长度都有上限，换行一律拒绝；
子进程拿到的是空的标准输入输出，桌宠不等它、也不给它发信号，所以最坏情况也只是"启动了用户
指的那个程序"，读不到、写不了、删不掉任何东西。

**没有 `background` 权限**，这是刻意的：常驻帧由 manifest 的 `background` 字段申请、
由既有的 `events`（收宿主事件）或 `net.ws`（守一根自己打开的长连接）门控。门禁里有一条
「权限表与方法表逐项一致」的断言（每个权限都必须被某个方法使用、每个方法都必须命名一个
已声明的权限），一个只用来"批准后台运行"、背后没有任何方法的权限会正好违反它。

**`net.ws` 为什么必须由宿主持有连接**（而不是插件自己 `new WebSocket`）：

1. 协议端的 `access_token` 要走 `Authorization` 头，浏览器的 `WebSocket` **设不了请求头**；
2. 插件界面会被重建（更新插件、重渲染列表），而连接必须活过重建，否则"重建期间到达的那条
   群消息"就永远丢了；
3. `net.fetch` 的域名白名单是宿主的一个决定；页面自己开 socket 会让它变成装饰。

**`llm.borrow` 借的是"配置"，不是"密钥"**：借出方在自己的 manifest 里声明
`"shareLLM": true`（对话插件从 1.4.0 起这么做），借入方在**自己**的 manifest 里申请
`llm.borrow`——安装时你被问的是借入方那一条。运行时宿主读借出方的设置与密钥并发请求，
密钥不出宿主进程，借入方的 `storage.get` 也拿不到它。

**`llm.chat` 的 `history` 与 `system`**（1.4.0 起）：

- `history: [{role: "user"|"assistant", text}]`：宿主会裁剪（最多 32 条、合计 12000 字，
  超出丢最旧的、丢弃未知 role），再拼进请求——群聊的"每群各记一段"就靠它；
- `system`：给了它，宿主就**只**用这段提示词，**不再**注入桌宠的世界快照（待办、番茄钟）。
  这不是格式选择而是隐私边界：群聊的答案会被一屋子人看到，不该顺带发出你的待办清单。

**`audio` 为什么不是 `storage` 的加宽**：两者装的形状不一样。`storage` 的接口是**文本**
（插件自己的 JSON；字节也能进，但得像表情包那样编成 base64，代价是 4/3，而且 `storage.remove`
的键不许带点，文件连扩展名都没有），`audio` 是**二进制、几百 KB 量级**且要能直接播放。
只要记住一个设置的插件，不该为此被授予一个它永远不用的音频出口。

**没勾的权限，它一项也用不了**：每一次调用都在宿主侧被拒绝，而且**状态一点不变**——
不会写待办、不会弹气泡、不会发请求、不会存东西、不会发出声音。

### 四种界面落点，以及它们都不能违反的规矩

1. **面板槽位**：占满它声明的那块 380×520 区域（对话插件声明的 `panelSlot:"chat"` 就是
   面板的「对话」tab），内部滚动。它**不产生任何窗口几何**，所以不影响区域裁剪、不触发 resize。
2. **浮层面**：插件声明一个或多个矩形（上限 8 块），宿主把它们（夹回窗口边界后）并进窗口的裁剪区域，
   和气泡用**同一套机制**。前端只按宿主下发的矩形摆 iframe，自己不算尺寸。
3. **常驻帧**：`background: true` 的插件由桌宠挂一个**隐藏的** iframe
   （`#plugin-background`，`display:none`，所以不占位置也不吃点击），只在声明了该字段
   **且**已授权 `events` 或 `net.ws` 时才挂。它让插件在**没有任何界面打开**时也能收到东西——
   番茄钟到点与提醒触发都不会等用户先打开面板，QQ 插件的群消息同理。
   **每个合格插件各一帧**（按 pluginId 同步：新出现的挂上、不在了的摘掉），
   因为两个常驻插件的界面是两个文档，共用一个帧就等于谁后装谁把前一个挤掉。
4. **市场托管**：插件的界面可以由**市场程序**在自己的窗口里挂起来（语音插件的配音工坊）。
   这时插件在桌宠这边可以只有 `background`，不占任何面板落点。
   两个程序共用同一套资源路由与同一个调度器，只有**能力表不同**：
   市场没有待办、没有番茄钟、没有宠物，所以 `todos.*`/`timer.*`/`bubble.say`/`surface.*`/
   `llm.chat`/`events.subscribe` 在它那里会回答「本程序不支持该方法」——
   这个回答比一个共享的表更诚实，后者会让插件在错误的地方失败得更深。
5. **沙箱**：插件的界面跑在 `<iframe sandbox="allow-scripts">` 里——**没有**
   `allow-same-origin`，所以它是不透明源，读不到宿主页面、读不到 cookie、读不到存储。
   它只能 `postMessage`，而每一条都经过宿主**唯一一个**受权限门控的调度入口。

窗口**永远不会 resize**：插件的浮层面只改「可见区域」，不改窗口宽高。
这也意味着**插件面板矩形固定 380×520**，想要更大的界面就挂到市场窗口里，
或者像市场那样另起一个独立程序。

### `net.fetch` 的 `encoding` 与体积上限

正文默认按文本返回。要取**二进制**必须显式说 `encoding: "base64"`，因为文本形式是**有损**的：
Go 的 JSON 编码器会把非法字节替换成 U+FFFD，一个 WAV 于是"大小看着对、播出来是噪声"。
`base64` 返回的是原始字节的 base64，插件解码后交给 `audio.save`。

**单次响应的上限是 8 MiB**（1.12 起；之前是 1 MiB 且**静默截断**）。超限时返回
`truncated: true`，插件据此知道"这段字节不完整"——QQ 插件的图库正是被旧上限坑过：
317 张表情包里 156 张正好是 1 MiB 的 base64，也就是只存下了动图的前几帧。

### 市场地址

市场是一个**独立的公开仓库**：[`pet-pc-plugins`](https://github.com/shixiansi/pet-pc-plugins)
（本仓是私有的）。地址框在**插件市场程序的顶部**，默认走 **gh-proxy.com 镜像**
指向 `raw.githubusercontent.com`——因为后者在国内不通（`docs/genshin-tts.md` 里有同样的处理）。

顶部那一行现在只有**控件**，没有再写一遍「插件市场」：窗口标题栏已经有那四个字，页面重复一遍
只是把地址栏挤窄。最左边是**深/浅色开关**（图标画的是点下去会得到的那个），主题存在
`plugin-market.json` 的 `theme` 里，重启还在；插件自己的界面（iframe 里那份文档）**不受影响**，
它画的是它自己的配色。

- 地址留空 = **强制使用内置示例源**（随 exe 分发的那份），用于离线或镜像不可达时。
- 远端不可达时会**回退**到内置源，并在界面上说明「市场不可达，正在使用内置示例源」——
  这两种情况的提示是分开的，因为「你没填地址」和「你填的地址没响应」要修的地方不一样。
- 地址值存在**市场程序自己的** `plugin-market.json` 里，不写桌宠的 `config.json`。
  首次运行时它会从桌宠的旧设置里**播种一次**（读得到就用，读不到就用内置源），此后各管各的。

### 安装流程

`下载 zip → 校验 sha256 → 解压到数据目录 plugins/<id>/ → 你逐项授权 → 启用`

- **sha256 不匹配就拒绝安装**，已装集合**不变**；解压时逐项校验条目路径，拒绝 `../` 与绝对路径。
- 市场条目声明的权限必须与包内 `manifest.json` **逐项相等**，否则拒绝——你在界面上看到的
  就是它真正要的。
- **安装不等于启用**：装完是停用状态，你显式启用它才跑。

### 插件数据放在哪

| 路径 | 内容 |
| --- | --- |
| `%AppData%\PetPC\plugins.json` | 已装索引（版本、启停、已授权权限） |
| `%AppData%\PetPC\plugins\<id>\` | 插件解压后的文件（含 manifest 里 `assets` 声明的包内文件） |
| `%AppData%\PetPC\plugin-data\<id>\` | 插件的私有存储与配置（`storage.*`、`config.*` 与 `audio.*` 唯一的可写落点） |
| `%AppData%\PetPC\plugin-data\<id>\audio\<name>.wav` | 插件自己的音频（语音插件的台词片段与内置音频都在这儿） |
| `%AppData%\PetPC\plugin-data\<id>\share\<name>` | 跨插件托盘里**它发布的**那份值（宿主写，别人只能读） |
| `%AppData%\PetPC\plugin-market.json` | **插件市场程序自己**的偏好（地址、上次选中的插件、窗口尺寸、深/浅主题） |

**`storage` 的键是相对路径，不是文件名**（1.11 起）。`media/stickers/bytes/790ed6cc` 会写到
`plugin-data\<id>\media\stickers\bytes\790ed6cc`，父目录由宿主建好；每一段仍然只能是字母、
数字、`_`、`-`（最多 4 段、整条 200 字符），所以 `.`、`..`、盘符、反斜杠这些拼法一律被拒，
键永远出不了自己的目录。四个配套方法：`storage.dir` 的 `sub`（把 `media\video\` 这类子目录
的绝对路径交给插件启动的 curl / ffmpeg）、`storage.stat`（多大）、`storage.list`（这个文件夹
里到底有什么——「清理自己的垃圾」没有它就做不到）、`storage.move`（在自己的目录里改名——
迁移三百个文件因此是零拷贝）。为什么不是文件名：一个 QQ 插件把两百张表情包、
两个 24 MB 的视频和每群一份往来全写进根目录，打开 `plugin-data` 谁也看不出哪个能删。

**卸载**会同时删掉这三处属于它的东西，包括私有存储与密钥——装了不想要就干净回到原状。

### 端到端冒烟（人工可复现）

按顺序走一遍，每一步都有可观察的结果：

| # | 操作 | 应该看到 |
| --- | --- | --- |
| 1 | 双击 `build\bin\PetPC.exe` | 桌宠出现在屏幕边上 |
| 2 | 单击桌宠打开面板，切到**设置**，点**「打开插件市场」** | `PetPCPluginMarket.exe` 独立窗口出现，左侧已装列表读出桌宠那边的插件 |
| 3 | 在地址框里确认镜像地址，点「刷新」 | 市场列表出现条目；若镜像不通则显示「市场不可达，正在使用内置示例源」 |
| 4 | 选中「对话插件」，点「安装并授权」 | 权限表逐项列出它要的权限，**每项都是未勾选的**，确认按钮**是灰的** |
| 5 | 勾上需要的权限并确认 | 状态走过 `下载 → 校验 → 解压 → 授权`；插件出现在左侧已装列表 |
| 6 | 在右侧「配置」里填好 AI 配置与 API Key，点保存 | 显示「已保存」；关掉市场再开，值还在，而 Key 只显示为掩码 |
| 7 | 关掉市场，回到桌宠切到**「对话」**tab | 对话插件的界面占满这块 380×520 区域（不再有「对话插件还没装好」的提示） |
| 8 | 双击桌宠 | 插件自己的浮层面出现：回复卡在宠物**正上方**、输入条在**正下方**，两块均以宠物为中心（300 宽）；回复卡里只有**最新一条回复**，没有历史提问；**窗口大小和位置一点没变**，面板之外是桌面 |
| 9 | 在浮层里发一条消息 | 回复**逐字出现**（宿主把 `llm.chat` 的流式增量经 `pet:plugin-event` 路由给这个 iframe） |
| 10 | 在市场里停用或卸载这个插件 | 回到面板的「对话」tab，槽位显示「对话插件还没装好：在设置里点「打开插件市场」装上并授权它。」；双击桌宠也不再弹浮层 |
| 11 | 在桌宠数据目录确认旧数据 | 旧的 `llm*` 设置与 `llm-history.json` / `llm-usage.json` / `llm-key.bin` 已被搬进 `plugin-data/com.shixiansi.plugin-chat/`，原文件改名 `.bak` 保留 |
| 12 | 装「语音插件」并授权（含 `audio` / `events` / `net.fetch`） | 插件出现在已装列表；桌宠这边**不新增任何面板 tab**（仍然是 4 个） |
| 13 | 在市场里选中「语音插件」 | 右侧出现它自己的**配音工坊**界面：左栏角色、右栏五条台词，就是这个插件的 `panel.html` 被市场挂起来的那一份 |
| 14 | 删掉 `%AppData%\PetPC\voice\user\voice-user.json` 之外什么都没做，重启桌宠 | `plugin-data\com.shixiansi.plugin-voice\` 下出现 `audio\*.wav` 与 `voice-settings`；**`voice\user\` 原样还在**（只读来源，回滚路径） |

第 7、8 步各覆盖一条桥接链路：前者是 **ready → init** 握手（插件在收到 `init` 之前
不能猜自己的权限），后者是**浮层几何只算一次**（同一个矩形既喂给窗口区域也喂给 iframe 定位）。
第 12–14 步覆盖**常驻帧**与**市场托管**：插件在桌宠侧只占一个隐藏帧，界面却在另一个程序里。

> 大模型那一步需要先在**插件市场的「设置」表单**里填好 key；没配好时插件会提示
> 「还没配置大模型」，而不是静默失败。

### 自己写一个插件

1. 在 `pet-pc-plugins` 仓里建 `plugins/<你的插件id>/`，放 `manifest.json` 与资源；
2. 跑 `tools/package.ps1`——它会打出 `dist/<id>-<version>.zip`、实算 sha256 并回写 `index.json`；
3. 提交 `dist/` 与新的 `index.json`；
4. 在市场程序的地址框里指向你自己的仓（改一处即可，见该仓 README）。

插件的样式**不许**用 `box-shadow` / `filter` / `text-shadow` / `transform`：
这些装饰会画到盒子外面，而盒子之外就是用户的桌面。

## 语音插件

桌宠说**固定台词**——番茄钟结束、待办提醒弹出时，用游戏角色的声音说一句预录好的话。
完整文档见 `docs/voice.md`。

**语音是插件，不是宿主内置功能**（`com.shixiansi.plugin-voice`）。
台词、角色库、三条开关、逐句渲染，全都归它；桌宠只负责**宣布事实**与**播放音频**。

| 台词 | 什么时候说 |
|---|---|
| 专注时间结束了，起来活动一下吧。 | 专注阶段结束 |
| 休息结束了，我们继续吧。 | 休息阶段结束 |
| 有些事情到期了，记得看一下。 | 有今天到期的待办 |
| 有事情已经逾期了，记得处理一下。 | 有待办逾期 |
| 现在没有待办，好好休息吧。 | 提醒触发但列表为空（需显式开启） |

5 条，合计 **569 KB**，作为 manifest 的 `assets` **随包分发**，音色是**可莉**。
装完即用，不需要联网、不需要装 GPT-SoVITS、不需要先渲染任何东西。

### 宿主这边只剩两样东西

语音搬进插件之后，宿主**不知道什么叫"台词"**。它只提供两条通用机制：

- **两个边缘事件**（`events` 权限）：`timer.phaseEnded`（`{phase:"focus"|"break"}`）与
  `reminder.fired`（`{due,overdue,total}`）。两者都**只带事实、不带措辞**——
  该说什么、用谁的嗓子、要不要出声，全是插件的事。
  > 它们与 `timer.changed` 的区别很重要：后者是**状态广播**（倒计时一动就发），
  > 想知道"专注刚刚结束"的插件得自己记住上一帧再判断跳变 —— 也就是每个插件各自
  > 重算一遍宿主**已经算出来**的结论。这两个事件直接给出结论。
- **`audio.*` 能力**（`audio` 权限）：`save` / `list` / `remove` / `play` / `stop`，
  外加 `import`（把 manifest 的 `assets` 里声明过的包内文件复制进插件自己的音频目录）。
  播放走 `internal/desktop` 的 winmm 封装，按**路径**播放，和桌宠历史上一样。

插件的三个开关（总开关 / 朗读番茄钟 / 朗读待办提醒）与「每一句采用哪一版」都住在
插件自己的 `storage` 里。**桌宠的 `config.json` 里已经没有 `voice*` 字段了。**

> 为什么 `import` 要存在：播放器工作在插件的**私有目录**上，而包是**只读**的——
> `audio.play` 收的是名字，不是包内路径。插件当然可以自己 `net.fetch` 自己的资源
> （资源路由带 `Access-Control-Allow-Origin`）再把字节交给 `audio.save`，
> 但那样整段音频要**过两遍桥**（先 ArrayBuffer、再 base64）。
> `import` 让宿主直接复制文件，插件只报一个名字。

### 配音工坊：在市场窗口里，不在桌宠面板里

工坊是**这个插件自己的一个 HTML 文档**，由**插件市场程序**直接铺在详情区里（一个沙箱 iframe，
没有外框也没有标题——文档就是那块地方）：

桌宠面板 → 设置 → **打开插件市场** → 选中「语音插件」→ 右侧下方就是工坊。

（详情区右侧现在是：顶部一行 `权限` / 开关 / `设置` / `卸载`。`权限` 点开是**贴着按钮的悬浮层**，
`设置` 点开是**弹窗**——两者都不占布局，所以不会把工坊往下挤；插件自己的界面装在面板里，
装好并启用就**直接展开**，占满剩下的高度。）

两栏照旧：**左栏角色**（点一下即切换），**右栏五条台词**（试听 / 生成 / 用这版 / 清除，
外加「整套换成这个角色」）。

> **为什么挂在市场而不是面板**：面板是固定 380×520 的矩形，窗口区域按它裁剪，**长不大**；
> 而工坊是个工作面（5 条台词 × 每行多个版本）。市场窗口是 **980×700 且可缩放**，
> 塞进去不用重排。这也是插件机制的一条通用能力，不只对语音有用：
> **插件的界面可以由市场托管**，所以插件要工作面时不必再单独出一个 exe——
> 上一版的 `PetPCVoiceStudio.exe` 就是这样被删掉的。

### 一条核心规则：生成 ≠ 采用

```
生成一版 → 存起来，可以听、可以比、可以留     ← 不影响桌宠
采用一版 → 之后这一句就说这一版              ← 改变这一句念哪一版
点角色   → 桌宠立刻改用那个音色              ← 改变"用谁的嗓子说"
```

版本**只增不删**，所以「这一句读得不好」可以**只重生成这一句**，
反复挑到满意再采用，已经好的那几句**完全不受影响**。
「清除采用」和「停止」都是**可逆**的，重置**不删**已生成的音频。

> **「点角色」和「采用」是两件事**：角色决定用谁的嗓子，采用决定这一句念哪一版。
> 桌宠真正出声要两者都满足 —— **当前角色名下有这一句已采用的版本**。

### 引擎由你自己启动

角色的声音由**本机 GPT-SoVITS** 合成（默认 `D:\GPT-SoVITS`，地址默认
`http://127.0.0.1:9880`）。**插件不会替你启动它**——这是明确的取舍：
"启动一个进程"这项能力交给任何已装插件，等于给它们任意代码执行。

所以工坊顶部的状态指示器只会告诉你**服务在不在**，连不上时给出启动命令，
点「生成」在引擎未运行时**不会发请求**。

**播放永远不需要引擎**：包内自带的 5 条音频装完即用；
引擎只在你想**换角色**、或重新渲染某一句时才需要。

> 这和当初被停用的**实时合成**（`_archive/README.md`）是两件事：
> 这里每条台词**只合成一次、之后永久复用**，所以"慢/重/不稳定"三条都不适用 ——
> 而**不稳定反而变成了有用的东西**：生成多版，挑最好的那一版。

### 老语音库会一次性迁移

上一版把语音库放在 `<数据目录>\voice\user\`（`voice-user.json` + `clips\*.wav`）。
首次启动时 `plugins.MigrateVoiceData` 会把它**复制**进
`plugin-data\com.shixiansi.plugin-voice\`：开关三项、角色表、**每一个 take**
（不只当前角色的——工坊的全部意义就是在角色之间切换，只留一个正好毁掉其余的渲染），
以及每条台词当前采用的那一版。片段按 `audio\<line>-v<NNN>.wav` 命名。

三条性质与对话迁移相同：**只读来源**、**先写完再打标记**、**标记一存在就不再读**。

> **但来源不改名、不删除**（对话迁移会把原文件改成 `.bak`，这里不会）。
> 差别在**重建成本**：聊过的历史再聊一遍就有了，而这些片段每一条都是几分钟的
> GPU 时间，且需要跑着 GPT-SoVITS 才能重做。它们一共几 MB，
> 而"猜错了"的代价不可恢复 —— 所以原样留着，迁移只做复制。
>
> 迁移也**绝不采用一个片段不在磁盘上的版本**：指向一个不存在的文件会让插件
> **一声不出**，那比"采用了次一版"糟得多，因为它看起来就是功能坏了。
>
> 第一次启动时插件可能还没装（没有可读的私有目录），此时迁移是**静默的 no-op**，
> 不打标记；装好插件再重启一次就会补上。

## QQ 群聊插件

把大模型接进 QQ 群：**群友 @ 它**，它就用对话插件那套模型配置回答，每个群各记一段上下文。
插件 id `com.shixiansi.plugin-qq`，设计文档见 `openspec/changes/qq-chat-plugin/`。

```
Yogurt / Milky 协议端  ──ws 长连接──▶  宿主（net.ws）  ──ws.message──▶  插件常驻帧
                                                                        │
                  llm.chat（借用对话插件的模型配置）◀────────────────────┤
                                                                        │
                  net.fetch POST /api/send_group_message ───────────────▶ 群里
```

### 为什么连接不在插件里

Milky 的事件是**服务端往客户端推**的，`net.fetch` 那种一问一答收不到；而让插件页面自己
`new WebSocket` 也走不通：`access_token` 要走 `Authorization` 头（浏览器 WebSocket 设不了
请求头）、界面会被重建而连接必须活过重建、页面能自己开 socket 就等于把 `net.fetch` 的
域名白名单变成装饰。所以宿主提供 `net.ws`：**连接、重连、心跳、白名单、停用即断**都在 Go 侧，
插件只拿三个动词和一个事件流。

- `ws.open {url, token}` → 立即返回，之后的状态都是 `ws.state` 事件（`connecting` / `open` /
  `error` / `closed`），失败按 1→2→4→8→15→30 秒退避重连；
- `ws.message {text}`：一帧一条，原样交给插件——**协议由插件解释**，宿主不懂 Milky；
- 30 秒心跳顺带当**存活检测**：插件被停用时连接会自己断，不会留下一个"用户已经关掉、
  却还在收群消息"的会话；
- 地址必须在 manifest 的 `netHosts`（或那个 `hostWhitelist` 设置项的当前值）里，`ws/wss` 之外
  的 scheme 直接拒；`ws.state` 里的 url **查询串一律打码**（token 常常就写在
  `?access_token=` 里，那串东西会进面板和截图）。

### 模型配置只填一次

QQ 插件默认**借用对话插件的模型配置与密钥**（`llm.borrow` + 借出方的 `shareLLM`）。
你在市场里给对话插件填好地址、模型、Key，装 QQ 插件时确认一次"可以用别的插件的模型配置"，
以后换模型/换 Key 只改一处。想用另一套，就在 QQ 插件自己的 `llmBaseUrl` / `llmApiKey` 里
填上——**自有配置优先**，这也是"停止借用"的唯一开关。密钥始终留在宿主进程里。

### 它怎么决定说不说话

| 配置 | 默认 | 作用 |
| --- | --- | --- |
| `server` | `127.0.0.1:3000` | Milky 协议端地址（`host:port`，也可写整条 `http://…/前缀`） |
| `accessToken` | 空 | 同时用于 WS 的 `access_token` 查询参数与 API 的 `Authorization` 头 |
| `atOnly` | 开 | 只回应 @ 机器人；关掉之后由下一项决定它插不插话 |
| `replyChance` | 0 | **非 @ 消息的插话概率**（百分比）：0=不插话，50=一半消息会接话，100=每条都回。只在 `atOnly` 关掉时生效；被 @ 或命中前缀时永远 100% |
| `proactiveMinutes` | 0 | **主动开口**：平均每隔多少分钟自己说一句（0=关闭）。是随机间隔而不是定时：每分钟抽 `1/N` 的概率，所以平均 N 分钟、实际间隔不规律；只在最近 N 分钟内有人的群里开口 |
| `prefix` | 空 | 前缀触发（例如 `#问`），留空即关闭 |
| `groupAllow` | 空 | 只在这些群生效，留空=所有群 |
| `contextTurns` | 8 | 每群记住几条往来（宿主另有 32 条 / 12000 字的上限） |
| `replyMaxChars` | 300 | 回复字数上限 |
| `cooldownSec` | 5 | 同一群最小间隔，防止刷屏 |
| `quoteReply` | 开 | 引用提问那条消息回复 |
| `clientPath` | 空 | **协议端可执行文件**的绝对路径（例如 `E:\lagrangeV2\yogurt-windows-x64 (1)\yogurt.exe`）。留空=不代管，需要你自己开 |
| `clientArgs` | 空 | 启动协议端时附带的参数，**空格分隔**（可留空） |
| `autoStartClient` | 关 | 连不上协议端时**自动启动**上面那个程序。只在配了路径时生效，而且每次页面只拉起一次 |

**协议端的自动启动是可选的、默认关的**：连接前插件先用 `net.fetch` 打一次
`/api/get_login_info`（1.5 秒超时）看协议端在不在——有响应就照常连；没响应、且你填了路径并
打开了开关，才调 `process.launch` 启动**一次**，然后等 2 秒再走原来的 WebSocket 连接与退避
重连。日志会分别写清"没开启自动启动""路径为空""已启动协议端客户端（pid N）""启动客户端失败：…"，
因为用户看到的"未连接"背后是这四件完全不同的事。

另外三条不写在配置里，但代码里是硬规则：**它自己发的消息绝不触发自己**（协议端会上报机器人
自己的消息，不挡就是自问自答的循环）、**私聊不处理**、**模型不可用只在日志里说，不在群里说**
（群里不该被告知机器人是怎么配的）。

**带视频/语音的消息一律不回**（1.12 起）：画面和声音它一点都收不到，却会顺着"有人 @ 我"照常作答，
于是产出"这视频挺有意思""你声音真好听"这类凭空的话——宁可沉默。判据放在触发规则**之前**：消息里
只要有 `video` / `short_video` / `record` / `voice` / `audio` 段（引用里带着也算），这条就不回答，
日志每群 10 分钟说明一次（带上实际的段类型，方便发现别的协议端点名字）。它仍然会进背景聊天缓冲，
占位符写的是 `[视频（画面看不到）]` / `[语音（听不到）]`，所以攒批那一路也不会把它当成看过、听过的
东西去接话。

**戳一戳会被回一句**（1.12 起）：这是冲它来的动作，不是背景。`group_poke` / `friend_poke` / `nudge`
事件，或消息里带 `poke` 段，只要目标指向它，就在群里回一句短话并 @ 戳的人——**不调模型**
（连点的人不值得一次调用），每群 60 秒最多一次。

两种反应都是**概率**，都在设置里填，没有"总是/从不"的开关：

| 设置 | 默认 | 行为 |
| --- | --- | --- |
| `pokeBackChance` | 40 | 被戳时"戳回去"的概率（剩下的概率是回一句话）；协议端不支持戳人时自动改成回话，不会沉默 |
| `quoteChance` | 60 | 回答时**引用那条提问**的概率（0=从不引用，100=每条都引用） |
| `stickerChance` | 30 | 回完一句话后**随机再贴一张表情**的概率（0=从不贴，100=每次都想贴），仍受每群冷却约束；模型点名要发的那张不受此概率限制 |

戳回去优先用协议端的 `send_group_poke`（试到 `group_poke` / `send_poke`，都不支持就回话并记一行日志）。
**戳一戳只回话、不贴表情**：它是高频动作，若这里也贴图，表情冷却会被它吃掉，真正回答提问时反而贴不出来。

**它什么时候说话，三档**：被 @ / 命中前缀 → 一定回；`atOnly` 开着 → 其他消息一律不理；
`atOnly` 关掉 → 由 `replyChance` 抽签。三档而不是一个开关，是因为"偶尔插一句"和"每条都回"
是两件事，而中间那档才是通常想要的：开关只能二选一，配上 5 秒冷却就变成"每五秒回一条"，
看起来像坏了而不是像话多。

**同一个群一次只答一条，其余排队**（1.12 起）：一场群里两个人前后脚 @ 它，第二条不会因为
"上一条还在回答"被丢掉，而是排进队列（每群最多 4 条），答完第一条再按 `cooldownSec` 的间隔
接着答。冷却期内的新消息也走队列而不是丢弃——排队是为了"不丢话"，不是为了连环轰炸。
不同群互不阻塞：两个群的两个问题会同时在飞。

**引用提问也是概率**（`quoteChance`，默认 60，0=从不引用、100=每条都引用）：以前是个开关，
真机上"每条都引用"像复读机，"从不引用"又接不住"你说的那句"，中间那段才是想要的。掷骰子的地方
只有 `sendGroupReply` 一处——主动开口、攒批插话、定时提醒传的都是"没有可引用的消息"，不会引用。

**主动开口**同理，但它是**平均间隔**：每 60 秒抽一次 `1/N`（N = `proactiveMinutes`），
所以平均 N 分钟说一句、间隔不规律；而且只在最近 N 分钟里有人说过话的群里开口——
没有话题就沉默，一个对着空群自说自话的机器人正是大家会删掉的那种。

**攒批自主插话（P3，1.12 起）**是另一条路：没人叫它时，它也会看群里的聊天，自己决定要不要接一句。
关键在于**每条消息都不花一次调用**：

```
群消息进内存缓冲（0 次请求）
   ↓ 每 15 秒本地过一遍闸（全过才发请求，且一批只发一次）
① 距上次评估 ≥ batchWindowSec（默认 120 秒）
② 缓冲里 ≥ 3 条新消息（冷清的群因此永远不触发）
③ 本群这一小时 < batchMaxPerHour（默认 8 次，硬上限）
④ 社交能量 > 0.35（累了就不多想事）
   ↓
一次调用同时覆盖那一批（最多 10 条）→ 模型要么 {"silent":true}（大多数情况），要么说一句
```

所以花费的上限是**窗口**给的，不是消息量给的：90 条消息/小时的群，最多 8 次调用/小时，而不是 90 次。
被 @ 时会顺手把缓冲里的"刚才在聊"作为上下文带进同一次调用（不额外花钱），并且这批就不再重复消费。
攒批的提示词比回答时短得多——不带表情候选、不带待收藏，只带人设、规则、这个群的记忆要点和能量状态。

**它也可以不说话**（1.12 起）：模型可以在回答里只输出 `{"silent":true}`，这次就一个字都不发，
但记忆和能量照常更新。触发规则没变（还是"被 @ / 命中前缀才答"），变的只是"被叫了也可以敷衍"
——`energyBaseline` 越低，它越倾向这样。参考的是
[nonebot-plugin-aigf](https://github.com/Funny1Potato/nonebot-plugin-aigf-master) 的社交能量
思路：能量高时话多、被 @ 加成，说完一句按字数扣，形成一个"话多→累了→安静→恢复"的循环。

### 记忆与观测

**插件的代码是一个入口加一组模块**（1.12 起）：`panel.html` 按顺序加载 `lib/*.js`，最后是
`app.js`。用的是**经典 script**（不是 ES module），因为经典 script 共享同一个全局作用域——搬家
时一个字的逻辑都不用改；而 ES module 会让"把脚本 eval 进 jsdom"的测试方式失效。

| 文件 | 管什么 |
| --- | --- |
| `lib/core.js` | 文档骨架、DOM 引用、宿主桥（`request`） |
| `lib/store.js` | 私有目录的键与布局、1.10→1.11 的搬迁、每次启动的整理 |
| `lib/state.js` | 运行时状态、纯函数工具、`note`/persist、Milky API |
| `lib/inbound.js` | 收到的消息 → 一次回答：段扁平化、@ 判定、引用展开、视频闸、每群排队 |
| `lib/importer.js` | 主人私聊导入表情包（识图 + 存字节 + 残图就地补齐） |
| `lib/protocol.js` | 尾部 JSON 围栏协议（`splitDirectives` / `parseReply` / 字段白名单） |
| `lib/reminders.js` | 定时提醒与"@群主/@全体成员/我/QQ 号"的解析 |
| `lib/memory.js` | 群记忆、群友卡片、社交能量 |
| `lib/proactive.js` | 主动开口、攒批自主插话、提示词与预算 |
| `lib/bili.js` | B 站联动（下载、合并、发送、投稿推荐） |
| `lib/admin.js` | 群内命令、协议端自动启动、连接 |
| `lib/workshop.js` | 市场面板：状态卡、群列表、记忆卡、表情包、待收藏 |
| `lib/stickers.js` | 发表情、自动收藏、残图补标记与群历史找回 |
| `app.js` | 入口：宿主消息泵、`window.__qq` 测试接缝、启动接线 |

两条硬约束（踩过就知道）：

1. **新文件必须写进 `manifest.json` 的 `assets`**——打包脚本只固定带
   `manifest.json/panel.html/app.js/style.css`，其余全靠这个清单（voice 插件就是这么带音频的）；
2. **加载顺序要写在 `panel.html`**，测试从那里读同一份清单（不另存一份，否则加文件时必然漏）。

**今日用量与上限**：宿主把每个插件的模型调用计数写在 `llm-usage` 里，工坊的状态卡读它显示
每群的往来存在插件私有目录的 `history/<群号>`（`storage.set`），**每次回答前重读**——因为
市场窗口里能"忘掉这个群"，缓存在内存里就会把用户刚删的东西悄悄写回去。宿主另外维护
`state/status` / `state/groups` / `state/log` 三个文件，市场里打开的同一个 `panel.html`
读它们画状态页：连接状态、机器人账号、模型来源（借自谁）、每个群的往来条数与清除按钮、
社交能量与记忆条数、最近 20 条日志。

**长期记忆**（1.12 起）：模型在一次回答的尾部顺手交回 `remember` / `forget` / `friend` 指令，
落成三份小文件——`memory/<群号>/notes`（这个群值得记的事，≤20 条）、
`memory/friends/<QQ号>`（群友卡片：昵称、别名、一句话）、`state/energy/<群号>`（社交能量）。
它只把**当前发问者**的卡片和这份 notes 拼进 system（宿主给的上限是 4000 字符），
所以是"记得你"而不是"记得所有人"。

**主动 @ 与定时提醒**（1.12 起）：模型可以点名要 @ 谁——正文里写 `@昵称`（插件用群成员名单换成
真正的 @ 段），或者在围栏里写 `"at":["时先思"]`。**段类型是 `mention`**（Milky 的 @ 段就叫这个名字，
写成 `at` 协议端会静默丢掉，真机上就吃过这个亏）。群友说"每天 5 点 at 我一下"这类话时，它还可以
下发一条**定时提醒**：

```json
{"remind":[{"time":"17:00","every":"day","text":"该下班了","at":"时先思"}]}
```

- `time` 必须是 `HH:MM`（本地时间），`every` 是 `day`（每天）或 `once`（只一次），`at` 可省略
- 插件存进 `state/reminders`，每 30 秒对一次表，到点发一条带真 @ 的消息；**触发时不调模型**（文本早就存好了），所以不花钱
- 每群最多 5 条；一天只发一次；只看 `HH:MM` 相等，**不补发**错过的（机器人半夜关着，第二天早上不该收到昨晚的提醒）
- 工坊的记忆卡里能看到并删掉这些提醒；`#状态` 也会报一句

**记忆可以人工改**：工坊的群列表里，「记忆」那一格是个按钮——点开是那个群的记忆卡，逐条列出，
可以单条删掉，也可以自己补一条（去重按前 12 字、遵守 `memoryNotesMax` 上限）。改完立刻生效：
机器人每次回答前都会重读同一份文件。在此之前唯一的人工动作是「忘掉这个群」，好的一起扔——
模型把"某人下周出差"记到一个已经搬走的人身上时，这个区别很要命。

**这个协议是"必须"的，不是"可选"的**：提示词里写的是"每条回复都必须以唯一一个 ```json 围栏
结尾，没有要记的就写 `{}`"。1.12 最早写成"需要时才带"，真机上一整晚的回复里**一个围栏都没有**
——记忆永远是空的、表情永远走随机兜底、也从不沉默。所以现在：

- 模型原话会留一份在 `state/probe`（最近 3 条），工坊的状态卡里能直接看到「最近一次模型原话」，
  一眼分清是"模型没写"还是"插件没认出来"；
- 漏了围栏时日志会写一句「模型没带尾部围栏，这次记忆/表情/沉默都没生效」（每群 10 分钟一次），
  不会刷屏但一定看得见；
- 群列表的「记忆 / 能量」两列：机器人只在回答后才写进索引，说不了几句话就一直是空的，所以工坊
  对索引里没有的那些**自己读文件**（只读最近 12 个群）。

**表情包**（1.12 起）：模型不再只能说"我想发个开心的"，而是从候选里挑具体一张
（`{"meme":"<hash>"}`）；候选按"和这句话的字面重合度 + 用得少的优先"筛出
`stickerCandidateMax` 条（317 张全塞进 prompt 要 ~4K token/次，筛完只要 ~300）。
**这一步是纯本地的**：只用库里已有的 `tag` / `description` / `keywords` 排序，不调模型、
更不调识图。

识图只在两处发生，而且都先按内容 hash 查过"这张认不认得"：

| 场景 | 会识图吗 | 说明 |
| --- | --- | --- |
| 主人私聊导入表情包 | 会 | 导入时打 tag + 描述；同一 hash 已入过库就直接跳过 |
| 群里出现从没见过的新图 | 会 | `autoCollectStickers`，每群每小时最多 3 张，超出就不收；关掉开关完全不碰 |
| 回复时挑表情 / 再次导入同一批图 | 不会 | 前者纯本地排序，后者在识图之前就按 hash 跳过了 |

**待收藏是一条"有出口"的队列**（10 格）：群里出现新图时它会下载 + 识图，存进
`media/stickers/pending/`，下一次说话时把描述摆给模型，由它在围栏里用 `save_meme` 决定收不收；
工坊的表情包卡片里也有一个**收件箱**，缩略图 + 描述 + 「收进图库 / 丢掉」两个按钮。
排队满 10 张时**不再识图**——真机上这一条是花钱不产出的典型：满了照样识、再把最旧的挤掉，
318 行里 `collected` 一直是 0。

**内容安全拦截是单独处理的一类失败**（1.12 起）：服务商把某次请求判成敏感内容时
（`The request contains sensitive content`），说明**这轮上下文里有它不接受的词**——真机上就是
群里有人让机器人"把脏话记下来"，那句话与它的复述一起进了 `history/<群号>`，于是之后每一条请求
都带着它们、一律被拒，机器人哑了好几分钟。

它**自己就会恢复，不需要谁去群里发指令**：

1. 先按阶梯缩小上下文重试——丢一半旧往来 → 只留两轮 → 完全不带（历史本来就空时只试最后一档，
   因为那时被拦的多半是系统提示本身），首次成功的那一档**写回磁盘**，从此不再带那些话；
2. 十分钟内刚被拦过就直接用最小上下文，不再先白跑一次失败请求（失败也计费）；
3. 三档都失败才放弃，日志里的建议是**工坊里点「忘掉这个群」**（一次点击，也清 `notes` 与
   `history/<群号>`），而不是让人去敲命令；
4. 不是内容安全的错误照旧原样抛出，不会被这套兜底掩盖。

最小上下文 = 人设 + 规则 + 这一句提问，不含历史、群记忆、群友卡片和表情候选。进提示词的群名、
名片、记忆、描述都会先去掉不可打印字符（QQ 的群名里真的会有 `\u0011` 这类东西）。

**「残图」**：被宿主下载上限截断过的表情包看起来完全正常，只是动图只剩前几帧。工坊的表情包卡片
会把这类单独标出来——摘要里写「其中 N 张被截断过」，筛选里多一项「残图（被截断）」，格子用虚线
描边，那个视图里还有一个「删除这 N 张残图」（点两下确认：沙箱化的 iframe 里没有 `confirm()`）。
1.12 之前导入的那批没有标记，插件靠**字节数**认：正好 `1,398,104`（= 1 MiB 的 base64）就是被切过的，
每次启动用一次 `storage.list` 补标记（真机上 317 张里认出了 156 张）。

补图有两条路，都不需要你手上有原件：

1. **「从群历史里找回」**（同一个视图里的按钮）：残图缺的是**数据**，不是描述，所以它不重新识图，
   而是去群历史里把图重新下回来、按**前 48 KB 的前缀指纹**认出同一张，然后把完整字节写回
   **同一个 key**（hash 不变，分类、描述、使用次数都还在），并清掉截断标记。接口名各家不同，
   它按 `get_history_messages` / `get_group_msg_history` / `get_group_messages` 挨个试；协议端
   一个都没有时，它会如实说"没有提供群历史接口"，而不是假装找过。
2. **重新发一遍**：把完整的图私聊发给机器人（合并转发或直接发）。**这条路径也会先用指纹比对**——
   认出某张残图的完整版就**就地补齐、不重新识图**（分类和描述沿用旧的）；只有真正没见过的新图
   才识图一次。一百多张图会边跑边报「已处理 30/156 张…」，不会让你对着沉默等十几分钟。

找回失败的那些，留在视图里也就是"动图只剩前几帧"，点两下就能删。

**今日用量与上限**：宿主把每个插件的模型调用计数写在 `llm-usage` 里，工坊的状态卡读它显示
「今日模型：N 次调用 · 约 M tokens（每次约 K）· 上限 X 次」。**上限是真的会拦的**——宿主按
`llmDailyBudget` 拒绝超出的调用（失败也计数），而插件没声明这一项时上限是 0，也就是不限；QQ 插件
1.12 起声明了它（默认 300 次，一次大批导入会吃掉很多次）。设成 0 就是明确"不限"。

**它自己挑的那张不受 `stickerChance` 限制**，只受每群冷却约束；`stickerChance` 管的是
"按情绪标签随机"那条兜底路径。

**群内命令**（只有群主/管理员能用）：`#状态` 报能量与记忆条数、`#忘掉` 清空本群的记忆要点。

**它的私有目录是有结构的**（1.11 起，1.10 是全部平铺）：

| 路径 | 内容 |
| --- | --- |
| `state/status` `state/log` `state/groups` | 状态页读的三份快照（连接状态、最近 60 行日志、群索引；群索引里还带着能量与记忆条数） |
| `state/layout` | 布局标记：整理只跑一次，之后每次启动只多一次 `storage.stat` |
| `state/video` | 发出去的视频的保留清单，`pruneVideoFiles` 按它清理 |
| `state/energy/<群号>` | 社交能量（0~1，每条消息回充、每次说话消耗） |
| `history/<群号>` | 每群的往来（重读，不缓存） |
| `memory/<群号>/notes` | 这个群的长期记忆（模型自己增删改） |
| `memory/friends/<QQ号>` | 群友卡片（昵称/别名/一句话/在哪些群出现过） |
| `media/stickers/index` `media/stickers/categories` | 表情包索引（含 `keywords`、`usageCount`、`truncated`）与人工分类表 |
| `media/stickers/bytes/<hash>` | 表情包的字节（base64；只由导入写，删除分类不碰它） |
| `media/stickers/pending-index` `media/stickers/pending/<hash>` | 待收藏的群图：描述 + 字节，≤10 张，模型点头才搬进图库 |
| `media/video/<name>` | 要发给协议端的成品（留 10 分钟） |
| `media/video/tmp/<name>` | curl 下的中间流（合成完即删） |
| `share/bili-jobs` | 跨插件托盘里本插件发布的那份值（宿主写） |

顶层文件夹（`state` / `history` / `memory` / `media` / `share`）**故意都不与 1.10 的任何键同名**：
1.10 的表情包索引本身就叫 `stickers`，如果新文件夹也叫 `stickers`，把索引搬进
`stickers/index` 就得先建 `stickers\` 这个目录——而那个名字此刻是一个文件，`MkdirAll`
直接失败，于是整批表情包搬不动、图库看起来空了一片。避开同名之后，每一个搬迁都是普通的
改名，任意顺序、任意次重复都成立。

升级时插件在**两个进程里**各探一次 `state/layout`（桌宠的常驻帧、市场的工坊），然后用
`storage.move` 把 1.10 的平铺文件逐个改名搬进上表的位置——两百多 MB 的表情包因此不必经
桥搬三倍流量。搬迁幂等（源不在、目标已在都算"做过了"），所以两个进程同时启动也不会搬坏；
旧桌宠（1.11 之前）会拒绝带斜杠的键，此时插件退回 1.10 的文件名继续工作，只留一行日志
说明要升级桌宠才能整理。

**标记只挡"一次性的大搬迁"，每次启动还有一次轻量整理**（`tidyLeftovers`，一次
`storage.list` + 通常零次改名）。理由是升级窗口里真实存在两个写者：桌宠/市场内存里还是
1.10 的代码，它会继续往根目录写 `status` / `groups` / `log` / `categories`。所以每次启动
都扫一遍根目录，把认得出的东西收进来：

- 六个平铺键**按内容合并**而不是覆盖（平铺那份可能带着旧进程刚记住的群名、刚导入的表情包
  行），合并完删掉平铺那一份，目录不会在每次启动后又变乱；
- `hist_<群号>`、`sticker_<hash>`、`bili*`/`bilivideo*` 按**名字形状**归位——索引不知道的
  也要搬，因为 1.10 的群索引会被它自己清空（`loadGroupsIndex` 那个 bug），照着索引搬会把
  四份群记忆留在根目录、升级后看起来"机器人全忘了"；同名文件已存在时，记忆留**条数多的**
  那份（真机上旧进程只记得最新一轮，无脑用新的会把四轮记忆盖成两句话）；
- 有记忆没索引的群补回 `state/groups`（`name:''`、`lastAt:0`，只为了让工坊还能看到它）；
- 账本已经忘了的视频产物搬进 `media/video/` 并补一条账，让 `pruneVideoFiles` 按原有的
  10 分钟规则收走——真机上正好躺着两个这样的文件（48 MB），而 1.10 里它们永远不会被删。

## 功能实现说明

### 1. 透明贴边窗口

`main.go` 里 `Frameless + AlwaysOnTop + DisableResize`，背景色 `A:0`。

关键在于**透明度需要三步**，缺一不可：

```go
Windows: &windows.Options{
    WebviewIsTransparent: true,               // ① WebView2 默认背景设为全透明
    WindowIsTranslucent:  true,               // ② 窗口获得逐像素 alpha 表面
    DisableFramelessWindowDecorations: true,  // ③ 见下方说明
}
```

然后由 `internal/desktop.MakeTransparent()` 调用
`DwmExtendFrameIntoClientArea`，把四个边距都设为 **-1**（DWM 的「整块玻璃」模式）：

```go
m := winMargins{Left: -1, Right: -1, Top: -1, Bottom: -1}
```

- `WebviewIsTransparent` 只改 WebView2 的**默认背景色**，并**不**给窗口 alpha 通道。
- `WindowIsTranslucent` 会加上 `WS_EX_NOREDIRECTIONBITMAP`，这才是逐像素 alpha 的来源。**少了它，页面里所有透明像素都会被贴到一层不透明白底上**，表现为宠物背后一个白色方块（详见下文第 7 节）——而且因为很多人桌面是白的，这个 bug 肉眼和截图都极难发现。
- Win32 窗口本身还会用自己的背景画刷铺满客户区，所以还需要 `MakeTransparent`：Wails 自己确实也调用了 `DwmExtendFrameIntoClientArea`，但边距是 `1px`，那只能拿到默认边框样式，并不会让客户区参与合成。
- `DisableFramelessWindowDecorations: true` 是必需的：否则 Wails 会在每次 `WM_ACTIVATE`（也就是每次点击桌宠）时把边框重新设回 1px，把玻璃效果顶掉。
- 另外去掉了 `WS_CAPTION | WS_THICKFRAME` 并改用 `WS_POPUP`，并在 Win11 上把 `DWMWA_BORDER_COLOR` 设为 `DWMWA_COLOR_NONE`，消掉那圈 1px 描边。

**贴边定位**用的是原生 Win32，而不是 `runtime.WindowSetPosition`：

> Wails v2 的 `WindowSetPosition` 在 Windows 上把 x/y 当作**相对于工作区**的坐标，而 `WindowGetPosition` 返回的是**绝对屏幕坐标**。两者混用会让窗口在偏移不为 (0,0) 的显示器上悄悄跑偏。所以窗口几何全部走 `SetWindowPos` / `GetWindowRect`，统一用物理像素。

> **测试方法学提醒**：验证透明度**不能**只对比「运行时的截图」和「关闭后的截图」。桌面是白色时，白底白框与真透明无法区分，测试会给出假通过。必须把宠物放到**已知纯色的对照窗口**前取样（见 `.dev\greentop.ps1`）。

### 2. 自定义图片

打包后前端资源被嵌进二进制，`<img src="C:\...">` 是读不到用户本地文件的。这里用 **AssetsHandler** 解决：

1. 前端点「更换图片」→ Go 调 `runtime.OpenFileDialog`；
2. 选中的文件**复制**到数据目录（`%AppData%\PetPC\pet-image.png`），而不是记住原始路径 —— 这样用户之后移动或删除原文件也不影响，同时保证被访问的路径始终在我们可控的目录里；
3. 前端 `<img src="/pet-image?v=...">`，由 `assetserver.Options.Handler` 拦截并流式返回文件，带 `Cache-Control: immutable`（URL 上的 `v` 参数负责缓存失效）。

### 3. 待办与日程

Go 侧结构体 + JSON 文件持久化，原子写入（临时文件 + rename），崩溃不会写坏数据。
排序规则：未完成在前（有截止时间的按时间升序，无时间的排后面），已完成的按完成时间倒序排在最后。

面板不用多窗口，而是**同一个窗口切换视图**：Go 计算好 pet 与 panel 各自的矩形，前端按坐标绝对定位。桌宠的屏幕位置保持不变，窗口围绕它向有空间的一侧展开（贴右边缘时面板自动翻到左边）。

### 4. 开机自启

写 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`（`internal/desktop/desktop_windows.go`），不需要管理员权限。值形如 `"C:\path\to\PetPC.exe"`，路径带引号以兼容含空格的目录。

引号必须是 **Windows 命令行引号**，不能用 Go 的 `%q` 动词去拼：`%q` 是 Go 源码转义，会把每个反斜杠都转义成 `\\`，写出 `"F:\\pet_pc\\...\PetPC.exe"`。这个值本身在注册表里"存在"，所以设置界面显示已开启，但资源管理器解析不了它、每次登录都静默跳过 —— Shell-Core 里留下 `9708` 事件且 PID 为 `0`。`autostartCommand` 负责正确的引号，`RepairAutostart` 在 `GetState` 里顺手把旧版本写坏的值改回来。

还有**第二种**同样表现（勾选着、值也在、开机就是不启动）的原因：任务管理器「启动」页签关闭自启时**不会删掉 Run 值**，而是在 `Explorer\StartupApproved\Run` 里写一个 12 字节的 blob，首字节 `0x03` 表示禁用（`0x02`/`0x06` 表示启用；这个映射用真实开机数据核对过：OneDrive 是 `0x03` 且确实没启动，ctfmon/Steam 是 `0x02` 且启动了）。所以 `AutostartEnabled` 必须同时检查"值存在"**和**"没有被标记禁用"，`RepairAutostart`/`SetAutostart` 会清掉这个禁用记录。

`RepairAutostart` **只**修 `\\` 这种畸形值，不会因为"值和当前 exe 不一致"就改写 —— 它在每次 `GetState` 都会跑，若无条件对齐当前 exe，任何另一个副本（测试二进制、第二份安装、别的目录的构建）都会悄悄劫持用户的自启项。开发期间 `go test ./...` 就真的把真实 Run 值改成了临时 `PetPC.test.exe`。要换指向只能通过设置界面显式开关。

测试**绝不能**读写真实值 `PetPC`：`autostart_windows_test.go` 全部走 scratch 值名 `PetPC-test-do-not-use`，并用 `TestSuiteDoesNotTouchRealEntry` / `TestAutostartTestsLeaveRealEntryAlone` 守住这条线（早期版本真的因为跑测试把自启关掉了）。

读取时以**注册表为准**而不是配置文件 —— 用户可能在任务管理器里自己关掉自启，这样设置界面不会显示错误状态。

### 5. 拖动与点击的区分

这里**没有**用 Wails 的 `--wails-draggable`，而是前端用 Pointer Events 自己驱动：

> Wails 的拖动是把移动交给 Windows 的原生模态循环（`WM_NCLBUTTONDOWN` + `HTCAPTION`）。这带来两个问题：webview 收不到配对的 `mouseup`，因此**点击和拖动无法区分**；而且在这个循环结束前，Go 侧根本无法移动窗口。

自己实现后：按下后位移超过 4px 才算拖动（调 `StartDrag` / `DragTo` / `EndDrag`），否则算点击（切换面板）。

### 6. 点击待办不应影响宠物图片

`renderPet()` 只在图片地址**真的变化**时才给 `<img>` 赋值：

> 给 `src` 赋值——即使赋的是同一个值——也会让浏览器丢弃已解码的位图重新解码，图片会空白一两帧。而每次勾选待办都会返回完整状态快照并重跑渲染，所以无条件赋值会让宠物在每次点击复选框时闪一下，尽管图片和待办毫无关系。

实测：连续勾选 3 个待办 + 开关面板，`renderPet` 赋值次数为 **1**（仅首次加载）。

### 7. 宠物背后的白色方块 —— 缺少 `WS_EX_NOREDIRECTIONBITMAP`

宠物图片四周有一个**白色矩形**，正好是宠物图片的大小（150×200）。

根因是 `WindowIsTranslucent: false`：

```go
// Wails window.go
exStyle = w32.WS_EX_CONTROLPARENT | w32.WS_EX_APPWINDOW
if windowsOptions.WindowIsTranslucent {
    exStyle |= w32.WS_EX_NOREDIRECTIONBITMAP   // ← 关键
}
```

没有 `WS_EX_NOREDIRECTIONBITMAP`，窗口就没有逐像素 alpha 表面，WebView2 的合成结果会被贴到一层**不透明的（白色）底板**上。页面里所有"透明"的像素于是显示为白色——而宠物图片是 SVG，只有猫的轮廓有像素，所以整个 150×200 的框都露白。

改成 `WindowIsTranslucent: true` 即可。

**为什么这个问题藏了这么久**：我之前的透明度测试都是「程序运行时的截图」对比「关闭程序后的截图」。用户的桌面是**白色**的，白底上的白框和"透明"看起来完全一样，所以每次测试都通过。直到把宠物放在一块**纯绿色窗口**前面做对照，才暴露出这个方块：

| | 纯绿(透明) | 白色 | 猫 |
|---|---|---|---|
| 修复前 | **0%** | **52%** | 48% |
| 修复后 | **51.3%** | **0.1%** | 48.6% |

现在 `.dev\greentop.ps1` 把「纯色背景对照」固定成了回归测试，避免同类误判。

### 8. 背景被"虚化" —— `WindowIsTranslucent` 在 Win10 上顺带开了毛玻璃

打开 `WindowIsTranslucent` 之后，宠物周围出现一片**模糊**，像蒙了层毛玻璃，而且**跟着窗口矩形走**。

因为 Wails 对这个选项的处理在 Win10 上是这样的：

```go
// Wails window.go
if windowsOptions.WindowIsTranslucent {
    if !win32.SupportsBackdropTypes() {   // Win10 → false（没有 Win11 backdrop API）
        result.SetTranslucentBackground() // ← ACCENT_ENABLE_BLURBEHIND：毛玻璃模糊
    } else {
        win32.EnableTranslucency(...)     // Win11 走这里
    }
}
```

我要的只是**逐像素 alpha**（消除白块），`WS_EX_NOREDIRECTIONBITMAP` 已经提供了；模糊是 Win10 分支额外附送的，不需要。

解法：用同一个（未公开但稳定的）`SetWindowCompositionAttribute` 把 accent 覆盖成 `ACCENT_DISABLED`：

```go
// internal/desktop.SetWindowBlurDisabled()
policy := accentPolicy{AccentState: accentDisabled}
data := compositionAttribData{Attrib: wcaAccentPolicy, Data: &policy, SizeOf: ...}
procSetWindowCompositionAttribute.Call(hwnd, &data)
```

关键点是**只改 accent，不动 `WS_EX_NOREDIRECTIONBITMAP`**，所以白块修复保留、模糊消失。

**怎么客观判断"有没有模糊"**：模糊会抹掉高频细节。所以放一块**噪点背景**在宠物后面，量「相邻像素差的平均值」：

| | 头顶上方 | 左侧空白 |
|---|---|---|
| 修复后（当前） | **74.6** | **84.1** |
| 同一窗口运行时重新打开模糊 | **5.1** | **2.4** |

细节量差 15~35 倍，说明测量足够灵敏，且模糊确实是我这一处修掉的。回归测试：`.dev\blurtest.ps1`。

### 9. 宠物旁边那层"阴影/虚化" —— 其实是**面板自己的 `box-shadow`**

上面那步修完，用户仍反馈点击宠物后图片旁边有一层虚化。真正的元凶是另一处：

```css
#panel {
  box-shadow: 0 10px 30px rgba(0, 0, 0, 0.45);   /* ← 这行 */
}
```

`box-shadow` 画在**边框盒之外**。面板右边缘在窗口 x=380，宠物框从 x=390 开始、间距只有 10px，而阴影模糊半径是 30px——所以**面板的阴影直接盖到宠物身上**。

用纯绿色背景量一条横切线，差别一目了然（G 通道，宠物框左端 → 右端）：

```
面板关闭:  255 255 255 255 ... 255         ← 完全透明
面板打开:  227 230 232 234 ... 255         ← 从左边约 26px 的渐变
```

那个渐变就是阴影。因为它是**平滑的**，看起来就像"背景被虚化了"。

去掉面板阴影后，开/关两种状态**完全相同**（全部 255），旁边什么都没有。

> 经验：任何 `box-shadow` / `filter` 都会画到元素盒子之外。这个窗口里"元素之外"就是**用户的桌面**，所以这类装饰性效果在这里一律不能加——这也正是用户那句"就不能啥也不加吗"的意思。

**排查过程的一个教训**：我先后怀疑过 DWM 玻璃层和 CSS `filter`，都做了 A/B，结果**两者都不是**（玻璃层开关切换后像素完全一致）。定位靠的是最后那条**逐像素横切面**——直接打印数值，而不是继续猜层。噪声指标（"细节量""绿色百分比"）在这个过程中多次给出误导性结论，因为它们把猫的轮廓和背景混在一起统计了。

### 10. 消除闪动（三个独立问题）

这三处都会表现为「闪一下」，但根因完全不同：

**(a) 黑块 —— Wails 的背景画刷忽略了 alpha**

`window.go` 里 `SetBackgroundColour(hwnd, R, G, B)` 只传 RGB，`BackgroundColour{A:0}` 的 alpha 被丢掉，于是窗口类画刷是**纯黑**。平时被 webview 盖住看不见，但窗口每次 resize 都会用这个画刷擦出新暴露的区域，在黑底玻璃模式下就擦出一块黑矩形。

解法：`desktop.SuppressBackgroundErasure()` 把 `GCLP_HBRBACKGROUND` 设成 `NULL_BRUSH`（什么都不擦）。

A/B 实测（同一次运行、同一桌面）：未修复 **17 帧整帧纯黑**（占窗口 95%），修复后 **0 帧**。

**(b) 启动/交互中出现标题栏 —— 窗口创建时就带 `WS_OVERLAPPEDWINDOW`**

Wails 创建窗口用的是 `WS_OVERLAPPEDWINDOW`，标题栏要到 `WM_NCCALCSIZE` 才隐藏。这中间窗口是**真的带标题栏**的，所以会看到「PetPC」标题栏和最小化/最大化/关闭按钮。

解法分两层：

1. **创建时隐藏**：`StartHidden: true`，前端等图片 `decode()` 完成、并多等几帧让 WebView2 合成器呈现后，才调 `App.Ready()`，由原生 `ShowWindow` 显示。
2. **改成 `WS_POPUP`**：`desktop.StripWindowFrame()` 不再只是"抹掉若干个装饰位"，而是直接把样式换成 `WS_POPUP`。弹窗式窗口**按定义**就没有标题栏、边框和调整大小框，所以后续任何操作（resize 重算、显示/还原、重新激活）都不可能把标题栏找回来。同时在每次 resize 后都重新断言一次。

> 注意不要用 `runtime.WindowShow()`：它在 Wails 内部受 `hasBeenShown` 标志保护，与 WebView2 导航存在竞态，过早调用会导致窗口**永远不显示**（我在过程中踩过一次）。

运行中实测：样式恒为 `0x94000000`（= `WS_POPUP`），78,032 帧连续采样中 `WS_CAPTION` **一次都没出现**。

**(c) 面板开合时图片位置跳变 / 每次点击图片闪一下**

这是最难的一个，走了三次弯路才找到正解。

**弯路一：窗口 resize 的竞态。** 最初打开面板就 `SetBounds` 放大窗口。日志实测 WebView2 的视口比窗口**慢约一帧**：

```
win=540x520 open=true innerW=150   <- 窗口已是 540，视口还是 150
win=540x520 open=true innerW=540   <- 视口才更新
```

窗口左边缘已移到 1372，但网页视口仍 150 宽，猫落在 `1372+150-150=1372`（左边），等视口变宽才跳回 1762 —— 这就是「图片跳到左上角」。

**弯路二：把它遮住。** 加了 `syncViewportFreeze()`，视口不一致时把猫 `visibility:hidden`。位置跳变压下去了，但代价是**每次点击猫都消失一帧**，而且这个竞态本质赢不了：只要窗口 resize，视口必然滞后。

**正解：让窗口永不 resize。** 窗口**恒定** 540×520（面板大小），开关面板只改**窗口区域**：

```go
// 区域 = 页面真正绘制的东西：面板 ∪ 宠物（不是整个窗口）
desktop.SetWindowRegion(hwnd,
    desktop.RegionRect{Bounds: panelRect, Radius: panelRadius},  // 圆角对齐 CSS
    desktop.RegionRect{Bounds: petRect},                          // 宠物
)
```

`SetWindowRgn` 是原子操作，**完全不碰窗口几何**，于是：
- 视口恒定 → 竞态从根上消失；
- 猫的 CSS 位置变成**常量** → 一个像素都不动；
- 面板始终渲染着、只是被裁掉 → 打开**零延迟**，不需要重绘，也就没有白框；
- 裁剪区域外的点击穿透到桌面 → 关闭时行为和宠物大小的窗口一致。

实测（同一进程、同一位置）：

| | 关闭面板 | 打开面板 |
|---|---|---|
| 窗口 | 1372,265 540×520 | **1372,265 540×520**（完全一致） |
| 猫（窗口内偏移） | 418,187 | 417,187（1px 抗锯齿） |
| 面板暗色占比 | 0.1% | 66.8% |

对比修复前的 **390~405px** 跳变，现在只剩 1 像素抗锯齿差异。**位置跳变已消除。**

**(d) 面板右上角那条浅蓝色横线 —— 区域裁到了「窗口」而不是「画出来的东西」**

修好 (c) 之后又冒出一个：打开面板时，宠物那一列的顶部有一条**浅蓝色横线**（约 157×14px）。

原因还是"没画的地方露出来了"。窗口高度 = `max(宠物高, 面板高)` = 面板高 520，而宠物只有 200 高。所以宠物上下各有一块**页面从不绘制**的区域，它们和窗口的玻璃层叠加，渲染成一条淡蓝的半透明色带。关闭面板时窗口区域被裁成宠物大小，这块被裁掉所以看不见；**一打开面板，我原来写的是"清除裁剪"（整个窗口都可见），色带就露出来了**。

正解：**区域应该是「页面真正绘制的东西」，而不是「窗口」**——即 `面板 ∪ 宠物`：

```go
regions = []desktop.RegionRect{
    {Bounds: panelRect, Radius: panelRadius},  // 面板（圆角）
    {Bounds: petRect},                          // 宠物
}
// SetWindowRegion 内部用 CombineRgn(RGN_OR) 取并集
```

`Radius` 也不能省：面板 CSS 是 `border-radius: 14px`，如果区域用**直角**矩形，四个圆角外侧仍会留下一小块被染色的像素。用 `CreateRoundRectRgn` 把半径对齐 CSS，两者就完全重合。

实测（同一探针、修复前后）：

| | 宠物列顶部像素 | 判定为"蓝带"的像素数 |
|---|---|---|
| 修复前 | `179,204,229`（淡蓝） | **164** |
| 修复后 | `255,255,255`（纯桌面） | **7**（且都在 x≈23-48，是「添加」按钮本身的蓝色） |

逐行扫描确认：`y=0..24` 每一行里，宠物那一列（x≥374）**全部是桌面原色**，面板右边缘之外不再有任何染色。

### 11. 气泡：三种形态、一块区域、三态互斥

提醒气泡、选择待办气泡、写总结气泡**不新开窗口**，而是复用面板那块 380px 位置，
通过**切换区域裁剪**显示/隐藏。

```go
// applyWindowGeometry() 里，同一时刻只能是其中之一
空闲：      { 宠物 }
气泡显示：  { 气泡(圆角), 宠物 }
面板打开：  { 面板(圆角), 宠物 }
浮层打开：  { 回复卡, 输入条, 宠物 }   // 见第 13 节
```

这不是为了省事，而是被历史问题逼出来的结论：

- **不能 resize**：窗口 resize 会让 WebView2 视口滞后一帧，宠物跳到错误位置（第 10(c) 节）。气泡和面板都在这块区域里切来切去，如果每次切换都改窗口尺寸，这个竞态会以更高频率复现。
- **区域必须精确等于「画出来的东西」**：第 10(d) 节的淡蓝色带就是这么来的。气泡的卡片尺寸因此在 Go 侧是**常量**（提醒 300×140 / 选择 300×200 / 总结 300×160），由 Go 算出物理矩形并同时用于区域裁剪和前端定位——**同一份数据**，不是两处各算一遍。
- **气泡不能有任何 shadow / filter**：和第 9 节同一个道理，阴影画在盒子外面，而盒子外面就是用户的桌面。
- **尖角画在盒子内部**：`#bubble` 预留了一条 10px 的边带放三角形，它永远不会超出卡片矩形，也就不会被区域裁掉半个角。
- **出现/消失只用透明度过渡，不用位移**：位移会在过渡中露出卡片还没铺满的那部分盒子，而区域是按盒子裁的，看起来就是一道缝。
- **气泡与面板互斥**：打开面板时收起气泡，反之亦然。两个都在同一块区域里，同时"显示"在区域裁剪上无法表达。
- **「等回答」的气泡也不能被浮层顶掉**：共用一块矩形意味着打开浮层不是"盖住"提问而是**删掉**提问，而总结气泡是休息的门控（第 11 节末），删掉它等于计时器永久停住且屏幕上没有解释。所以 `OpenLive` 在此时直接拒绝，前端把双击改成"把光标送进那个输入框"——报错的 toast 长在面板里，而面板此刻必然关着，所以不能靠报错。反方向不用新代码：提问气泡出现时 `showBubble` 本来就会收掉浮层，这是对的（浮层只是"当前这一轮"的视图，回复照常落盘，再双击就回来）。

气泡的内容通过 `Layout.Bubble` 与几何**一起**下发，而不是单独发一个事件：如果前端从两条消息分别拿到文字和坐标，就可能出现"气泡画好了但还没被裁进可见区域"（或反过来）的那一帧。

**写总结气泡里的键盘**：`Enter` 保存、`Shift+Enter` 换行。气泡不是 `<form>`，所以这是显式挂的 `onkeydown`（每次渲染都要清掉上一个，否则会带着上一条记录的 id 存进新记录）。`isComposing` 必须判断 —— 中文输入法**选字的那一下回车**否则会把半截总结存掉。

**写计划气泡**（第 5 节「番茄钟」）用的是**同一套**规则与同一张卡片：`Enter` 提交、`Shift+Enter` 换行、`isComposing` 不提交，`onkeydown` 每次渲染先清空。"跳过"与"开始专注"是**同一条提交路径**，只差一个空字符串——门控卡的是"有没有应答"，不是"有没有写字"。

> **计划气泡的门控不能靠提问气泡那套自愈就够了**：总结气泡被面板折叠掉之后，记录页还能改那条记录，所以门控有出口；而**计划气泡在面板里没有任何应答入口**。因此额外做了两处自愈：**关闭面板时若门控仍在且当前无气泡就重弹**（`SetPanelOpen(false)`，在 `a.mu` 释放**之后**调用，否则 `showBubble` 重入 `a.mu` 死锁），以及**重启时重弹**（与 `PendingRecordId` 的自愈同构）。再加上 `HidePet` 遇到计划门控直接拒绝（`errPlanBlocksHiding`），门控不可能变成死路。

> **锁序**：既有链是 `pomoMu → a.mu`（`tickPomodoro` 持 `pomoMu` → `completePhaseLocked` → `showBubble` 取 `a.mu`）。因此 `pendingPlanWaiting()` 自取 `pomoMu`、**不得**在持 `a.mu` 时调用；`showPlanBubble()` **不得**在持 `a.mu` 时调用（它最终要取 `a.mu`）；`completePhaseLocked` 已持 `pomoMu`，所以直接读 `out.State` 而不调 `pendingPlanWaiting()`。内存里的本次计划 `a.focusPlan` **只在 `pomoMu` 下读写**。

### 12. 设置页的布局

设置页是**唯一比面板高**的一页（380×520 的矩形装不下，要滚好几屏），
所以它和对话记录一样**在 `#tab-settings` 内部滚动**，绝不允许把面板撑高——
面板矩形来自 layout、窗口区域又按它裁剪，撑高就等于让"画出来的盒子"和"裁出来的区域"对不上（第 10(c)/10(d) 节）。

改动前它是**十段一模一样的扁平列表**，每段之间一条 1px 分隔线。分隔线只说明"某事结束了"，
不说明"哪些属于一起"，所以连「桌宠图片」和「大小」之间都画了一条线——分组信息等于没有。
现在改成**四张分组卡片**（外观与启动 / 番茄钟 / 对话提醒 / 数据与退出），
组内用小标题（隐藏与显示 / 阶段时长 / 当前番茄 / 节奏）再分块。

> **大模型对话与主动说话两组整体移除了**：它们的控件（21 + 4 = 25 个 id）随配置一起搬进了
> **插件市场程序**——配置归对话插件、编辑面在独立窗口里。设置页现在只剩一行
> **「打开插件市场」**按钮。删净是必须的：宿主这边已经没有配置源，
> 留一半控件在页面上会让用户以为改它有用。

> **语音朗读那一组也整组移除了**：三条开关、试听、停止、音色显示、
> 「打开配音工坊」6 个控件随功能一起搬进**语音插件**（见「语音插件」一节），
> 所以卡片由五张回到四张。这里的理由和大模型那两组同构：
> 宿主已经没有语音配置可存——`config.json` 里的 `voiceEnabled/voicePomodoro/voiceReminder`
> 三个字段被删掉了，留着控件就是让用户去改一个不存在的东西。

> **插件市场是唯一的独立程序**，它不在设置页里，但设置页有它的入口按钮。
> 设置页放的是"开关"，而市场是**工作面**（列表 + 详情 + 权限表 + 配置表，
> 现在还托管插件自己的界面）；
> 面板是固定 380×520 的矩形、窗口区域按它裁剪，塞进去会非常拥挤 —— 这就是拆出去的起因。

排版的机制只有一条，就是 `--label-col`（76px）：

```css
.field { display: grid; grid-template-columns: var(--label-col) 1fr; }
```

所有**带标签的行**都是这套两列栅格，于是控件落在同一条 x 上。这不是可选的美化——
第一版用 flexbox，结果是每个字段行的控件各自漂移，差几十像素，看起来不像"另一种行"，
而像**没对齐**，比完全不分组更糟。

**开关行是刻意的例外**：复选框和它的文字是**一个整体**（框就是控件，文字是它的说明），
所以文字紧挨着复选框，不推到值那一列去。第一版为了"全页只有一条 x"把它们也套进栅格，
结果复选框和它管的文字之间空了 76px，看起来像"一个框配一句无关的说明"。
两行类型现在只共享**唯一的左边距**（复选框和字段标签同在 x=23），形状不同但左边缘一致。

另外两条：
- **标签顶端对齐**，不垂直居中：值那一列可能是两行（提示语、一排按钮、人设文本框），
  居中的话标签会飘到整块的中间，读起来就不像"这个标签管这一块"。
- **没有 `transform`/`box-shadow`/`filter`**：和第 9 节同一个道理，它们画在盒子外面，而盒子外面是用户的桌面。

验证分两层：`.dev/check-frontend.cjs` 钉**结构**，`.dev/run-frontend-harness.cjs` 钉**实测结果**
（浏览器里量出来的 x 坐标、右边缘有没有越界、七组标题是否互不相同）。
`.dev/layout-report.cjs` 把整页几何打**成文字**，方便在没有图形界面的环境里复核布局。

| `plugin-market.json` | **插件市场程序自己**的偏好（市场地址、上次选中的插件、窗口尺寸、深/浅主题） |
| `voice\` | **旧版语音库，已迁移但保留**：`user\voice-user.json` + `user\clips\<台词>\vNNN.wav`。只被**读过一次**，永不改名也永不删除（见「语音插件」一节的迁移说明）；新语音数据在 `plugin-data\com.shixiansi.plugin-voice\` |

> 旧的 `llm-history.json` / `llm-usage.json` / `llm-key.bin` 与 13 个 `llm*` 配置项会在
> 首次启动时**一次性迁移**进 `plugin-data/com.shixiansi.plugin-chat/`，原文件改名 `.bak` 保留；
> 迁移是**幂等**的（第二次不再搬），失败时不会动原文件。此后对话历史与配置都只住在插件私有目录里。

> 旧的 `voice\user\` 同样一次性迁移进 `plugin-data\com.shixiansi.plugin-voice\`，
> **但来源保持原样**（不改名、不删除），理由见「语音插件」一节。
> 两个迁移都是**先写完再打标记**的：中途失败就不留标记，下次启动重试。
>
> 插件市场自己的设置在**它自己的文件**里（`plugin-market.json`），与桌宠的 `config.json` **分开**：
> 它不是桌宠的设置，而且桌宠的 Config 会随每次 `GetState` 推到 webview，
> 不必要的东西不该放在那里——分开也是「另一个程序绝不修改桌宠配置」这条保证的前提。

位置以**逻辑像素**保存，所以改 DPI 缩放后不会跑偏。

`pomodoro.json` 和 `llm-usage.json` 是**运行状态**而非用户偏好，所以容错策略不同：损坏时**静默重置，不弹提示**（丢"今天用了几次"无所谓）。
`pomodoro-records.json` 和 `llm-history.json` 是**不可再生的用户数据**，损坏时按 `todos.json` 的规则处理：改名 `.bak` 保留 + 界面提示。

`voice\user\voice-user.json`（旧库）是**例外**：它损坏时**静默重置**，不弹提示、不改名。它唯一不可恢复的内容是"选了哪一版"，
为此让桌宠起不来是荒谬的；而那些音频文件仍在磁盘上，可以重新选。
迁移遇到一个**解析不了**的旧库时会**报错而不是跳过**——静默产出一个空插件
看起来和"迁移成功、但你的语音没了"一模一样。

**API Key 永不进入 `config.json`**：`GetState()` 会把整个 `Config` 原样发给 webview，密钥放在那里等于一次 `JSON.stringify(state)` 就泄露到页面。它有专门的加密文件，前端只能拿到 `hasKey` 和一个掩码（有单测断言序列化后的 State 里不含密钥）。

**容错**：JSON 损坏、被截断、带 UTF-8 BOM（记事本默认行为）、类型不对、文件为空或缺失 —— 任何一种情况都不会导致程序打不开。解析失败的文件会被改名成 `*.bak` 保留，界面弹提示，程序用默认值照常启动。

`voice-user.json` 是**例外**：它损坏时**静默重置**，不弹提示、不改名。它唯一不可恢复的内容是"选了哪一版"，
为此让桌宠起不来是荒谬的；而那些音频文件仍在磁盘上，可以重新选。

**向后兼容**：旧版 `config.json` 没有番茄钟/提醒的键，`Normalise` 对所有"零值不合法"的项按**缺省值**补齐（时长、间隔、条数等），所以升级后不会出现 0 分钟的专注阶段。`reminderJitterMaxMin` 是例外——它的合法值包含 0，所以缺省按 0 兜底，避免把用户显式设的"准点提醒"悄悄改掉。

### 关于对话框

「跳过」「放弃番茄钟」这类需要二次确认的操作，用的是**面板内自绘的确认卡片**，不是 `window.confirm`，也不是 Wails 的 `runtime.MessageDialog`。

两者都是**原生对话框**：WebView2 会把 `window.confirm` 渲染成一个标题为「wails.localhost 显示」的白色浏览器窗口，无视应用主题、盖住整个面板，并且位于窗口裁剪区域之外。桌宠的窗口是被 `SetWindowRgn` 精确裁剪的，任何脱离这块矩形的 UI 都会显得像外部程序的弹窗。

自绘卡片的结构是**全panel遮罩 + 居中卡片**，`Esc` 取消 / `Enter` 确认，默认焦点落在「取消」上以避免误按回车丢番茄。

这里踩过两个坑，都值得记下来：

**(a) 弹窗"移一下位置" —— transform 被动画覆盖。**

第一版把卡片写成 `top:50%` + `transform: translateY(-50%)` 居中，同时又套用了面板的入场动画 `animation: panel-in`。而 `panel-in` 的关键帧本身就是 `transform: translateY(4px) → none` —— **动画期间它覆盖掉居中用的 transform**，卡片因此先偏下、再弹回中心，看起来就是"会移一下位置"。

修法不是去和动画抢 transform，而是**根本不用 transform 居中**：外层遮罩用 `position:absolute; inset:0` + flexbox 居中，卡片作为普通流内元素。现在这段 CSS 里**一个 `transform` 都没有**，冲突从结构上消失。

**(b) 卡片和面板"同个色调没有区分"。**

第一版卡片底色 `#30343d` 压在面板色上，实测对比度只有 **1.47:1**（对未变暗的面板仅 1.28:1），确实糊在一起。

修法是同时压暗遮罩、提亮卡片：遮罩 `rgba(6,7,9,.68)`、卡片 `#4a5162`。实测卡片填充 `74,81,98` 对遮罩后的面板 `13,16,20`，对比度 **2.30:1**，一眼可辨。

> 顺带把卡片的入场动画也改成**纯透明度**（`fade-in`）：缩放入场属于"位移/形变"，而这个窗口被裁剪到"页面真正画出来的东西"，任何会动的效果都可能露出未被绘制的部分——和气泡同理。

验证方式：把这些 CSS 原样喂给无头 Edge 渲染成 540×520 的静态页，再逐像素量。**先做对照实验**（黑/灰/白/卡片色块）确认截图管线颜色忠实，否则测出来的数字不可信；另外必须**关掉动画**再量，否则会在动画中途取样（第一版就因此量到一片灰，差点误判成渲染错误）。

**(c) 点「保存」没反应、写总结气泡不消失。**

这是**前端渲染源与后端状态脱钩**造成的，跟 CSS 无关。

前端的气泡**完全由 layout 驱动**（`GetLayout()` → `applyLayout(layout.bubble)`）。而 `clearBubble()` 当时只清了 `a.bubble`，**没有更新 `a.layout.Bubble`**——于是 `GetLayout()` 继续把"已经关掉的气泡"发给前端，前端就把它重新画出来。表现就是：点保存毫无反应、气泡赖着不走，**但记录其实已经正确写入了**（这正是最难从现象反推的地方）。

修法：新增 `setBubbleLocked()` 作为**唯一**改 `a.bubble` 的入口，它同时维护 `a.layout.Bubble`，并让 5 处调用点（`showBubble` / `clearBubble` / `DismissBubble` / `SetPanelOpen` / `OpenTodoPanelFromBubble`）全部走它。`clearBubble` 另需 `applyWindowGeometry()` 把窗口区域收回到宠物大小。

回归测试：`TestBubbleAndLayoutStayInStep`、`TestSaveSummaryClearsBubble`、`TestSkippingSummaryAlsoClosesThePrompt`。

> **这个测试验证过它真的能抓 bug**：把修复临时退回旧写法后，三个测试立刻失败，并直接打印出 `clearBubble left the layout advertising the bubble: &{Kind:summary …}`——失败信息就指着根因。写完测试要确认它在 bug 存在时会红，否则等于没测。
>
> 另一条教训：**"点了没反应"要先去查状态同步，而不是先怀疑前端事件或 CSS**。这次记录已落盘、接口已返回，唯一的问题是后端内存里的 layout 没跟着更新。

- 仅实现了 Windows（`desktop_other.go` 提供桩函数，macOS/Linux 需要自行补 `SetAutostart` 等）。
- 提醒只用桌宠气泡，没有系统级通知（不会进 Windows 通知中心）。
- 记录页没有统计图表 / 趋势分析，只有总条数与累计时长；按天折叠，但一天之内仍是平铺。
- 番茄钟同时只能有一个，不支持并行计时，也不做云同步。
- 单显示器布局经过验证；多显示器下窗口定位按所在显示器的工作区计算，但未在多屏环境实测。
- 拖动过程中不会实时吸附，只在松手时吸附。
- 窗口尺寸是固定的 `宠物 + 间距 + 面板`（100% 缩放时 540×520）。若所在显示器工作区小于该尺寸，面板会被压缩到工作区内。
- 缩放宠物大小时窗口会真正 resize 一次（这是唯一需要改窗口尺寸的操作），此时视口仍会滞后一帧；因为它只在设置面板里操作、不涉及点击宠物，所以不影响观感。
- 气泡（提醒/选择待办/写总结）与面板**共用同一块区域且互斥**，尺寸固定；这是区域裁剪必须精确所决定的，内容超长时靠内部滚动而不是撑大卡片。对话**不是**气泡，它是插件的浮层面。
- **设置页要滚动才能看全**：删掉 AI 那两组之后短了很多，但仍**不能**因此把面板撑高（见「功能实现说明」）。同屏只能看到一组多一点，所以分组标题的位置比分组本身更影响可读性。
- **设置页布局只在浏览器引擎里量过，没在真机 WebView2 里量过**：本次开发环境无法创建 WebView2 控制器（改动前的旧二进制同样失败，与本改动无关）。已用真实浏览器引擎加载**真实构建产物**量了字段行 / 开关行的 x 坐标、右边缘越界、滚动与分组标题层级，并用 `.dev/layout-report.cjs` 把几何打成文字逐行复核；但首次在真机上打开设置页时仍建议确认一遍（对齐、有没有横向裁切、最后一组能否滚到）。
- 未用像素探针验证「气泡显示时宠物四周完全无染色」——历史经验表明 `CopyFromScreen` 抓这类分层窗口会得到空白图，数据不可信。气泡与面板走完全相同的裁剪路径且无任何阴影/滤镜，但仍建议实机确认一次。
- **大模型只做了聊天**：还不能替你改待办/番茄钟（工具调用未实现——`internal/llm/protocol.go` 的 `ChatRequest` 里没有 `tools` 字段，流式解析也不认 `tool_calls`，所以模型没有可调用的手）。**主动说话已整体移除**（配置搬给插件后宿主没有配置源了，见「大模型对话的历史沿革」）；插件日后可以用 `llm.chat` + `pet.bubble` 自己实现。
- **对话界面不是独立窗口**：它要么是面板里的一个槽位，要么是紧贴宠物的浮层面，**不能**脱离面板单独摆放。要真正的独立弹窗需要第二个窗口，而 Wails v2 无多窗口 API，且本项目靠类名找窗口 —— 成本高一个数量级（试过用气泡卡片模拟，已回退，见 `docs/llm-chat.md` §8.0）。真正的「独立窗口」诉求现在由**插件市场**一个独立程序承接（它顺便还托管插件自己的工作面，语音插件的配音工坊就是），代价是它要自己的 module 与构建链。
- 大模型只支持 **OpenAI 兼容协议**（`/chat/completions`）；Anthropic 原生 `/v1/messages` 未做，但 `Provider` 接口已留位。
- 对话回复按**纯文本**渲染，不做 Markdown（避免为它引入解析器和新的样式风险）。
- 对话的**像素级实机验证尚未跑过**：本次开发环境里 WebView2 无法创建控制器（`800700aa`，改动前的旧二进制同样失败，已确认与本功能无关）。浮层面的几何已用真实浏览器引擎 + 假 Wails 桥接（行为与盒模型验证）与 `.dev/verify-live.ps1`（真机在**有交互桌面**时）两层覆盖，但首次在真机上使用时建议按 `docs/llm-chat.md` §12 的清单确认一遍。
- **语音插件的工坊界面没有在真机 WebView2 里点过**：本环境无法创建 WebView2 控制器
  （`800700aa`，改动前的旧二进制同样失败，与本功能无关）。宿主侧（迁移、`audio.*`、
  两个边缘事件的发出）由 Go 单测覆盖，插件前端由 `market/tests/plugin-voice.test.js`
  （vitest + jsdom，**55 项**）驱动**真实的 `app.js` 与 `panel.html`**，
  `.dev/check-frontend.cjs` 钉住结构、权限配对与资源随包。
  **但"在市场里选中语音插件、看到两栏工坊并点得动"这一步没有被任何真实浏览器驱动验证过**——
  jsdom 能证明逻辑与 DOM 结构，**证明不了排版**（两栏在 720 宽下是否真的不横向滚动，
  只能靠眼睛）。细节与尚未验证的部分见 `docs/voice.md` §8。
- **语音插件需要本机装着 GPT-SoVITS 才能"换角色"**（默认 `D:\GPT-SoVITS`，
  地址默认 `http://127.0.0.1:9880`）。**引擎由用户自己启动，插件不会代劳**——
  这是明确取舍："启动一个进程"若作为能力开放，等于给每个已装插件任意代码执行。
  引擎的存活状态由插件探测：**探测明确失败**时点「生成」直接拒绝并说明原因（不发请求），
  探测未回复（"未知"）则不拦——把未知当不可用会让按钮在一次探测完成前一直是死的。
  而**包内自带的 5 条音频装完即用**，播放路径永远不需要引擎。
- **`/set_gpt_weights` / `/set_sovits_weights` 没有对真实引擎验证过**：
  这两个热切换端点是旧工坊用过的（`api_v2.py`），插件改成
  `set_gpt_weights → set_sovits_weights → POST /tts` 三步走（引擎常驻一个模型，
  不先切权重就会用上一个角色的声音合成），但**顺序与参数只由 jsdom 测试钉住**。
- **语音插件不占桌宠面板的任何落点**：它在桌宠侧只有一个隐藏的常驻帧，
  界面挂市场。所以桌宠面板的 tab 数仍然是 **4**，也不会为了它出现第 5 个。
- **市场托管插件界面时，能力表是市场自己的**：`todos.*`/`timer.*`/`bubble.say`/`surface.*`/
  `llm.chat`/`events.subscribe` 从市场调用会得到「本程序不支持该方法」——
  市场没有待办、没有番茄钟、没有宠物。这是刻意的：一个共享的能力表会宣称这些方法到处可用，
  然后在更深处以别的形式失败。
- **常驻帧最多一个**：`background: true` 的插件由桌宠挂一个隐藏 iframe。
  两个常驻插件会各要一个帧，而"事件投给谁"必须是唯一的，所以没有做多帧调度。
- **旧语音库保留在 `voice\user\`**：迁移只复制、不改名、不删除（片段太贵，见「语音插件」一节）。
  想回收那几 MB 需要自己动手，程序不会替你清理。
- **插件市场程序的窗口不能在真机 WebView2 里打开过**：本环境同样无法创建 WebView2 控制器（`800700aa`，改动前的旧二进制也一样）。所以市场的**窗口样式与布局**由 `.dev/verify-plugin-market.ps1` 在有交互桌面时验证（`WS_THICKFRAME`/`WS_MAXIMIZEBOX` 两个样式位、客户区约 980×700、权限行右边界内侧 2px 竖条的像素扫描、地址框宽度 ≥ 容器 90% 且与保存按钮同一水平带），本环境会按既有约定报「无交互桌面」并 `exit 0`。首次在真机上使用时按上面「端到端冒烟」表第 2–6 步确认。
- **插件的面板视图不能在真机 WebView2 里点开过**：本环境的合成点击能到达桌宠的**窗口**，但到不了页面里的**控件**，所以「打开插件面板视图」这一步无法用像素门禁驱动。插件的几何与协议由三层替代验证覆盖：`internal/plugins` 与 `app_plugin_surface_test.go` 的纯函数单测（夹回、圆角/椭圆、缩放换算、区域与视图一致）、行为 harness（每块矩形的 iframe 摆放坐标与布局逐项相等、沙箱属性恰为 `allow-scripts`、逐帧的 `rectIndex/rectCount` 握手、按 `pluginId` 的事件路由）、以及 `.dev/verify-plugin-surface.ps1` 能跑到的**关闭态**判据（未开浮层面时该矩形不属于窗口，加上 `PETPC_OPEN_PLUGIN_MARKET` 钩子确实启动了市场程序）。首次在真机上使用时，按上面「端到端冒烟」表从第 7 步开始确认。
- **插件市场默认走 gh-proxy.com 镜像**：`raw.githubusercontent.com` 在国内不通。镜像不可达时会**回退到随 exe 分发的内置示例源**并在界面说明原因，所以插件功能本身不会因为网络而不可用。
- **插件的浮层面只支持矩形并集**（可带圆角），不支持任意曲线外形或逐像素 alpha 掩码。
- **本轮不做**：插件市场的评分/评论/下载量统计、自动更新与版本回滚、插件签名与非对称校验、多市场聚合、插件间依赖解析、GitHub Pages 托管市场页、把 exe 作为 Release 附件分发。
- **线上 push 由你自己执行**：本仓配了 `origin`（`https://github.com/shixiansi/pet_PC.git`）但**从未推送过**；市场仓同理（`pet-pc-plugins`，公开）。
